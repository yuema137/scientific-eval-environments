# December 2024 Monthly Report

## Month at a Glance

- Six works entered the knowledge base this month, and all six are new releases first public in December 2024: [ProcessBench](../works/processbench.md) (2024-12-09), [AnalogXpert](../works/analogxpert.md) (2024-12-17), [SafeAgentBench](../works/safeagentbench.md) (2024-12-17), [Speak-to-Structure](../works/tomg-bench.md) (2024-12-19), [LiveIdeaBench](../works/liveideabench.md) (2024-12-23), and [Aviary](../works/aviary.md) (2024-12-30).
- Four of the six sit under [Scientific Agent Benchmarks](../topics/scientific_agents.md) — [AnalogXpert](../works/analogxpert.md) (analog circuit design), [Speak-to-Structure](../works/tomg-bench.md) (molecule generation), [LiveIdeaBench](../works/liveideabench.md) (scientific idea generation), and [Aviary](../works/aviary.md) (biology environments) — spanning four unrelated fields with no shared leaderboard.
- What separates those four is not the field but the most basic decision an evaluator makes first: what counts as a correct answer. One checks a single valid design, one wraps each task in an environment with a terminal reward, one accepts any molecule that satisfies the instruction, and one abandons a correct answer entirely to score open-ended creativity.
- The other two turn the lens from the agent to what a plain success rate hides. [ProcessBench](../works/processbench.md) asks whether a judge can locate the earliest wrong step in a reasoning chain; [SafeAgentBench](../works/safeagentbench.md) asks whether an embodied agent will refuse a hazardous instruction rather than dutifully carry it out. Both report that the measured property is done poorly.

## What Changed This Month

**The month's scientific-agent benchmarks agree on almost nothing except that domain answers need a domain-appropriate check — and they disagree, concretely, on how many correct answers a scientific task even has.** The convenient default for scoring a domain model is to compare its output against one reference string. That works when a task has exactly one right answer, but most scientific work does not: a circuit can be wired several valid ways, many molecules satisfy the same request, and a research idea has no reference at all. The four scientific-agent additions this month each settle that question differently, and laid side by side they form a spectrum. [AnalogXpert](../works/analogxpert.md) stays closest to a single reference — a synthesized analog topology is either structurally correct or it is not, checked by rule programs or a human reviewer. [Aviary](../works/aviary.md) wraps each scientific task in a partially observable environment and reduces correctness to a terminal reward. [Speak-to-Structure](../works/tomg-bench.md) deliberately makes the answer one-of-many: an open-ended instruction is satisfied by any molecule that meets it, not by reproducing a memorized target. [LiveIdeaBench](../works/liveideabench.md) drops the notion of a correct answer altogether and scores open-ended idea quality on five creativity dimensions via an LLM panel. The shared premise is that surface plausibility is not enough; the disagreement is over whether "correct" means one answer, one of many, or a graded quality — and that choice, made before any model is run, determines what each benchmark can measure.

**The remaining two works stop asking whether the task succeeded and start measuring what a success rate conceals.** A final answer that looks right can rest on a broken step, and an agent that competently executes tasks will competently execute dangerous ones. [ProcessBench](../works/processbench.md) targets the first gap directly: by balancing answer-correct and answer-incorrect solutions and having experts annotate the earliest erroneous step, it makes the rate at which a correct final answer sits on a flawed process directly measurable — from 3.5% of answer-correct GSM8K solutions up to 51.8% on Omni-MATH — and then tests whether process reward models and prompted critic models can find that step. [SafeAgentBench](../works/safeagentbench.md) targets the second: it pairs hazardous and safe task variants so that refusal is scored separately from competence, and finds the best baseline rejects only 10% of detailed hazardous tasks while swapping the underlying model barely moves the number. Neither work grades whether the end task was solved; each grades a property — process soundness, safe refusal — that outcome accuracy leaves invisible.

## Selected Topic Developments

### [Scientific Agent Benchmarks](../topics/scientific_agents.md)

Four of the month's six works are primary references here, and the useful way to read them together is along the "what counts as a correct answer" axis described above, from the most constrained check to the least.

- [AnalogXpert](../works/analogxpert.md) sits at the constrained end. It encodes an analog designer's workflow into an LLM agent: topology is represented as SPICE code, a subcircuit library narrows the design space, and the task is split into block selection and block connection handled with chain-of-thought and in-context learning, then refined by an incremental proofreading step. Correctness is a near-single-reference check — synthetic cases verified by automated structural-rule programs, real cases by human reviewers matching every block and connection to the requirement. On a purpose-built benchmark of 30 real and 2,000 synthetic cases it reaches 40% (synthetic) and 23% (real) success against GPT-4o's 3%, evidence that encoding design expertise, not raw scale, drives the gain. The boundary: the card is compiled from the arXiv abstract and full text, with no venue in the metadata and no verifiable code or dataset repository.

- [Aviary](../works/aviary.md) turns each scientific task into a policy-in-an-environment problem, formalizing agents as policies over language-grounded partially observable Markov decision processes and collecting them in an extensible gymnasium. Three of its five environments are scientific — DNA-construct manipulation (molecular cloning), answering research questions from the literature, and protein-stability engineering — and each supplies a terminal reward (multiple-choice scoring, or a binary stabilizing/not-stabilizing signal from a Rosetta ΔΔG check). The reported headline is a cost-performance result: a small open-source-backed agent (Llama-3.1-8B trained by expert iteration) matches or exceeds frontier agents and human experts on several tasks at up to ~100× lower inference cost. That headline comes from the paper's *training* contribution, which is adjacent to this repository's evaluation-centric scope; Aviary is documented here for its reusable scientific environments, not the training method. A caution to carry forward: the released code has since diverged from the paper's five environments.

- [Speak-to-Structure](../works/tomg-bench.md) (introduced as TOMG-Bench) makes the one-to-many stance explicit. Most text-to-molecule evaluation is one-to-one — an instruction paired with a single reference molecule — which penalizes valid novel answers. Speak-to-Structure instead checks whether a generated molecule satisfies the instruction across three open-domain task families: molecule editing (MolEdit), optimization (MolOpt), and customized generation (MolCustom). The first release organized each task into three subtasks of 5,000 test samples each; the current version reports a comprehensive evaluation of 31 LLMs and pairs the benchmark with OpenMolIns, an instruction-tuning dataset large enough to lift Llama3.1-8B past GPT-4o and Claude-3.5 on the benchmark — evidence that the headroom it exposes is trainable. The work was retitled between versions (TOMG-Bench in 2024 to Speak-to-Structure/S²-Bench later), so version-specific figures should be read against the version that states them.

- [LiveIdeaBench](../works/liveideabench.md) removes the correct answer entirely. It isolates divergent thinking by prompting models with a single keyword — 1,180 keywords spanning 22 scientific domains — and scoring the generated scientific ideas with a dynamic panel of state-of-the-art LLMs on five dimensions grounded in Guilford's creativity theory: originality, feasibility, fluency, flexibility, and clarity. Across 40+ models the finding is a dissociation: creativity is poorly predicted by general-intelligence metrics, with QwQ-32B-preview rivalling top models like claude-3.7-sonnet:thinking despite lower general-intelligence scores. The result stops at single-turn, minimal-context generation rather than an interactive setting, and the card flags that the paper was retitled and that its Nature Communications venue is a repository claim not carried in arXiv metadata.

### [Credit Assignment](../topics/credit_assignment.md)

[ProcessBench](../works/processbench.md) is the month's one work here, and it defines what the topic measures at the level of a static reasoning trace. Prior process-assessment benchmarks either used problems that recent models have outgrown, or labeled only whether the final answer was right without saying which step went wrong. ProcessBench changes the graded object to a single integer: given a problem and an *n*-step solution, the judge must return the index of the earliest erroneous step, or −1 if every step is correct. It is built from 3,400 cases across four subsets (400 from GSM8K, 1,000 each from MATH, OlympiadBench, and Omni-MATH), weighted toward competition- and Olympiad-level problems, with solutions drawn from twelve open-source generators, reformatted to uniform step granularity, and error locations annotated by human experts under a three-to-five-annotator agreement rule. The single-integer format lets two judge families — process reward models and general LLMs prompted as critics — be scored on one F1 scale (the harmonic mean of accuracy over erroneous and over correct samples). Averaged over the four subsets, o1-mini reaches 87.9, QwQ-32B-Preview 71.5, GPT-4o-0806 61.9, the authors' fine-tuned Qwen2.5-Math-7B-PRM800K 56.5, and the strongest existing open-source PRM (Skywork-PRM-7B) 42.1 — a wide gap between prompted critics and existing PRMs. Two boundaries bound the result: labels may stay noisy on the hardest Olympiad problems, and the ~30% of solutions discarded for lack of annotator consensus may bias the distribution toward cases experts could resolve. The judged unit is a static, pre-generated solution, so the earliest-error index localizes a reasoning error inside one text and carries no notion of tool calls, environment state, or actions across turns — the seam where this differs from trajectory-level credit assignment.

### [General Long-Horizon Agent Benchmarks](../topics/long_horizon_evaluation.md)

[SafeAgentBench](../works/safeagentbench.md) is the month's one work here, and it treats an embodied planning episode as the long-horizon unit while measuring safety rather than capability. The gap it targets is that a benchmark scoring only task success rewards an agent for competently executing whatever it is told — including "heat the towel on the stove." SafeAgentBench separates the two by pairing hazardous and safe variants of the same task: 750 executable tasks over 10 hazard categories and 3 task types, planned and executed in SafeAgentEnv, a universal embodied environment with a low-level controller and 17 high-level actions, against 9 state-of-the-art baselines with multi-agent support. Scoring runs from both an execution and a semantic perspective, with task success rate and rejection rate as the core metrics, so refusal calibration is measured apart from task competence. The finding is stark and architectural: the most safety-conscious baseline rejects only 10% of detailed hazardous tasks, and swapping the underlying LLM does not notably improve safety awareness — redirecting safety effort from model choice toward system design. The boundary is that hazards are simulation-only, so physical-world risk transfer is not evaluated; the embodied household setting also sits outside the repository's science/engineering domain axis, and the card notes the repository README carries older baseline figures than the abstract treated as canonical.

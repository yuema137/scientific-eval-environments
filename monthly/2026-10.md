# October 2026 Monthly Report

> **English** | [简体中文](../zh/monthly/2026-10.md)

> **Coverage:** Cards added to main during 2026-10

## Month at a Glance

October's cards converge on a single refusal: a plausible final answer is no longer allowed to stand in for the work behind it. A derivation that reaches the right formula is scored separately from whether the shown steps justify it; an agent that fits a simulator's data is scored separately from whether it found the mechanism; a report that reads well is scored separately from whether the code it describes actually ran. The same suspicion drives the artifact benchmarks, which no longer grade a generated script or a reported number but open the file the agent produced — a CAD model, a Simulink block diagram, a finite-element case — and run it. And it drives a wave of meta-evaluation, in which the object under test is the evaluator itself: can an agent build one, generate the benchmark, or reuse a frozen verifier, and can any of these be trusted.

Twenty-seven works reached `main` this month: eighteen first appeared in October, and nine are backfills whose public release predates it. Physics derivations and strong-field physics form the heaviest subject cluster — [PHYRD](../works/phyrd.md), [PhysClosureBench](../works/physclosurebench.md), and [QFT-Bench](../works/qft-bench.md) all land in the same weeks — but the organizing fact of the month is methodological rather than topical: across physics, laboratory robotics, interpretability, and engineering CAD, the new benchmarks keep splitting a single score into the part that measures output and the part that measures process, and then report the cases where the two disagree.

## What Changed This Month

### A right answer is not a finished piece of science

The month's largest cluster rebuilds scoring so that a correct result cannot absorb the credit for everything around it. [PHYRD](../works/phyrd.md) splits each theoretical-physics problem into public subquestions and gives credit for a part only when its conclusions, derivation steps, and applicability conditions are all correct, so a correct closed-form answer with a missing condition scores nothing for that part; its *Reproduce* track rebuilds a published result from stated premises and its *Discover* track changes one condition and asks what still holds. [QFT-Bench](../works/qft-bench.md) settles a quantum-field-theory answer with a symbolic check first and an LLM judge only when that is inconclusive, then adds a second judge that asks whether the displayed derivation actually supports the answer — and finds correct answers whose shown work does not justify them, with faithfulness labels that match experts only 73% (Opus-5) and 67% (GPT-5.6) of the time. [PhysClosureBench](../works/physclosurebench.md) makes the split structural: a 20-criterion Atomic Score credits local steps while a separate Research Closure level (RC0–RC4) asks whether the indispensable evidence for a complete answer is in place, and across 1,050 attempts, 83 of the 229 that score at least 8/10 still fall short of closure.

[EurekaBench](../works/eurekabench.md) draws the same line in a simulator: an agent runs experiments for up to four hours and submits a mechanism as prose, code, and a log, and the best agents come within 1.4 points of the human reference on predictive accuracy but trail it by 27.3 points on insight — fitting the data is not explaining it. [DISCERN](../works/discern.md) stages the split across a life-science workflow, scoring data vetting, analysis verification, and hypothesis proposal separately with matched clean controls so an agent loses credit both for missing a defect and for rejecting sound data; perfect scores drop from 60.8% of Level 1 to 0.6% of Level 3. [SAEScientist-Bench](../works/saescientist-bench.md) turns the sparse-autoencoder interpretability loop into a task and finds the same gap at the level of evidence-reading: agents design reasonable contrastive probes but often misread their own measurements of which dictionary feature fires. And [Into the Unknown](../works/into-the-unknown.md) pushes the idea to its limit, grading an unpublished follow-up direction against a scientist's own success conditions split into integrity, completeness, and sufficiency — none of 135 submissions is valid, so the strict metric is 0% for every agent and only node-level pass rates separate them.

### Grade the artifact by running it, not by reading about it

A second cluster attacks the gap between a convincing description and a working deliverable by refusing to grade anything that has not executed. [EngiWorld](../works/engiworld.md) has agents drive 26 professional engineering applications through a GUI or command line and then opens the resulting artifact — a solid model, a mesh and load case, a board layout — to check geometry, physical feasibility, and design rules; a run that ends with a plausible report but an invalid file scores zero, and the best agent reaches only 44.3 of 100 with 6 of 168 multi-software attempts succeeding. [CADWorld](../works/cadworld.md) narrows this to one tool, driving FreeCAD through screenshots and mouse-and-keyboard actions and then opening the saved `.FCStd` file to verify entities, constraints, assembly joints, CAM material removal, and FEM setups with no LLM judge in the loop. [SimuVerity](../works/simuverity.md) builds executable Simulink models for 101 engineering systems and scores them by native simulation behind a hierarchical gate — delivery, executability, an engineering qualification check — before any of six engineering dimensions is scored, and the best system reaches 42.86 against 96.01 for the reference models. [OSWorld-Science](../works/osworld-science.md) moves the general computer-use setup into the software scientists actually run, grading only the collected application state and output files after the episode.

[SCI-AGENT-EXAM](../works/sci-agent-exam.md) carries the same discipline into general scientific tasks by scoring two channels: deterministic checkers rerun the agent's code on hidden inputs while an LLM judge grades the written report against an expert rubric, and reporting both exposes agents that write a convincing report about analysis that did not execute correctly. [ScienceIDE](../works/scienceide.md) turns public scientific repositories into executable environments with private verifiers that compare numerical outputs against scientific references, then reuses that same verifier to filter supervised demonstrations and supply a reinforcement-learning reward — evaluation here is not a final step but the development loop itself.

### Moving the bar past the leaderboard

Several cards reject the leaderboard as the ceiling. [Agent4Sci](../works/agent4sci.md) starts each run from a verified reproduction of the best *published* model on a scientific ML benchmark and scores the relative improvement an agent can add in 12 hours on 8 H200 GPUs, with a separate evaluation agent on a sequestered test set and an auditing agent checking the trajectory for gaming; the paper finds most gains come from engineering rather than research insight. [AutoDataBench](../works/autodatabench-auto-research.md) isolates one lever by freezing the model, pipeline, and evaluation and letting the agent change only the training data, then scoring its best in-distribution checkpoint on a hidden out-of-distribution set. [Astro2Method](../works/astro2method.md) asks whether a model can pick the better machine-learning method for an astronomy problem — the one the source paper measured as better — and finds direct prompting near chance on the hard items, with retrieval and reasoning scaffolds not reliably helping and the source paper's own masked pipeline description helping most. [SciΠvot](../works/scipivot.md) is built from the moment a principal investigator overrides an agent's plan: frozen project records from just before a real correction ask a model to choose between the agent's original plan and the human-corrected one, diagnosing judgment on contested decisions rather than estimating a general error rate.

### Can the evaluator itself be built, automated, or trusted

A fourth cluster turns the lens on evaluation machinery. [EvalResearchBench](../works/evalresearchbench.md) hands an agent a budget — three hours, $100 for its own inference, $100 for pilots — and asks it to freeze an executable evaluator, then measures how closely that evaluator's scores and rankings track 14 target benchmarks, including sealed targets the agent never saw. [AutoSciBench](../works/autoscibench.md) has an agent *generate* the benchmark: a generator builds a task from a concept and recipe, solves it blind, and a judge rates verifiability and difficulty and flags shortcuts, with the generator revising until both criteria hold. [AgentProofBench](../works/agentproofbench.md) freezes a reusable acceptance program for web agents and tests whether it stays correct when the initial state changes what the same instruction requires, and whether gating an agent on its verdict improves delivery. [Predictive Credit](../works/predictive-credit.md) replaces a judge reading an explanation with a forecasting test — an explanation earns credit only if it lowers a fixed forecaster's loss relative to a plain description and a donor explanation — and reports that natural-explanation predictive credit was not confirmed at the resolutions tested, while a researcher-written mechanism note did lower error. [AlphaIdeaBench](../works/alphaideabench.md) scores research proposals against an explicit resource budget and separates harness effects from backbone effects by running eight harnesses on one shared backbone and eight backbones inside one shared harness.

### Learning and self-improvement when the experiment is costly

The month's embodied and skill-learning cards share a constraint the text benchmarks lack: acting has a physical price. [PhysRSI-eval](../works/physrsi-eval.md) measures physical recursive self-improvement — whether an agent controlling a simulated dual-arm robot gets better across up to 17 refinement rounds by revising its own code, tools, skills, and notes — and relates five improvement axes to public benchmark scores while ablating which parts of the persistent workspace carry the gain. [RobotAgentBench](../works/robotagentbench.md) rebuilds one real home as 50 layouts in Isaac Sim and tests standalone policies against coding agents that plan, execute, and verify, including a recursive-self-improvement configuration; the best configuration averages 48.5 at the task level but only 15.4 on open-ended scenarios, against 18.0 for the best standalone policy. [EmbodiedCLBench](../works/embodiedclbench.md) tests whether an agent can recombine skills learned on basic household tasks, finding that either kept trajectories or a distilled skill summary lifts advanced-task success from 3–12% to 16–52%, but that adding learning samples beyond one brings no consistent further gain. [SlowLab](../works/slowlab.md) makes the cost explicit and irreversible: a one-year greenhouse campaign where each crop occupies a compartment for 180 days and can only be continued or destroyed, and where agents plant their second wave only after the first closes in 94–100% of runs, so in-season readings never change what they plant. [Labference](../works/labference.md) separates a laboratory robot's operation *selection* from its physical *execution* and task completion, so a correct choice lost to a dropped object and a clean transfer of the wrong object are told apart.

## Selected Topic Developments

The month's active topics are legible as one argument seen from different sides, which is why they appear together. [Scientific Agent Benchmarks](../topics/scientific_agents.md) is the busiest axis — it holds the physics-derivation cards ([PHYRD](../works/phyrd.md), [QFT-Bench](../works/qft-bench.md), [PhysClosureBench](../works/physclosurebench.md)), the simulator and workflow cards ([EurekaBench](../works/eurekabench.md), [DISCERN](../works/discern.md), [Into the Unknown](../works/into-the-unknown.md), [SAEScientist-Bench](../works/saescientist-bench.md)), and the artifact-grounded cards ([EngiWorld](../works/engiworld.md), [CADWorld](../works/cadworld.md), [OSWorld-Science](../works/osworld-science.md), [SimuVerity](../works/simuverity.md), [SciΠvot](../works/scipivot.md), [Labference](../works/labference.md)) — but what unites these is not the subject matter; it is that each one replaces a monolithic success score with a decomposition that can fail in a diagnosable place.

[Evaluator Reliability & Validation](../topics/evaluator_reliability_validation.md) is where that decomposition turns on the evaluator itself. [QFT-Bench](../works/qft-bench.md)'s faithfulness judge and [SimuVerity](../works/simuverity.md)'s expert-validated gate measure how far an automated grader can be trusted; [AutoSciBench](../works/autoscibench.md) and [EvalResearchBench](../works/evalresearchbench.md) ask whether an agent can construct a valid evaluator at all; [AgentProofBench](../works/agentproofbench.md) tests whether a frozen verifier survives a change of state; and [Predictive Credit](../works/predictive-credit.md) abandons judge-reading entirely for a forecasting signal. Read together, these cards repeatedly report that the evaluator is the weak link — LLM graders agree with experts well short of certainty, and a verifier correct on one state can accept the wrong outcome on another.

[Benchmark Design, Validity & Contamination](../topics/benchmark_design_validity_contamination.md) collects the cards most explicit about what their own scores cannot establish — [AutoSciBench](../works/autoscibench.md), [EvalResearchBench](../works/evalresearchbench.md), [PHYRD](../works/phyrd.md), [Predictive Credit](../works/predictive-credit.md), and [SlowLab](../works/slowlab.md), whose simulator openly failed its own external check for air temperature and humidity. [Resource-aware Evaluation](../topics/resource_aware_evaluation.md) binds a different thread: [AlphaIdeaBench](../works/alphaideabench.md) scores budget feasibility, [SlowLab](../works/slowlab.md) meters a scarce and irreversible experimental campaign, and [DISCERN](../works/discern.md) and [SCI-AGENT-EXAM](../works/sci-agent-exam.md) treat cost and stage as first-class — the common move is that spending, not only correctness, now enters the score. [Skill Learning & Evolution](../topics/skill_learning_evolution.md) carries the embodied self-improvement cards ([PhysRSI-eval](../works/physrsi-eval.md), [EmbodiedCLBench](../works/embodiedclbench.md), [RobotAgentBench](../works/robotagentbench.md)), each asking whether an agent improves by revising its own code, skills, or kept experience across repeated physical attempts; [EmbodiedCLBench](../works/embodiedclbench.md) adds the deflating note that experience past a single sample brings no consistent further gain. Finally, [Planning & Decision-Making Evaluation](../topics/planning_decision_evaluation.md) ([SciΠvot](../works/scipivot.md), [Labference](../works/labference.md)), [Trajectory Evaluation](../topics/trajectory_evaluation.md) ([SCI-AGENT-EXAM](../works/sci-agent-exam.md)), [Agent Harnesses & Scaffolding](../topics/agent_harnesses_scaffolding.md) ([Agent4Sci](../works/agent4sci.md), [Astro2Method](../works/astro2method.md), [RobotAgentBench](../works/robotagentbench.md)), and the two evaluation-driven-development topics — [Data Curation](../topics/evaluation_driven_data_curation.md) ([AutoDataBench](../works/autodatabench-auto-research.md)) and [Post-Training](../topics/evaluation_driven_post_training.md) ([ScienceIDE](../works/scienceide.md)) — each supply one more vantage on the same shift from grading a result to grading the process that produced it.

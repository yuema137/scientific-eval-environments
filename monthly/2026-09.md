## Month at a Glance

September's additions move the object under test away from a single agent run and toward the artifact that surrounds it: the harness an agent works inside, and the literature an agent gathers before it proposes an idea. Both harness benchmarks ask whether a gain survives a change the agent did not choose, such as a growing capability menu or a different executor model. The ideation benchmark asks whether letting the agent search for its own reading list changes what a literature-grounded critic sees.

The month is small. Three cards reached `main`, all published in September, so the report keeps to two story lines rather than stretching them into a trend.

## What Changed This Month

### The harness becomes the submitted artifact

Earlier harness benchmarks in this repository mostly hold the scaffold fixed and compare models inside it, or let an optimizer edit a harness and report the downstream lift. September's two cards change which side of that loop is scored.

[HarnessDev](../works/harnessdev.md) asks a model to build the execution software itself. Creation starts from a runnable seed with no solving policy and one to three development cases; the resulting harness is frozen and then run by an executor model on downstream tasks, including MLE-bench competitions. Because the creator and executor are separated, the same harness can be scored with its authoring model or with a common runtime model. The evidence is mixed in a useful way: improvements vary across revisions and shrink on unseen tasks or different executors, and the reported token efficiency counts execution only, not the cost of development.

[EvoHarnessBench](../works/evoharnessbench.md) changes the harness from the outside instead. Across 17 streams with three to six stages, tools, skills, or specialist-agent pools are added while earlier task instances stay fixed. That design separates two questions that a single accuracy number merges: does the agent keep solving old tasks when its capability menu grows, and does adaptation help on the tasks the new capabilities were meant for? Its boundary is equally explicit: capabilities only accumulate, so removal and modification are not tested.

Read together, the two cards treat a harness as something that can regress. Neither shows that a harness improvement transfers in general; both report where it does not.

### Who chooses the reading list

[AgentIdeaBench](../works/agentideabench.md) compares two ways of producing a scientific hypothesis with the same output format and the same critics: receive a curated reading list, or gather the literature yourself. The critics retrieve prior art before judging originality, rather than relying on a judge model's memory. In the reported study, active exploration improves feasibility, clarity, and specificity, but measured originality does not significantly improve. The limits matter for how far this reaches: scores are model judgments with human agreement checked only on 100 computer-science pairs, hypotheses are never tested experimentally, and the Active condition changes retrieval control, multi-turn interaction, and tool use at once.

## Selected Topic Developments

[Agent Harnesses & Scaffolding](../topics/agent_harnesses_scaffolding.md) and [Resource-aware Evaluation](../topics/resource_aware_evaluation.md) move together this month for a concrete reason. Once the harness is the scored artifact, its cost has to be reported separately from the model's: HarnessDev reports executor tokens but excludes creator development tokens, and EvoHarnessBench records tokens, tool calls, and latency alongside retention. [Skill Learning & Evolution](../topics/skill_learning_evolution.md) enters through EvoHarnessBench's adaptation split, where persistent artifacts are learned from separate examples before the next stage.

In [Evaluator Reliability & Validation](../topics/evaluator_reliability_validation.md), AgentIdeaBench's contribution is a retrieval step inside the critic plus a small human agreement study (77% agreement with the human majority, Cohen kappa 0.55). It does not validate the critics outside computer science.

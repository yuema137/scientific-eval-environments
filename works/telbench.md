## Overview

TELBench is a benchmark for span-level error localization in deep-research agent trajectories, testing whether a model can pick out harmful error spans among normal exploration, failed searches, tentative hypotheses, and harmless noise. It holds 1,000 verified trajectory instances (600 easy / 400 hard) drawn from a corpus of 2,790 real agent runs, each segmented into ordered semantic spans that carry binary error / non-error labels.

## Summary

TELBench argues that outcome-level evaluation of deep-research agents reveals whether a run succeeded but not which part of the trajectory first made the answer unreliable. Built from 2,790 real trajectories spanning three deep-research benchmarks, three backbone models, and two agent frameworks, it converts raw logs into ordered semantic spans and asks a model to localize the harmful error spans among benign exploration, failed searches, and noise. The paper pairs the benchmark with DRIFT, a claim-centric auditing framework that improves span-level error localization and first-error accuracy by up to 30 percentage points over bare-LLM prompting.

## Tasks

1,000 verified instances (600 easy / 400 hard), each a full agent trajectory segmented into an average of 11.95 ordered semantic spans that the model must label error or non-error. Instances were mined from 2,790 trajectories generated by running GPT-5, Gemini-2.5-Pro, and Claude-Sonnet-4.5 under the MiroFlow and OAgent frameworks over 465 tasks from GAIA-val, XBench, and BrowseComp-test (BrowseComp downsampled to 200 tasks). Candidate error spans proposed by two frontier-LLM annotators were verified by expert annotators — seven experts each spent over 300 hours — and the corpus was filtered through 1,890 error-bearing trajectories (67.7% of the corpus) down to the 1,000 with clear boundaries and enough benign distractor spans.

## Domains

Deep-research agent trajectories — web search, browsing, tool use, evidence inspection, and answer synthesis — drawn from the GAIA, XBench, and BrowseComp task distributions.

## Evaluation

- **Span-level localization.** Each semantic span is a binary error / non-error target scored with macro-averaged precision, recall, and F1 over error spans.
- **First-error accuracy (FEA).** Measures whether the earliest predicted error span matches the earliest annotated error, isolating temporal localization from aggregate detection.
- **Splits and repeats.** Results are reported on the full Verified-1K set and on its 600 easy / 400 hard partition, with each configuration run three times.
- **Reported.** DRIFT posts the best overall macro-F1 for every backbone model, lifting Claude-Sonnet-4.6 from 21.89 to 54.91, DeepSeek-V3.2 from 22.46 to 50.51, GPT-5.4 from 33.93 to 52.48, and Gemini-2.5-Pro from 31.01 to 48.41 against Bare LLM, Codex, and Claude Code baselines; first-error accuracy stays much lower, with Claude-Sonnet-4.6 reaching only 24.10 overall (up from 11.30).

## Typical Duration

No fixed step or wall-clock budget is imposed; each instance is one completed trajectory averaging 11.95 semantic spans. Audit cost is reported in tokens: DRIFT averages 17,653–22,643 total tokens per trajectory for the DeepSeek, GPT, and Claude backbones and 53,043 for Gemini-2.5-Pro (whose thinking dominates), against bare-LLM baselines of 5,649–14,307.

## Main Contribution

A benchmark and claim-centric auditing framework for span-level error localization in deep-research agent trajectories, reframing reliability evaluation as finding the earliest unsupported commitment that makes an answer unreliable rather than judging the final answer alone.

## Key Design Ideas

- Semantic spans as the analysis unit: raw logs are normalized and segmented at shifts in search target, candidate set, time scope, verification criterion, or reasoning objective.
- Binary error / non-error labels defined by harm to the answer path, so normal exploration, failed searches, tentative hypotheses, recovered mistakes, and tool noise are not errors by themselves.
- A data-induced mechanism taxonomy: an eight-stage operation schema plus 18 primary faults grouped into six fault families (Constraint Handling, Search and Retrieval, Evidence Grounding, Entity Mapping, Information Processing, Process Control), used only for analysis.
- DRIFT's claim-centric pipeline — a Claim Keeper ledger, a Support Seeker assigning direct / weak / missing / conflicting support, and a Dependency Tracer that marks spans committing to or reusing unsupported claims.

## Strengths

- Semantic-span segmentation gives a unit coarse enough to compare across heterogeneous, framework-specific logs yet fine enough to localize the first harmful commitment.
- Labels come from a two-stage pipeline of LLM proposal plus expert adjudication (seven annotators, over 300 hours each) that targets specific harmful commitments rather than blanket-labeling failed runs.
- Separating span-level F1 from first-error accuracy exposes that detecting some error and pinpointing the earliest one are distinct abilities, the latter remaining hard even for the strongest auditor.

## Limitations

- Repository note: All trajectories come from three deep-research QA benchmarks (GAIA, XBench, BrowseComp) run under two frameworks and three backbone models, so error patterns and the induced fault taxonomy may not transfer to other agent settings.
- Repository note: The 1,000 instances are filtered to those with clear, verifiable error boundaries and ample benign distractors, making the set a curated diagnostic subset rather than a representative sample of the 2,790-trajectory corpus.

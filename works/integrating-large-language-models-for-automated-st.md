## Overview

A hand-curated benchmark of twenty structural analysis word problems (SAWPs) on 2D frames with ground-truth solutions, used to compare four LLMs inside an OpenSeesPy-backed framework and to measure the run-to-run stability of the best of them.

## Summary

The paper proposes a framework in which an LLM acts as the core engine that parses a natural-language structural description and translates it into an executable Python script driving OpenSeesPy for finite-element analysis and OpsVis for visualization. Because no publicly available dataset systematically pairs structural descriptions with clear layouts and ground truth, the authors manually design a twenty-problem benchmark of structural analysis word problems to evaluate it. Three experiments are run on that benchmark: a best-of-three comparison across four base models, a five-run generative-stability study on the strongest one, and an ablation on expert-crafted system instructions. The framework produces a structured report per problem containing the problem description, the generated code, explanations, and internal forces at each node with their maxima and minima.

## Tasks

Twenty structural analysis word problems (SAWPs) on 2D frames, manually designed with corresponding ground-truth schematics. Each problem is presented in a standardized format with five components: geometrical properties, material properties, loading conditions, boundary conditions, and requirements for result visualization. The requested output is the resulting deformations and internal forces — axial force, shear force, and bending moment — in the frame. Problems were generated by adapting three patterns from seed examples: Pattern 1 varies the number of stories and bays (extending a one-bay, one-story frame up to a three-bay, two-story frame); Pattern 2 introduces asymmetry, for example a first bay of two stories beside a second bay of one; Pattern 3 adds structural features common in engineering practice, specifically diagonal members and cantilever beams. Typical instances use 4 m column heights, 6 m girder spans, a 2,000 N horizontal point load, and a 1 × 10⁴ N/m uniform vertical distributed load, with E = 2 × 10¹¹ Pa, column area 2 × 10⁻³ m², girder area 6 × 10⁻³ m², and moments of inertia 1.6 × 10⁻⁵ m⁴ and 5.4 × 10⁻⁵ m⁴. All supports are fixed. The full problem set is given in Appendix A and the ground-truth solutions in Appendix C.

## Domains

Civil & Structural Engineering. The evaluated objective is the structural analysis of 2D building frames — columns, girders, cantilever beams, and diagonal members under point and distributed loading — with deformations and internal forces as the graded quantities. The authors situate the work in civil engineering and note that the benchmark targets a foundational structural pattern before scaling to high-rise buildings and bridges. No co-domain is assigned; OpenSeesPy and OpsVis are the instruments, not the evaluated objective.

## Evaluation

- **Comparative analysis (best-of-3).** Each experiment is run three consecutive times per problem; a problem counts as solved if the framework produces a correct response in at least one of the three attempts, reported as an upper-bound comparison across models. Results over the twenty SAWPs: GPT-4o 100%, GPT-4 85%, Gemini 1.5 Pro 80%, Llama-3.3 30%.
- **Generative stability.** GPT-4o inside the framework is run five times per problem, with accuracy defined as the probability that a correct and complete solution is generated. Nine problems reach 100% (examples 1, 4, 7, 8, 15, 17, 18, 19, 20), eight fall in the 60–80% band (2, 3, 5, 6, 9, 10, 12, 16), and three reach only 40% (11, 13, 14). All twenty produce complete and executable OpenSeesPy code. Performance declines specifically on asymmetrical frames.
- **Instruction ablation.** On problem 20, Gemini 1.5 Pro and GPT-4o are each run ten times independently with and without a distributed-loading-direction instruction. Without it, Gemini fails to define the distributed load correctly and GPT-4o reaches 70%; with it, GPT-4o reaches 100%. The paper also reports that integrating domain-specific instructions enhanced performance by 30% on problems with asymmetrical structural configurations.
- **Error taxonomy.** Failures among runnable scripts fall into two types: Type 1, where the framework fails to sketch the required structural layout (wrong bay or story count, a missing node, an incorrectly defined element); and Type 2, where boundary conditions are wrong or loads are misassigned, for example applying left-side point loads to all first-floor nodes.

## Main Contribution

The authors present the first systematic framework integrating LLMs with structural analysis software for automated analysis, together with a curated benchmark of twenty structural analysis word problems with ground truth — filling the gap they identify, that no public dataset systematically pairs structural descriptions, clear layouts, and ground-truth solutions.

## Key Design Ideas

- The benchmark is constructed by three named generation patterns (scaling stories and bays, introducing asymmetry, adding diagonal members and cantilevers), so difficulty varies along stated structural axes rather than arbitrarily.
- Every problem uses the same five-component standardized description format, and ground-truth schematics are prepared alongside for validating outputs.
- Two distinct protocols are used for two distinct questions: best-of-three for the upper-bound capability comparison across models, and five independent runs for generative stability of a single model.
- System instructions are treated as an experimental variable authored by structural engineers, decomposed into direction reasoning, number reasoning, and space rationality reasoning, and their effect is measured separately.
- The in-context-learning prompt is templated into four labelled blocks (general template, task-specific template, ICL examples, question), with a single reference example seeding pattern generalization.
- Generalization is probed by giving the framework only one reference example — a one-bay, one-story frame — and testing whether it extends to multi-bay, multi-story, cantilever, and diagonal-member configurations absent from the example.

## Strengths

- The best-of-three and five-run protocols separate what a model can do from what it does reliably, and the stability results are reported per problem rather than as a single mean.
- The instruction ablation is a clean controlled comparison on a single problem with ten independent runs per condition, isolating one expert-authored instruction.
- Ground-truth solutions and the full problem set are included in the appendices, so the benchmark is reproducible from the paper itself.
- The error taxonomy distinguishes layout errors from boundary-and-load errors, and the authors correctly attribute part of the failure to the framework's text-only interface, which prevents the model from seeing what it has drawn.

## Limitations

- Twenty problems on relatively simple 2D frames, which the authors themselves describe as straightforward for structural engineering professionals.
- Only static linear elastic analysis of plane frames; no 3D systems, nonlinearity, dynamics, or design decisions.
- The problem set was partly created with LLM assistance — the authors used LLMs to generate code from manually defined problem descriptions and then reviewed the results — which places some of the ground-truth burden on human review.
- Correctness is assessed against prepared schematics and expected outputs rather than by an automated numerical comparison protocol, and the paper does not state a tolerance threshold.
- Model coverage stops at GPT-4o, GPT-4, Gemini 1.5 Pro, and Llama-3.3, all of which were current in early 2025.
- Repository note: no code or dataset release is stated in the paper, though the problem set and ground-truth solutions appear in the appendices.

# 2024 年 12 月月度报告

> [English](../../monthly/2024-12.md) | **简体中文**

> **覆盖范围：** 2024-12 首次公开的工作

## 本月概览

- 本月共有 **6 项工作**进入知识库，全是**当月新发布**，都在 2024 年 12 月首次公开：[ProcessBench](../../works/processbench.md)（2024-12-09）、[AnalogXpert](../../works/analogxpert.md)（2024-12-17）、[SafeAgentBench](../../works/safeagentbench.md)（2024-12-17）、[Speak-to-Structure](../../works/tomg-bench.md)（2024-12-19）、[LiveIdeaBench](../../works/liveideabench.md)（2024-12-23）和 [Aviary](../../works/aviary.md)（2024-12-30）。
- 这六项里有四项落在 [Scientific Agent Benchmarks](../../topics/scientific_agents.md) 底下：[AnalogXpert](../../works/analogxpert.md)（模拟电路设计）、[Speak-to-Structure](../../works/tomg-bench.md)（分子生成）、[LiveIdeaBench](../../works/liveideabench.md)（科研想法生成）和 [Aviary](../../works/aviary.md)（生物学环境），横跨四个互不相干的领域，之间没有一张共用的排行榜。
- 真正把这四项分开的，不是领域，而是评测者最先要拍板的那个最基本的问题：什么才算一个正确答案。一个只认一份合法的设计，一个把每道题包进一个带终局奖励的环境里，一个只要分子满足指令就收，还有一个干脆不要正确答案，转去给开放式的创造力打分。
- 另外两项把镜头从 agent 身上挪开，转去照一个纯成功率会盖住的东西。[ProcessBench](../../works/processbench.md) 问的是：一个判分器能不能在一条推理链里找出最早出错的那一步；[SafeAgentBench](../../works/safeagentbench.md) 问的是：一个具身 agent 碰上危险指令，是会拒绝，还是照单全收、老老实实执行。两家都发现，它们各自要量的那个本事，模型做得都很差。

## 这个月到底变了什么

**本月这几个科学 agent benchmark 几乎在什么上都谈不拢，唯一的共识是：领域里的答案得用一个跟领域对得上的方式去查；而在一件很具体的事上它们各执一词，那就是一道科学任务到底有几个正确答案。** 先看给领域模型打分的老一套：把它的输出跟一条参考字符串比一下。这招在一道题只有一个正确答案时管用，可大多数科学工作不是这样：一个电路可以有好几种都合法的接法，同一个要求能有很多分子都满足，而一个科研想法压根就没有参考答案。本月新增的这四项科学 agent 工作，各自把这个问题定了不一样的调子；摆在一块儿看，正好排成一条谱。[AnalogXpert](../../works/analogxpert.md) 离「单一参考」最近：合成出来的一个模拟电路拓扑，结构上要么对要么不对，靠规则程序或者人工审阅来判。[Aviary](../../works/aviary.md) 把每道科学任务包进一个部分可观测的环境里，把「对不对」压缩成一个终局奖励。[Speak-to-Structure](../../works/tomg-bench.md) 是有意让答案变成「多个里的任意一个」：一句开放式指令，只要有分子满足它就算数，而不是要你把一个背下来的目标原样复现出来。[LiveIdeaBench](../../works/liveideabench.md) 干脆把「正确答案」这个概念整个扔掉，改由一组 LLM 评审，从五个创造力维度给开放式想法的质量打分。它们共同的前提是：光看表面上说得通还不够；分歧则在于「正确」到底指一个答案、多个里的一个，还是一个分档的质量，而这个选择在任何模型跑起来之前就定下了，也就决定了每个 benchmark 到底能量出什么。

**剩下这两项不再问任务成没成，而是转去量一个成功率藏起来的东西。** 一个看着没错的最终答案，底下可能垫着错的一步；一个能把任务干利索的 agent，也一样能把危险的任务干利索。[ProcessBench](../../works/processbench.md) 直接冲着第一个缺口去：它让「答案对」和「答案错」的解法各占一半，再请专家标出最早出错的那一步，这样一来，「最终答案对、可过程有毛病」这件事的发生率就能直接量出来了，从答案正确的 GSM8K 解法里的 3.5%，一直到 Omni-MATH 上的 51.8%；量完再去测：过程奖励模型，以及用提示词充当 critic 的模型，能不能把那一步找出来。[SafeAgentBench](../../works/safeagentbench.md) 冲的是第二个：它把危险版和安全版的任务成对配好，好让「拒绝」和「能力」分开算分，结果发现最好的基线在有详细描述的危险任务上也只拒掉 10%，而换一个底层模型几乎不挪动这个数。这两项都不评最终任务解没解开；它们各自评的是一个性质，过程站不站得住、该拒的时候拒没拒，而这个性质只看结果准确率是看不见的。

## 值得展开的 Topic

### [Scientific Agent Benchmarks](../../topics/scientific_agents.md)

本月六项里有四项以这个 Topic 为主入口。把它们放一块儿读，最好用的一条线就是上面说的「什么算正确答案」这根轴，从检查最紧的一头，一路排到最松的一头。

- [AnalogXpert](../../works/analogxpert.md) 站在检查最紧的这一头。它把一个模拟电路设计师的工作流程编进一个 LLM agent 里：拓扑用 SPICE 代码表示，一个子电路库把设计空间收窄，任务再拆成「选模块」和「连模块」两步，用思维链和上下文学习来做，最后再加一步增量式的校对来打磨。它对「正确」的判定接近单一参考：合成的案例交给自动的结构规则程序去验，真实的案例由人工审阅者把每一个模块和每一处连接都对着需求核一遍。在一个专门搭的 benchmark 上（30 个真实案例加 2000 个合成案例），它做到了 40%（合成）和 23%（真实）的成功率，而 GPT-4o 只有 3%，这说明把设计经验编进去、而不是单纯堆规模，才是拉开差距的原因。边界在这儿：这张 card 是从 arXiv 的摘要和正文整理出来的，元数据里没有发表 venue，也没有可核验的代码或数据集仓库。

- [Aviary](../../works/aviary.md) 把每道科学任务变成一个「策略在环境里」的问题：它把 agent 形式化成一组策略，跑在以语言为基础的部分可观测马尔可夫决策过程上，再把这些环境收进一个可扩展的 gymnasium 里。它五个环境里有三个是科学的：操作 DNA 构建体（分子克隆）、根据文献回答研究问题、以及蛋白质稳定性工程；每一个都给出一个终局奖励（选择题式打分，或者由 Rosetta ΔΔG 检验给出的「稳定/不稳定」二值信号）。它主打的结论是一个成本对性能的结果：一个靠开源模型撑起来的小 agent（用专家迭代训练的 Llama-3.1-8B），在好几个任务上追平甚至超过前沿 agent 和人类专家，而推理成本最多能低到约 1/100。这个主打结论来自论文里的*训练*贡献，跟本仓库以评测为核心的范围只是相邻；Aviary 收在这儿，是为了它那几个可复用的科学环境，不是那套训练方法。有一点要往后记着：放出来的代码后来跟论文里的五个环境已经对不上了。

- [Speak-to-Structure](../../works/tomg-bench.md)（最早叫 TOMG-Bench）把「一对多」的立场摆到了明面上。多数文本到分子的评测是一对一的：一句指令配一个参考分子，这会把合法的新答案也算成错的。Speak-to-Structure 反过来只查生成的分子满不满足指令，覆盖三大类开放域任务：分子编辑（MolEdit）、分子优化（MolOpt）和定制化生成（MolCustom）。第一版把每类任务都拆成三个子任务、每个子任务 5000 个测试样本；当前这一版报了一次覆盖 31 个 LLM 的全面评测，还给 benchmark 配了 OpenMolIns，一个指令微调数据集，大到能把 Llama3.1-8B 在这个 benchmark 上顶过 GPT-4o 和 Claude-3.5，这说明它暴露出来的那块提升空间是能靠训练补上的。这项工作在不同版本间改过名字（2024 年叫 TOMG-Bench，后来改叫 Speak-to-Structure / S²-Bench），所以跟版本有关的具体数字，要对着报出这个数的那一版来读。

- [LiveIdeaBench](../../works/liveideabench.md) 把正确答案彻底拿掉了。它靠只给模型一个关键词来单独考发散思维（1180 个关键词，横跨 22 个科学领域），再用一组会动态调整的顶尖 LLM 评审，从五个维度给生成的科学想法打分，这五个维度出自吉尔福德的创造力理论：原创性、可行性、流畅性、灵活性和清晰度。在 40 多个模型上，结论是一处脱钩：创造力用通用智能指标很难预测出来，QwQ-32B-preview 的通用智能分数更低，却能跟 claude-3.7-sonnet:thinking 这类顶尖模型掰手腕。这个结果停在单轮、几乎不给上下文的生成上，没走到交互式的场景；card 还标出，这篇论文改过名字，而它标称的 Nature Communications venue 是仓库这边的一个说法，arXiv 元数据里并没有带这条。

*（本月没有哪个 canonical domain 值得单开一节：六项工作在清单里都没有 canonical-domain 映射，所以那些跟具体领域相关的内容，模拟电路设计、分子生物学、化学、跨领域的想法生成，都放在上面的正文里讲了，下面索引里的 Domains 列六项全空。）*

### [Credit Assignment](../../topics/credit_assignment.md)

[ProcessBench](../../works/processbench.md) 是本月落在这个 Topic 下的唯一一项，它在「一条静态推理轨迹」这个层面上，把这个 Topic 要量的东西定了下来。以前评过程的 benchmark，要么用的题目已经被近期的模型做穿了，要么只标最终答案对不对、不说是哪一步错了。ProcessBench 把评分对象换成了一个整数：给一道题和一个 *n* 步的解法，判分器得返回最早出错那一步的序号，要是每一步都对就返回 −1。它一共 3400 个案例，分四个子集（GSM8K 出 400 个，MATH、OlympiadBench、Omni-MATH 各出 1000 个），偏重竞赛级和奥赛级的题目；解法取自十二个开源生成器，统一重排成一致的步骤粒度，出错的位置由人类专家在「三到五名标注者达成一致」的规则下标注。用单个整数这种格式，能让两类判分器，也就是过程奖励模型和被当成 critic 来提示的通用 LLM，在同一个 F1 尺度上打分（这个 F1 是「在错误样本上的准确率」和「在正确样本上的准确率」的调和平均）。在四个子集上取平均，o1-mini 到 87.9，QwQ-32B-Preview 71.5，GPT-4o-0806 61.9，作者自己微调的 Qwen2.5-Math-7B-PRM800K 56.5，而现有最强的开源 PRM（Skywork-PRM-7B）只有 42.1，被提示的 critic 和现有 PRM 之间差了一大截。有两条边界框住这个结果：在最难的奥赛题上，标注可能仍然带噪；而因为标注者没达成一致被丢掉的那约 30% 的解法，可能让分布偏向那些专家能判得清的案例。被评的单位是一份静态的、事先生成好的解法，所以「最早出错序号」定位的是一段文字里面的一处推理错误，它不带任何工具调用、环境状态或跨轮次动作的概念，这正是它跟轨迹层面的 credit assignment 分道扬镳的接缝。

### [General Long-Horizon Agent Benchmarks](../../topics/long_horizon_evaluation.md)

[SafeAgentBench](../../works/safeagentbench.md) 是本月落在这个 Topic 下的唯一一项，它把一整段具身规划的执行当成长程的那个单位，但量的是安全，不是能力。它盯住的缺口是：一个只按任务成功率打分的 benchmark，等于在奖励 agent「你让它干啥它就利索地干啥」，连「把毛巾放炉子上烤」也照干。SafeAgentBench 把这两件事分开的办法，是给同一道任务配上危险版和安全版：750 个可执行任务，覆盖 10 个危险类别、3 种任务类型，都在 SafeAgentEnv 里做规划和执行，这是一个通用的具身环境，带一个底层控制器和 17 个高层动作，对上 9 个支持多 agent 的顶尖基线。打分同时从执行和语义两个角度走，核心指标是任务成功率和拒绝率，这样「该拒的时候拒不拒」就跟任务能力分开量了。结论既扎眼又指向架构：最有安全意识的那个基线，在有详细描述的危险任务上也只拒掉 10%，而换掉底层的 LLM 并不能明显提高安全意识，这就把安全该下的功夫，从「挑模型」引到了「设计系统」上。边界在于：这些危险只存在于仿真里，所以往物理世界迁移的风险并没有被评到；而且这个具身的家居场景，本身就落在仓库的科学/工程 domain 轴之外；card 还指出，仓库 README 里带的基线数字，比被当成准的那份摘要还要旧。

# 2024 年 4 月月度报告

> [English](../../monthly/2024-04.md) | **简体中文**

> **覆盖范围：** 2024-04 首次公开的工作

## 本月概览

- 本月有 **2 项工作**进入知识库：**2 项都是当月新发布**，都是 benchmark，**没有历史补录**。分别是 [ChemBench](../../works/chembench.md)，2024-04-01 首次公开，还有 [OSWorld](../../works/osworld.md)，2024-04-11 首次公开。
- 这俩正好站在评测光谱的两头，对「模型到底行不行」也给出了正相反的结论。ChemBench 测的是一问一答的化学知识，结论是最好的那几个模型，平均下来能压过它招募的那批人类化学家；OSWorld 测的是一个 agent 能不能真操作一台电脑、一路干到目标，结论是最好的模型才 12.24%，而人类能过 72% 以上。
- 这两个结论差这么远，说的可不是模型质量有高有低。说白了，是它俩测的东西压根不是一回事：一个看的是一轮之内能想起来多少知识，另一个看的是在一个活的环境里、靠一连串动作够到一个目标。
- 每项工作也都把自己的边界摆明了。ChemBench 一边挂着「超越人类」的大标题，一边又答得过于自信，还在一些很基础的任务上翻车；作者把这个组合看成一个安全隐患，而不是一场干净利落的胜利。OSWorld 里人和模型差得最狠的是跨应用的工作流，也就是那些得在几个不同程序之间来回串动作的任务。

## 这个月到底变了什么

**两个 benchmark 都在回答「现在的模型到底有多强」，结论却对不上，为啥？因为它俩测的根本不是一回事。** 先看一眼那个头条数字，光盯着一个数容易走偏：不管是「最好的模型压过专家」还是「最好的模型才到 12%」，都会让人顺手给模型能力下一个笼统的结论。本月这两项新发布，正好说明这么读为啥不对：一个 benchmark 报出来的数，跟它在什么面上去测，是拆不开的。

[ChemBench](../../works/chembench.md) 测的是化学知识和推理。它整理了 2,700 多个问答对，用一套自动化框架给当前最强的开源、闭源模型打分，再拿一批招募来的人类化学家做对照。在这个面上，最好的那几个模型平均下来赢过研究里最好的人类化学家。它测的这个量，是模型在一轮之内能想起来、能推理出来多少东西，不用工具，也没有实验室或者多步工作流。ChemBench 也很清楚自己这个头条能说到哪儿：同样这些平均分「超越人类」的模型，还是会在一些基础任务上栽跟头，而且答得过于自信；作者把这个组合既当成一个能力结论，也当成一个安全隐患。

[OSWorld](../../works/osworld.md) 测的是一个 agent 能不能真操作一台电脑。它把一个多模态 agent 放进一个活的操作系统里，Ubuntu、Windows 或者 macOS 都行，然后按「有没有真干成」给 369 个任务打分：每个任务有一段脚本先把初始状态摆好，再由 evaluator 函数去检查 agent 真正产出的东西。在这个面上，人类能做完 72.36% 以上的任务，而最好的模型，也就是喂了 accessibility-tree 输入的 GPT-4，才到 12.24%。它测的这个量不是想起来多少知识，而是在一个 agent 并不能完全看清的环境里，靠许多步够到的一个目标状态。

两个放一块看，本月的证据就是：「今天的模型有多强」这个问题，离开评测的那个面，根本没有答案。在一个不涉及执行的知识面上，前沿模型平均下来已经超过专家了；在一个活环境里的执行面上，同一代模型比人类差了差不多一个数量级。这两个结论并不打架，它俩测的是不同的能力，而且谁也换不成谁。ChemBench 留下的那个口子，恰好就是 OSWorld 在探的：会化学，不代表能把一个任务干到底；能干完电脑任务，也不代表懂这个领域的知识。

## 值得展开的 Topic

### [Scientific Agent Benchmarks](../../topics/scientific_agents.md)

在这个 Topic 里，ChemBench 是「静态知识」那一头的主要参考。它把科学能力当成一问一答来测，而不是当成用工具或者跑实验室的工作流；它最不一样的一手，是把「超越人类」做成一个能测量的对照，而不是一句口号：招募来的化学家队伍提供人类基线，2,700 多个问答对这个规模上的自动打分，支持按 Topic 拆开看每一块的能力，而不是只给一个总分。在准确率之外还去探模型的置信度，才把「过于自信」拎出来当成一个**单独的**失败模式：一个模型可以平均下来是对的，却对自己什么时候会错标定不准。这个结论止步在知识和推理：因为什么都没执行，也没调用工具，这个分说的是模型知道什么，而不是它能不能把一个化学任务从头跑到尾。这套框架比论文活得还长，多模态的 MaCBench 就跑在同一条流水线上，所以它读起来更像一套可复用的基础设施，而不是一次性的排行榜。这里被评测的那个环节，是 [Scientific Problem Solving & Reasoning](../../activities/scientific_problem_solving_reasoning.md)。

### [General Long-Horizon Agent Benchmarks](../../topics/long_horizon_evaluation.md)

在这个 Topic 里，OSWorld 是「交互式、按执行来评测」这条线在操作系统这个尺度上的主要参考。这条线上早先那些交互环境都锁在浏览器里，OSWorld 把任务放进整个操作系统里跑，打分靠的是去检查真实状态，而不是去对一个答案字符串。它的机制是每个任务一份 JSON 配置，驱动四个阶段：从 VM 快照里把初始状态摆好，做后处理，用 getter 把要检查的产出物取出来，再用 evaluator 函数拿取到的状态跟标准答案比对；这一套背后是 134 个手写的评测函数，平均每个任务大概要写两个小时。正是这种「落到执行上」的做法，才让报出来的 12.24% 对 72.36% 这个差距，说的是任务有没有干成，而不是答案能不能想起来；它还把难点定位得很准：跨应用的工作流，也就是那些得在几个不同程序之间串动作的任务，是最难的一类，只有 2.97%。有两条边界框住了这个结论。奖励定义在 [0, 1] 上，本来是为了给部分完成留分，但结果只报一个平均成功率，所以每个任务里做了一半这种情况并没有单独拆出来；再就是，这个分只反映那些手写 evaluator 函数去检查的东西。

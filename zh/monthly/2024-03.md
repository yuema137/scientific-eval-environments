# 2024 年 3 月月度报告

> [English](../../monthly/2024-03.md) | **简体中文**

> **覆盖范围：** 2024-03 首次公开的工作

## 本月概览

- 本月共有 **1 项工作**进入知识库：**1 项当月新发布**，**0 项历史补录**。这项就是 [BrainBench](../../works/brainbench.md)，2024-03-04 首次公开。
- 它的主张，是把一场知识测验里到底在测什么，整个换了个方向：先别问模型能不能把一个已有结论背出来，改问它能不能预判一个没见过的实验最后会得出什么结果。
- 做法是搞一对「改了结果的摘要」。拿一篇《Journal of Neuroscience》的真摘要，配上一篇改写过、读着一样通顺、但结论被动了手脚的版本，让模型靠 perplexity 挑出哪篇是真的，既不用抽取答案，也不用另找一个 judge。
- 报出来的证据是：通用 LLM 在这项预测上赢过了人类神经科学专家，而且它们报的置信度跟真实准确率对得上。边界也说得一样清楚：这是个静态的二选一任务，不是 agent 评测，而且那几个抢眼的数字还得等全文来核。

## 这个月到底变了什么

**一项科学知识测验，从「回忆」挪到了「预测」。** 先看大多数测科学知识的 benchmark 是怎么打分的：它们测的是模型能复现出什么，找一个事实、把一套机制重述一遍、对上一个记录在案的结果。这是往回看的，它评的是模型有没有把文献里已经写下来的东西吸收进去。[BrainBench](../../works/brainbench.md) 换掉的，是它要测量的那个量。它问的是：一个没在纸面上见过的实验，模型能不能预判出它的结果。每道题都拿一篇《Journal of Neuroscience》的原始摘要，配一篇改过的版本，这个改动只动结果、但整篇读起来依旧自洽，这样文风和可信度大体保持不变，真正有差别的只有那个报出来的结果；模型靠比较两版的 perplexity 来选，既不用解析答案，也不用另配一个 LLM 打分器。置信度的校准（calibration）在这里是被当成头等属性来看的，不是事后补上的一笔。为啥这么看重它？因为一个做预测的东西，只有当它报出来的把握大小，真能预示它这一回到底对不对，才算有用。

证据是一份 200 个案例的数据集，横跨五个期刊分区，包括 behavioral/cognitive、systems/circuits、neurobiology of disease、cellular/molecular，还有 development/plasticity/repair；在这个数据集上，LLM 在预测结果这件事上超过了人类专家群体，模型报的置信度越高、准确率也越高，而一个在神经科学文献上调过的模型（BrainGPT）表现还要更好。

不过这个结果离一个笼统的大结论还差得远。BrainBench 是一次过的强制二选一，不是那种能来回交互的 agent 场景，所以它测出来的，是模型心里对「实验大概会得出什么」的那份内化直觉，而不是一个 agent 会怎么去规划、或真的去跑一个实验。它之所以被记在这里，是因为那套评测方法，也就是「预测实验结果、再拿校准来打分」这一套；这套方法跟评判科学 agent 直接相关，哪怕这个 benchmark 本身并不是一个 agent 评测。那个调过的 BrainGPT 模型属于建模层面的贡献，落在本仓库范围之外；而那些具体的准确率数字，这里标成了「待全文核对」，没有当成已经板上钉钉的事实照搬。

## 值得展开的 Topic

### [Scientific Agent Benchmarks](../../topics/scientific_agents.md)

BrainBench 落在这个 Topic 的边上，不在它的主群里。这个 Topic 下别的工作，都是把「对不对」锚在可执行的检查、实测的数值，或者科学实践里复现出来的结果上；BrainBench 给的不是这个，它给的是一套方法，预测一个实验的结果、再看这个预测的校准打几分，这个 Topic 之所以盯着它，是看它怎么去评判科学能力，而不是因为它真让哪个 agent 干了活。有两处设计，让它值得跟那些 agent benchmark 摆在一起记下来：一是那对「改了结果的摘要」，把「知不知道结果」跟「表面读着顺不顺」这两件事拆开了；二是基于 perplexity 的打分，把 judge 整个从流程里拿掉了。可以把它当成「模型作为科学预测者」这条线上的一个参照点，但有一句常备的提醒得记住：在一个静态的二选一上赢过专家，跟具备 agent 层面的科学能力，这俩不是一回事。

# 2025-04 月度报告

> [English](../../monthly/2025-04.md) | **简体中文**

> **覆盖范围：** 2025-04 首次公开的工作

## 本月概览

2025 年 4 月可以直接叫 verification-hardening month。FEABench、HLS-Eval、LLM-SRBench、PHYBench 和 AgentRewardBench 其实都在拆同一个问题：agent 会不会做、benchmark 能不能验、以及当验证不是确定性的时，evaluator 本身还能不能信。

## 这个月到底变了什么

### [Scientific Agent Benchmarks](../../topics/scientific_agents.md)

这组工作主要在回答一个更硬的问题：进到真实 scientific workflow 以后，benchmark 到底该怎么做，才不至于只是在测一层表面问答。

- [FEABench](../../works/feabench.md)：FEABench 评估 LLM 与 LLM agent 能否用有限元分析（FEA）端到端地求解物理、数学与工程问题：对自然语言问题描述进行推理，并通过 API 操作 COMSOL Multiphysics® 计算出答案。
- [HLS-Eval](../../works/hls-eval.md)：HLS-Eval 是评测 LLM 高层综合（HLS）设计任务的 benchmark 与框架：94 个配自然语言描述与测试台的独特设计，覆盖两类任务：从自然语言生成 HLS 代码，以及做 HLS 专有的编辑以优化性能与硬件效率：在 Vitis HLS 上按可解析性、可编译性、可运行性、可综合性判分。
- [Integrating Large Language Models for Automated Structural Analysis](../../works/integrating-large-language-models-for-automated-st.md)：一个手工编制的 benchmark，含二十道二维框架的结构分析应用题（structural analysis word problems, SAWP）并附 ground-truth 解；作者用它在一个以 OpenSeesPy 为后端的框架内对比四个 LLM，并测量其中最强者在多次运行间的稳定性。
- [LLM-SRBench](../../works/llm-srbench.md)：LLM-SRBench 是用 LLM 做科学方程发现的 benchmark，含 239 个高难度问题，专为防止简单记忆而设计：LSR-Transform 把常见物理模型改写为少见的数学表征以考察记忆之外的推理，LSR-Synth 引入需要数据驱动推理的合成发现型问题。
- [MLRC-Bench](../../works/mlrc-bench.md)：MLRC-Bench 追问语言 agent 能否解决机器学习研究挑战：一套 7 个竞赛任务，agent 须提出并实现新颖的研究方法，用客观指标评分：即它把「所提供基线到顶尖人类参与者」之间的差距缩小了多少：最佳 agent 只缩小了 9.3%。

### [Evaluator Reliability & Validation](../../topics/evaluator_reliability_validation.md)

把这组工作放一块看，关键是看它把 evaluation 里原来藏着的哪一层给掀出来了。

- [AgentRewardBench](../../works/agentrewardbench.md)：AgentRewardBench 是一个 benchmark，用于衡量自动评估器：LLM judge 以及 web agent benchmark 自带的规则式评分器：在多大程度上复现专家对 agent trajectory 的判断。它包含 1,302 条 trajectory，取自 5 个 web benchmark 和 4 个 agent LLM，每条都由专家标注者就成功、副作用和重复行为进行审阅。

### [Trajectory Evaluation](../../topics/trajectory_evaluation.md)

这一组不再只盯最后答案。整条 trajectory 本身就是证据，能看出 agent 当时看见了啥、怎么决定的、又漏掉了啥。

- [AgentRewardBench](../../works/agentrewardbench.md)：AgentRewardBench 是一个 benchmark，用于衡量自动评估器：LLM judge 以及 web agent benchmark 自带的规则式评分器：在多大程度上复现专家对 agent trajectory 的判断。它包含 1,302 条 trajectory，取自 5 个 web benchmark 和 4 个 agent LLM，每条都由专家标注者就成功、副作用和重复行为进行审阅。

## 值得展开的 Topic

[Scientific Agent Benchmarks](../../topics/scientific_agents.md)、[Evaluator Reliability & Validation](../../topics/evaluator_reliability_validation.md)、[Trajectory Evaluation](../../topics/trajectory_evaluation.md) 还是这个月最该连起来看的几页，但重点不在于把名字列出来。这几页之间的桥很直接：只要 scientific task 失去一个干净的确定性 oracle，judge 本身就会变成 benchmark 必须一并验证的对象。

# 2024 年 5 月月度报告

> [English](../../monthly/2024-05.md) | **简体中文**

> **覆盖范围：** 2024-05 首次公开的工作

## 本月概览

- 本月共有 **4 项工作**进入知识库：**4 项当月新发布**，**0 项历史补录**，全部归在 [Scientific Agent Benchmarks](../../topics/scientific_agents.md) 之下：[AgentClinic](../../works/agentclinic.md)、[CPsyExam](../../works/cpsyexam.md)、[AnalogCoder](../../works/analogcoder.md)、[RTL-Repo](../../works/rtl-repo.md)。
- 这四项做的其实是同一件事：收窄。每个 benchmark 都盯着一个专业领域下手，临床医学、心理学、模拟硬件、数字硬件，而不是去测通用能力。
- 这一批在「到底放出多少 agency」这件事上分成两拨。AgentClinic 和 AnalogCoder 把模型塞进一个交互或迭代的循环里；CPsyExam 和 RTL-Repo 只给一次回答打分。
- 本月最压得住的发现来自 AgentClinic，而且它横跨了上面那道分界：同样一批医学知识，换成一步步推进的临床工作来评，而不是静态答题，据报准确率会掉到静态问答的十分之一以下。这话本身就是一句警告：别把一个静态的领域知识分数，当成模型真能干这行的证明。
- 真正的分界线不是领域，而是验证有多严。AgentClinic 和 AnalogCoder 把分数落在执行上：一个有 moderator 把关的临床环境，还有能真跑起来的 Python 电路；CPsyExam 和 RTL-Repo 则是拿参考答案来对分。

## 这个月到底变了什么

**领域专精的 agent benchmark 成群到来。** 本月新增的每一项工作，都把评测收窄到单一的专业领域，问的是模型能不能干这个领域的活，而不是它能不能回答通用问题。[AgentClinic](../../works/agentclinic.md) 瞄准临床医学，覆盖九个专科、七种语言；[CPsyExam](../../works/cpsyexam.md) 用中文考试题来测心理学；[AnalogCoder](../../works/analogcoder.md) 瞄准模拟电路设计；[RTL-Repo](../../works/rtl-repo.md) 瞄准用 Verilog 写的、仓库规模的数字硬件。把它们放一块看，价值不在于它们覆盖了同一个领域，它们覆盖的其实是四个；价值在于四个互不相干的团队，在同一个月里都奔着同一个思路去了：通用 benchmark 对一个专业领域内部的表现讲得太少，那就干脆把这个专业本身砌进任务里。

**这一批在「有没有真动用 agency」上分了叉。** 四项里有两项，让「agent」这个标签名副其实。AgentClinic 让一个医生 agent 走一场接一场的问诊：它得问病史、开检查，还得在信息不全的情况下拍板下诊断；AnalogCoder 让一个 LLM agent 走一个靠反馈自我纠错的循环，不停生成、修补 Python 代码，直到电路能正常工作。另外两项虽然挂在同一个 Topic 下，却是一次性打分。CPsyExam 把一个 22,000 题的题库提炼成一套 4,000 题的均衡集合，每题只对一个答案打分，并沿两个维度把「心理学知识的回忆」和「案例分析的应用」拆开；RTL-Repo 每个样本只要一次 Verilog 补全，不过给它的上下文是周围的整个仓库。把一个静态的领域知识分数，当成 agent 层面能力的证据，恰恰是下一段要提醒你别做的那个推断。

**AgentClinic 量出了「把 agency 压成一道题」要付多大代价。** 先看医学模型过去那条评测路子，打的是静态选择题：模型看到一段信息都给全了的病例，然后挑一个答案。这条路子测的是能不能记住那些现成的事实，而不是当事实还得自己一点点问出来时，怎么一步步推出诊断。AgentClinic 换掉的就是这一步。它在医生 agent 周围摆上了病人 agent、测量 agent 和 moderator agent，这是一整个模拟环境，而不是一句 prompt；它报告说，一旦同样这些题变成一场接一场的问诊，诊断准确率会掉到静态问答那个数字的十分之一以下。它还带了一些工具，让「跨病例的学习」变得可测量（一本跨病例、一直留着的笔记本，据报给 Llama-3 带来最高 92% 的相对提升），把 24 种认知偏差和内隐偏差建模成一条鲁棒性维度，背后还有真实的电子病历和一项临床读者研究撑着。结论只走到 card 的来源能撑住的地方为止：这里的数字来自摘要和官方项目材料，基于 Claude 3.5 的 agent 据报在大多数设定里领先，但逐一设定的完整验证还没做完。真正能推广到医学之外的发现，是那个数量级的落差本身：这也正是一个理由，让我们把本月这些静态领域分数当成知识探针，而不是能力度量。

**硬件设计出现了两次，打分方式却是两套。** AnalogCoder 和 RTL-Repo 都在电气和硬件设计上评测模型，而它俩的对比之所以值得看，是因为差别在验证方式上，不在题材上。AnalogCoder 不需要训练：它的 agent 写 Python 来搭模拟电路，靠反馈自我纠错，还把解出来的子电路存进一个可复用的工具库；在一套精选的 24 个任务上，它成功设计出 20 个电路，比标准 GPT-4o 多五个，按执行结果以 Pass@1/Pass@5 打分。RTL-Repo 在严格度上走了相反的方向，换来的是规模和真实感：4,000 多个 Verilog 样本，取自公开的 GitHub 项目，每次补全都拿参考答案来判，靠的是编辑相似度和完全匹配（exact match），而不是仿真，评测覆盖 GPT-4、GPT-3.5、Starcoder2，以及专门做 Verilog 的模型（VeriGen、RTLCoder）。说白了，一个会把产物跑起来、看它到底能不能工作；另一个只看文本对不对得上，而且正如它自己的 card 所指出的，它并不验证功能正确性。在同一个领域里，这个月就已经把「以执行为准」和「以字符串匹配为准」这两种评测之间的落差摆了出来。

## 值得展开的 Topic

### [Scientific Agent Benchmarks](../../topics/scientific_agents.md)

这个 Topic 一口气收进四项领域专精的工作，它们合在一起，正好划出了这个 Topic 必须分清的几条设计路线。AgentClinic 定义了**交互环境**这条线：评测的单位是一个有 moderator 把关的多 agent 场景，分数反映的是一整条轨迹上的行为，它在任务轴上的用法同时横跨 [Scientific Problem Solving & Reasoning](../../activities/scientific_problem_solving_reasoning.md) 和 [Experiment Design & Scientific Discovery](../../activities/experiment_design_discovery.md)。AnalogCoder 落在相邻的**迭代设计**这条线上，一个 [Optimization & Engineering Design](../../activities/optimization_engineering_design.md) 的 agent 反复走生成与修补的循环，直到一个可执行的产物通过为止。CPsyExam 守着**静态领域问答**这条线，是一个只回答一次的 [Scientific Problem Solving & Reasoning](../../activities/scientific_problem_solving_reasoning.md) 探针，这个 Topic 必须把它和那些交互式的区分开。RTL-Repo 把补全这条线延伸到了**仓库规模**，是一个 [Scientific Software & Workflow Engineering](../../activities/scientific_software_workflow_engineering.md) 任务，它的新意在于跨文件的上下文，而不在于一个交互循环。各项工作逐一的说明在上面的*这个月到底变了什么*里；这里要说的是：「Scientific Agent Benchmark」不是一种设计，而是至少三种，而这个月把每一种都填上了内容。其中 AgentClinic 那个从静态到顺序推进的准确率崩塌，正好是一条经验证据，说明交互式的那几条线跟静态那条不是一回事，不能拿来互换。

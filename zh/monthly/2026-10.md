# 2026-10 月度报告

> [English](../../monthly/2026-10.md) | **简体中文**

> **覆盖范围：** 2026-10 加入 main 的 cards

## 本月概览

10 月这批卡凑到一块，犟的是同一个理：一个看着像样的最终答案，不许再替它背后的那摊活儿领功。推导凑出了对的公式，是一回事；写出来的步骤到底撑不撑得起这个公式，另算一笔分。agent 把模拟器的数据拟合上了，是一回事；它有没有找到机理，另算一笔分。报告读着顺，是一回事；它描述的那段代码到底跑没跑起来，还是另算一笔分。那几个看产物的 benchmark 也是这股劲：它们不再去给生成的脚本或报上来的数字打分，而是直接把 agent 产出的文件打开，一个 CAD 模型、一张 Simulink 框图、一个有限元算例，然后把它跑一遍。这股劲还推出了一波 meta-evaluation，这回被测的是评测器自己：agent 能不能把评测器搭出来、能不能把 benchmark 生成出来、能不能复用一个冻住的 verifier，而这几样又信不信得过。

这个月有二十七张卡进了 `main`：十八张是 10 月首次公开的，九张是历史补录，它们公开发布的时间早于本月。物理推导和强场物理凑成了最大的一簇主题，[PHYRD](../../works/phyrd.md)、[PhysClosureBench](../../works/physclosurebench.md) 和 [QFT-Bench](../../works/qft-bench.md) 都落在同几周里。但真正给这个月定调的不是题材，是方法：横跨物理、实验室机器人、可解释性、工程 CAD，这些新 benchmark 都在把一个分数掰成两半，一半量产出、一半量过程，然后专门把两边对不上的地方报出来。

## 这个月到底变了什么

### 答案对，不等于这门科学做完了

本月最大的一簇卡，重做了打分方式，就为了不让一个正确结果把周围所有东西的功都吸走。[PHYRD](../../works/phyrd.md) 把每道理论物理题拆成几个公开的子问题，只有当某一部分的结论、推导步骤和适用条件全对，这部分才给分，所以一个闭式答案哪怕算对了、缺了个条件，这部分照样零分；它的 *Reproduce* 轨道要从给定前提重建一个已发表的结果，*Discover* 轨道则改掉其中一个条件，问哪些结论还站得住。[QFT-Bench](../../works/qft-bench.md) 判一道量子场论题时，先用符号检查定对错，符号查不出结论才叫 LLM judge 上；之后再加第二个 judge，专门问展示出来的推导到底撑不撑得起这个答案，结果真就揪出了一批答案对、但写出来的过程并不能证成它的情况，而且这种忠实度标注跟专家的吻合率只有 73%（Opus-5）和 67%（GPT-5.6）。[PhysClosureBench](../../works/physclosurebench.md) 把这道拆分做进了结构里：一个 20 条标准的 Atomic Score 给局部步骤算分，另立一个 Research Closure 层级（RC0–RC4），问的是一个完整答案不可或缺的那些证据到底齐没齐；1,050 次作答里，229 次拿到至少 8/10 的，其中 83 次仍然够不到 closure。

[EurekaBench](../../works/eurekabench.md) 在模拟器里划的是同一条线：agent 最多跑四小时实验，然后把机理以文字、代码和日志三样交上来，最好的 agent 在预测准确率上离人类参照只差 1.4 分，但在洞见上落后 27.3 分，拟合上数据不等于把它讲明白了。[DISCERN](../../works/discern.md) 把这道拆分铺到一条生命科学工作流上，对数据核查、分析验证、假设提出分开打分，还配了干净的对照，所以 agent 漏掉一个缺陷会丢分，把本来没问题的数据给否了也会丢分；满分率从 Level 1 的 60.8% 一路掉到 Level 3 的 0.6%。[SAEScientist-Bench](../../works/saescientist-bench.md) 把稀疏自编码器的可解释性循环做成一项任务，在读证据这一层上发现了同样的缺口：agent 能设计出合理的对比探针，可自己明明测了数据，到底是哪个字典特征被激活，却常常读错。而 [Into the Unknown](../../works/into-the-unknown.md) 把这个想法推到了头，它拿一个科学家自己定的成功条件来给一份尚未发表的后续研究方向打分，条件拆成诚信、完整性和充分性三块；135 份提交没一份算有效，所以严格指标对每个 agent 都是 0%，只有节点级通过率能把它们区分开。

### 产物要跑一遍才算数，不能光读它的说明

第二簇卡冲的是"说得天花乱坠"和"真能交付"之间那道缝：没跑起来的东西，一律不给分。[EngiWorld](../../works/engiworld.md) 让 agent 通过 GUI 或命令行去操作 26 个专业工程软件，然后把产出的文件打开，一个实体模型、一套网格加载算例、一张电路板布局，去核对几何、物理可行性和设计规则；一趟跑下来哪怕报告写得像模像样、文件却是无效的，照样零分，最好的 agent 也只到 100 分里的 44.3 分，168 次多软件尝试里只有 6 次成功。[CADWorld](../../works/cadworld.md) 把这件事收窄到一个工具上，通过截图和键鼠操作驱动 FreeCAD，然后打开存下的 `.FCStd` 文件去核对实体、约束、装配连接、CAM 去除材料和 FEM 设置，全程不放 LLM judge 进去。[SimuVerity](../../works/simuverity.md) 为 101 个工程系统建可执行的 Simulink 模型，靠原生仿真行为来打分，而且设了一道分层闸，交付、可执行性、一道工程资格检查，先过这道闸，才轮到六个工程维度里的任何一个算分，最好的系统只到 42.86 分，参照模型是 96.01 分。[OSWorld-Science](../../works/osworld-science.md) 把通用的 computer-use 场景挪进了科学家真正在用的软件里，episode 跑完之后只对收集到的应用状态和输出文件打分。

[SCI-AGENT-EXAM](../../works/sci-agent-exam.md) 把同一套规矩带进通用科学任务里，用两条通道打分：确定性检查器拿隐藏输入重跑 agent 的代码，同时一个 LLM judge 拿专家 rubric 给写出来的报告打分，两边一起报，就把那些报告写得挺唬人、底下分析其实没跑对的 agent 给暴露出来了。[ScienceIDE](../../works/scienceide.md) 把公开的科学仓库变成可执行环境，配上私有 verifier，拿数值输出跟科学参照去比，然后又把同一个 verifier 复用起来，拿去筛监督演示、给强化学习供奖励，这里的评测不是收尾的一步，它就是开发循环本身。

### 把标准顶过排行榜

有几张卡干脆不认排行榜是天花板。[Agent4Sci](../../works/agent4sci.md) 每趟都从一个经过验证、能复现的、某科学 ML benchmark 上*已发表*最佳模型起步，去算 agent 在 8 块 H200 上花 12 小时还能再往上加多少相对提升，另有一个评估 agent 在封存的测试集上打分、一个审计 agent 盯着轨迹查有没有钻空子；论文发现，提升大多来自工程，而不是研究上的洞见。[AutoDataBench](../../works/autodatabench-auto-research.md) 把一根杠杆单拎出来：模型、流水线和评测全冻住，只让 agent 动训练数据，然后拿它最好的分布内 checkpoint 去一个隐藏的分布外集上打分。[Astro2Method](../../works/astro2method.md) 问的是模型能不能给一个天文问题挑出更好的机器学习方法，也就是源论文实测更好的那个，结果发现直接提示在难题上接近瞎猜，检索和推理 scaffold 帮忙不稳定，反倒是源论文自己那段打了码的流水线描述帮得最多。[SciΠvot](../../works/scipivot.md) 的素材取自一个节点：课题负责人推翻 agent 计划的那一刻；它拿一次真实修正发生前的冻结项目记录，让模型在 agent 原来的计划和被人工改过的计划之间二选一，诊断的是在有争议的决策上的判断力，而不是去估一个笼统的错误率。

### 评测器自己能不能被搭出来、被自动化、被信任

第四簇卡把镜头转向了评测这套机器。[EvalResearchBench](../../works/evalresearchbench.md) 给 agent 发一份预算，三小时、100 美元供它自己推理、100 美元供试跑，让它冻结出一个可执行的评测器，再去量这个评测器的分数和排名跟 14 个目标 benchmark 贴得有多近，其中还包括 agent 从没见过的封存目标。[AutoSciBench](../../works/autoscibench.md) 让 agent *生成* benchmark：一个生成器从一个概念加一份配方搭出任务，盲解一遍，一个 judge 给可验证性和难度打分、把能抄近道的标出来，生成器反复修改，直到两条标准都满足。[AgentProofBench](../../works/agentproofbench.md) 为 web agent 冻结一个可复用的验收程序，测当初始状态改变了同一条指令的要求时，它还对不对，以及拿它的裁决去给 agent 把关，能不能让交付变好。[Predictive Credit](../../works/predictive-credit.md) 把"judge 读一段解释"换成了一道预测检验，一段解释只有当它相对于一段朴素描述、一段捐赠解释，能把一个固定预测器的损失压下去，才给它记功；它报告说，在所测的分辨率下，自然语言解释的预测性记功没能得到确认，而研究者手写的机理说明确实把误差降了下来。[AlphaIdeaBench](../../works/alphaideabench.md) 拿一个明确的资源预算去给研究提案打分，并让八个 harness 共用一个骨干、八个骨干共用一个 harness，好把 harness 的影响和骨干模型的影响分开。

### 实验很贵的时候，怎么学、怎么自我改进

本月这几张具身和技能学习的卡，有一条文本 benchmark 没有的约束：动一下手是要付出物理代价的。[PhysRSI-eval](../../works/physrsi-eval.md) 量的是物理递归自我改进，也就是一个控制着仿真双臂机器人的 agent，能不能在最多 17 轮打磨里，靠修改自己的代码、工具、技能和笔记一轮比一轮强；它把五条改进轴跟公开 benchmark 分数关联起来，同时做消融，看持久工作区里到底哪几部分带来了增益。[RobotAgentBench](../../works/robotagentbench.md) 把一个真实家庭在 Isaac Sim 里重建成 50 种布局，拿独立策略去对比那些会规划、执行、验证的编码 agent，其中包括一个递归自我改进配置；最好的配置在任务层面平均 48.5 分，但在开放式场景上只有 15.4 分，而最好的独立策略是 18.0 分。[EmbodiedCLBench](../../works/embodiedclbench.md) 测的是 agent 能不能把在基础家务上学到的技能重新组合起来，发现无论是留着轨迹还是蒸馏出一份技能摘要，都能把高级任务的成功率从 3–12% 抬到 16–52%，但学习样本加到一个以上，就再没有稳定的额外增益了。[SlowLab](../../works/slowlab.md) 把这份代价摆到明面上、还不可逆：一场为期一年的温室战役，每茬作物要在一个隔间里待满 180 天，中途只能接着养或者毁掉，而 agent 在 94–100% 的回合里都要等第一茬收完才种第二茬，所以生长季里读到的数据从来改变不了它种什么。[Labference](../../works/labference.md) 把一个实验室机器人的操作*选择*跟它的物理*执行*和任务完成分了开，这样一来，选对了却因为掉了东西而没完成，和干净利落地把错东西搬到位，这俩就能分得清了。

## 值得展开的 Topic

这个月活跃的几个 topic，其实是同一个论点从不同侧面看过去，所以它们才凑到一起。[Scientific Agent Benchmarks](../../topics/scientific_agents.md) 是最忙的一条轴，物理推导那几张卡（[PHYRD](../../works/phyrd.md)、[QFT-Bench](../../works/qft-bench.md)、[PhysClosureBench](../../works/physclosurebench.md)）、模拟器和工作流那几张（[EurekaBench](../../works/eurekabench.md)、[DISCERN](../../works/discern.md)、[Into the Unknown](../../works/into-the-unknown.md)、[SAEScientist-Bench](../../works/saescientist-bench.md)）、以及扎在产物上的那几张（[EngiWorld](../../works/engiworld.md)、[CADWorld](../../works/cadworld.md)、[OSWorld-Science](../../works/osworld-science.md)、[SimuVerity](../../works/simuverity.md)、[SciΠvot](../../works/scipivot.md)、[Labference](../../works/labference.md)）都归在它底下，但把它们拧到一起的不是题材，而是每一张都把一个铁板一块的成功分数换成了一种能在可诊断的地方出错的拆解。

[Evaluator Reliability & Validation](../../topics/evaluator_reliability_validation.md) 这边，是那道拆解反过来落到评测器自己头上的地方。[QFT-Bench](../../works/qft-bench.md) 的忠实度 judge 和 [SimuVerity](../../works/simuverity.md) 经专家验证的那道闸，量的是一个自动打分器能被信到什么份上；[AutoSciBench](../../works/autoscibench.md) 和 [EvalResearchBench](../../works/evalresearchbench.md) 问的是 agent 到底能不能造出一个有效的评测器；[AgentProofBench](../../works/agentproofbench.md) 测一个冻住的 verifier 在状态一换之后还撑不撑得住；而 [Predictive Credit](../../works/predictive-credit.md) 干脆放弃了读 judge，改用一个预测信号。连起来看，这些卡反复在报同一件事：评测器才是那根最弱的链条，LLM 打分器跟专家的吻合远没到板上钉钉，而一个在某个状态上没问题的 verifier，换个状态就可能把错的结果给放进来。

[Benchmark Design, Validity & Contamination](../../topics/benchmark_design_validity_contamination.md) 收的是那些最把"我这套分数证明不了什么"说在明面上的卡，[AutoSciBench](../../works/autoscibench.md)、[EvalResearchBench](../../works/evalresearchbench.md)、[PHYRD](../../works/phyrd.md)、[Predictive Credit](../../works/predictive-credit.md)，还有 [SlowLab](../../works/slowlab.md)，它的模拟器就大大方方承认自己在空气温度和湿度上没通过外部核对。[Resource-aware Evaluation](../../topics/resource_aware_evaluation.md) 串的是另一条线：[AlphaIdeaBench](../../works/alphaideabench.md) 给预算可行性打分，[SlowLab](../../works/slowlab.md) 给一场稀缺又不可逆的实验战役计量，[DISCERN](../../works/discern.md) 和 [SCI-AGENT-EXAM](../../works/sci-agent-exam.md) 把成本和阶段当头等公民看，大家共同的动作是：进分数的不再只有对错，花销也进来了。[Skill Learning & Evolution](../../topics/skill_learning_evolution.md) 扛着那几张具身自我改进的卡（[PhysRSI-eval](../../works/physrsi-eval.md)、[EmbodiedCLBench](../../works/embodiedclbench.md)、[RobotAgentBench](../../works/robotagentbench.md)），它们问的都是 agent 能不能在反复的物理尝试里，靠改自己的代码、技能或留存的经验一轮比一轮强；其中 [EmbodiedCLBench](../../works/embodiedclbench.md) 还补了一句让人泄气的话：经验过了一个样本之后，再多就没有稳定的额外增益了。最后，[Planning & Decision-Making Evaluation](../../topics/planning_decision_evaluation.md)（[SciΠvot](../../works/scipivot.md)、[Labference](../../works/labference.md)）、[Trajectory Evaluation](../../topics/trajectory_evaluation.md)（[SCI-AGENT-EXAM](../../works/sci-agent-exam.md)）、[Agent Harnesses & Scaffolding](../../topics/agent_harnesses_scaffolding.md)（[Agent4Sci](../../works/agent4sci.md)、[Astro2Method](../../works/astro2method.md)、[RobotAgentBench](../../works/robotagentbench.md)），加上两个评测驱动开发的 topic，[Data Curation](../../topics/evaluation_driven_data_curation.md)（[AutoDataBench](../../works/autodatabench-auto-research.md)）和 [Post-Training](../../topics/evaluation_driven_post_training.md)（[ScienceIDE](../../works/scienceide.md)），各自又给同一个转向添了一个看点：从给结果打分，转到给产出结果的那个过程打分。

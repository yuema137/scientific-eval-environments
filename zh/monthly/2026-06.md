## 这个月到底变了什么

### [Scientific Agent Benchmarks](../../topics/scientific_agents.md)

把这组工作放一块看，变化不只是多了几个分数，而是 evaluator 能看见、能诊断的东西变多了：

- [A Case Study of Evaluating AI Agents on a Neuroscience Data-to-Discovery Pipeline](../../works/a-case-study-of-evaluating-ai-agents-on-a-neurosci.md)：一项实证案例研究，在一条真实的果蝇光遗传学「数据到发现」流程上评估通用编码 agent，考察它们能否自动化科学家平日手工搭建的软件工程环节，评估标准以领域专家的做法为依据。
- [Autonomous Action Execution (AAE) Framework](../../works/aae-framework.md)：AAE 框架是一套四层多 agent 架构，用于把 LLM 推理安全地引入工业过程控制：LLM 只出现在仅做观察的 Monitor 层，模型提出的每一个动作都要交由确定性校验器审查，而校验器沿装置的 P&ID 拓扑做图遍历。评估由三部分构成：分级基线阶梯、针对人工构造提案的错误注入研究，以及横跨五个流程装置场景的重复运行稳健性研究。
- [Agentic Large Language Models for Automated Structural Analysis of 3D Frame Systems](../../works/agentic-large-language-models-for-automated-struct.md)：一个含十个不规则三维建筑框架体系的 benchmark：agent 须依据自然语言描述产出可执行的 SAP2000 脚本，只有当每一项受监测的结构响应都落在人工搭建的 ground-truth SAP2000 模型 1% 以内，才算通过。
- [AISE-Bench](../../works/aise-bench.md)：AISE-Bench 是面向学术知识图谱上学术信息检索的全流程标注 benchmark：1,133 组问答对，随附查询分类法、完整的 API 执行轨迹、经校验的参数，以及带参考链接、可溯源的答案，过程与结果一并计分。
- [ALeRCE Text-to-SQL](../../works/alerce-text-to-sql.md)：一套面向 ALeRCE 天文警报 broker 数据库的自然语言转 SQL 系统，随文发布了一个含 110 组自然语言/SQL 对的评测集：问题由天文学家提出，目标查询由专家撰写：并在其上以完全匹配的执行式指标比较了十三个 LLM。

说白了，这批工作共同往前推了一步：不能只看最后成没成，还得把行为、证据或改进环节摊开，才能知道下一步该改哪儿。

### [Skill Hierarchy](../../topics/skill_hierarchy.md)

把这组工作放一块看，变化不只是多了几个分数，而是 evaluator 能看见、能诊断的东西变多了：

- [A Framework for Evaluating Agentic Skills at Scale](../../works/a-framework-for-evaluating-agentic-skills-at-scale.md)：一套评估方法学，让 skill 作者把自己的 skill 变成带评分量规的真实可执行任务，并在大规模上应用于约 500 个真实 agent skill、1,000 个生成任务和 19 种 agent–模型配置。
- [Agent Skill Evaluation and Evolution: Frameworks and Benchmarks](../../works/agent-skill-evaluation-survey.md)：这篇综述关注 skill 建成之后如何评估、如何演化：把相关文献归入四种 skill 演化范式与六类以 skill 为中心的 benchmark，并指出 benchmark 覆盖上的结构性空缺。
- [ATOM-Bench](../../works/atom-bench.md)：ATOM-Bench 是一个真实机器人 benchmark，把**原子**操作技能与由它们搭起来的**组合**任务分开，于是组合任务上的失败可以归因：要么是底层原子技能不过关，要么是组合复用本身真的失效了。
- [PDAgent-Bench](../../works/pdagent-bench.md)：PDAgent-Bench 是一个 benchmark，用于在整个 VLSI 物理设计流程上评估基于 LLM/VLM 的 agent，它把任务级评估（概念题与工具中心题）与在真实电子设计自动化（EDA）环境中的工作流级闭环执行结合起来。
- [RigorBench](../../works/rigorbench.md)：RigorBench 给自主 AI 编码 agent 打分，评的不只是结果对不对，而是**工程过程纪律**：解是怎么得到的。它把过程纪律拆成七根分别计分的支柱，从完整的执行 trajectory 上算出各支柱得分，再聚合为综合的 RigorScore。

说白了，这批工作共同往前推了一步：不能只看最后成没成，还得把行为、证据或改进环节摊开，才能知道下一步该改哪儿。

- [Autonomous Action Execution (AAE) Framework](../../works/aae-framework.md)：AAE 框架是一套四层多 agent 架构，用于把 LLM 推理安全地引入工业过程控制：LLM 只出现在仅做观察的 Monitor 层，模型提出的每一个动作都要交由确定性校验器审查，而校验器沿装置的 P&ID 拓扑做图遍历。评估由三部分构成：分级基线阶梯、针对人工构造提案的错误注入研究，以及横跨五个流程装置场景的重复运行稳健性研究。
- [AISE-Bench](../../works/aise-bench.md)：AISE-Bench 是面向学术知识图谱上学术信息检索的全流程标注 benchmark：1,133 组问答对，随附查询分类法、完整的 API 执行轨迹、经校验的参数，以及带参考链接、可溯源的答案，过程与结果一并计分。

- [Skill Coverage](../../works/skill-coverage.md)：Skill Coverage 是面向可复用 agent skill 的、基于轨迹的测试充分性指标：它把 skill 的自然语言指令编译成半结构化的行为约束，再逐条核对：agent 轨迹有没有覆盖到该约束，覆盖时观察到的行为又是通过还是失败。
- [SkillJuror](../../works/skilljuror.md)：SkillJuror 是一套评估框架，把*一个 agent skill 如何组织*与*它说了什么*分离开来：在任务知识保持不变的前提下，比较 Progressive Disclosure 布局（一个精简的根文件，按需指向各项支撑资源）与归一化的扁平基线。

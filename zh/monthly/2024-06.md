# 2024 年 6 月月度报告

> [English](../../monthly/2024-06.md) | **简体中文**

> **覆盖范围：** 2024-06 首次公开的工作

## 本月概览

- 本月共有 **6 项工作**进入知识库：**6 项当月新发布**，**0 项历史补录**，全部是 2024 年 6 月首次公开的工作。
- 其中五项是有明确领域背景的 LLM 与 agent benchmark，都归在 [Scientific Agent Benchmarks](../../topics/scientific_agents.md) 下：硬件设计方向的 [AssertionBench](../../works/assertionbench.md) 和 [VHDL-Eval](../../works/vhdl-eval.md)，材料方向的 [MatText](../../works/mattext.md)，还有生命科学方向的 [GenoTEX](../../works/genotex.md) 和 [BioKGBench](../../works/biokgbench.md)。第六项 [NATURAL PLAN](../../works/natural-plan.md) 落在 [Planning & Decision-Making Evaluation](../../topics/planning_decision_evaluation.md) 下。
- 这个月反复出现的一个设计选择，是让 ground truth 有验证做后盾：判定对不对，靠的不是表面读着像不像、也不是对上某一个标准答案字符串，而是拿一个外部的、客观的东西去核对，比如经过形式化验证的 assertion、能自我验证的 testbench、专家整理的参考流程、几何模型的回归基线，或者是被审计的那张知识图谱本身。
- 反复出现的一个结果，是一种有边界的负面结论。每个 benchmark 报的都是当前模型在哪儿还差着、差在哪一步，而不是宣布又多了一项新能力。

## 这个月到底变了什么

**给 ground truth 加上验证后盾，是这批工作共同的那步棋。** 先看生成类任务过去是怎么评的：拿模型的输出去对一个参考答案，或者让人（或模型）判一判读着像不像。这么做便宜，但它会放过那些说得顺、其实是错的输出，也可能把本来对的另一种写法给判错。六项里有五项，把这一步换成了一个长在模型输出之外的检查。[AssertionBench](../../works/assertionbench.md) 拿形式化工具（GoldMine 和 HARM）已经验证过的一组 assertion 当标尺，去给模型生成的 assertion 打分。[VHDL-Eval](../../works/vhdl-eval.md) 把每一份生成的设计，都塞进一个能自我验证的 testbench 里跑一遍。[GenoTEX](../../works/genotex.md) 把 agent 跑完的整条分析流程，拿去跟生物信息学家整理的参考代码和结果做比对。[MatText](../../works/mattext.md) 在同一批晶体上，拿几何图神经网络的基线去量它性质预测的误差。[BioKGBench](../../works/biokgbench.md) 干脆把检查对准知识图谱本身：所谓做对了，就是真找出图谱里确实存在的一处事实错误。这么做的好处是，一个及格分很难靠糊弄拿到；代价是，每个检查能覆盖多广，说白了就被它背后那个 oracle 框死了，100 个设计、202 道题、一组固定的数据库，分数能铺多宽，全看它身后那份整理好的参考资料有多宽。

**LLM 硬件评测，往 Verilog 代码生成之外又走了一步。** 这两项工作，把硬件描述语言（HDL）的评测朝两个不同方向撑开了。VHDL-Eval 补的是语言这一块的缺口：现有的 LLM 硬件 benchmark 基本被 Verilog 占着，于是它凑齐了 202 道题（一部分是把 Verilog 的题翻成 VHDL，一部分是把公开的 VHDL 挑战题汇到一起），每道题都配一个能自我验证的 testbench，结论是通用模型迁移得不好，非得做针对 VHDL 的监督微调（SFT）不可。AssertionBench 补的是任务这一块的缺口：模型要生成的不是一份设计，而是那些 assertion，也就是把「一份设计绝对不能违反什么」讲清楚，再拿 100 个 OpenCores 设计上经过形式化验证的参考去打分。这两项摆一块看，正好是同一场扩张的两条边：一条是从「把硬件写出来」走到「把它规约清楚、再验证它」，另一条是从一种 HDL 走到另一种；而两项的结论都一样，现成的模型还不够用。

**这个月的 benchmark，落点都在具体哪儿掉链子，而不是又刷出什么亮眼战绩。** 只要报了分，读着都像个天花板，真正的贡献是把毛病诊断出来。MatText 把九种文本表示、最大到 70B 参数的模型、最大到 200 万个结构的数据集都扫了一遍，结果照样撞上「几何盲区」：基于文本的 LLM 能抓住类别层面的规律，却抓不到坐标信息，几何架构把它们甩开一大截。NATURAL PLAN 报的是，在十座城市的行程题上，所有被评的模型 exact match 都掉到 5% 以下。BioKGBench 报的是，无论通用的还是生物医学专用的顶尖 agent，要么失败、要么表现不佳。GenoTEX 的错误分析，把还没解决的那些难点摆到了台面上。没有一项在宣称问题已经解决，每一项都在指出到底是哪一步断了。

**NATURAL PLAN 把「规划」从「操作工具」里单拎了出来。** agent 规划类 benchmark 一直有个麻烦：一次失败，你说不清是工具选错了、工具没跑对、还是检索出了问题，未必真是规划本身的毛病。NATURAL PLAN 把这个含糊之处直接去掉了，它把 Google Flights、Google Maps、Google Calendar 的输出直接摆进 prompt 里，这样它那 3,600 道行程、会面和日程题，测的就是在信息固定的前提下，模型怎么把一个计划搭出来。这个取舍说得很明白：检索和随环境调整都被拿掉了，量的又只是一次性给出的计划，所以这个 benchmark 能把规划这件事读得很干净，但它说不了在反馈下重新规划、也说不了实时用工具的事。

## 值得展开的 Topic

### [Scientific Agent Benchmarks](../../topics/scientific_agents.md)

本月六项里有五项落在这儿，它们有个共同的立场：挑一件领域专家平时靠手工去做的活儿，想办法让它能对着一个客观参照去量。它们的区别，在于那件专家活儿到底是什么。

其中两项是硬件工作，上面讲 HDL 扩张时已经放一块说过了，[AssertionBench](../../works/assertionbench.md) 做的是有形式化背书的 assertion 生成，[VHDL-Eval](../../works/vhdl-eval.md) 做的是配自我验证 testbench 的 VHDL 代码生成，两项的结论都是通用模型还没过线。

[MatText](../../works/mattext.md) 把「一块晶体到底该怎么编码成文本」这件事，做成了一个受控变量：九种表示、最大到 70B 参数、最大到 200 万个结构的规模，全都拿几何 GNN 的基线来评。它的发现是结构性的，不是往前挪一小格：一堵「GNN-LM 墙」，文本编码抓不到那些几何感知模型能用上的坐标信息，所以它既是个 benchmark，也同样是一份带分析、带立场的结果。

[GenoTEX](../../works/genotex.md) 和 [BioKGBench](../../works/biokgbench.md) 把目标挪到了生命科学，也挪到了整条工作流上。GenoTEX 给 agent 的一整条基因表达分析流程打分，从选数据集、预处理到统计，都拿生物信息学家整理的参考代码和结果去对（按官方仓库的说法，是 911 个数据集上的 1,384 道题），所以打分是一步一步地打，而不是只看最后那个答案。BioKGBench 把「读懂文献」拆成两个原子任务（科学主张核验、知识图谱问答），再把它们组装成 agent 式的 KGCheck 审计，评测的对象就是那张知识图谱本身；论文里那个基线 agent，在现有的生物医学数据库里翻出了 90 多处真实的事实错误，这对一个 benchmark 的真实性来说，是一次难得的外部检验。

### [Planning & Decision-Making Evaluation](../../topics/planning_decision_evaluation.md)

[NATURAL PLAN](../../works/natural-plan.md) 是这个 Topic 本月唯一的一项，它的贡献是一个划边界的选择：把信息获取这一环固定住，好让规划能力能被单独读出来，不被工具选择或执行这些事搅进来。Google Flights、Maps、Calendar 的输出都直接给在上下文里，三类任务则通过城市数、参会人、日程和天数来调整约束的复杂度。它报出来的那几个数，GPT-4 在 Trip Planning 上 exact match 31.1%、Gemini 1.5 Pro 34.8%，而所有模型在十座城市的行程上都掉到 5% 以下，量的就是约束一涨、现在的规划器多快就跟不上了。这个设计的代价，跟好处正好是一体两面：exact match 可能把本来也对的另一种计划给判错，而只量一次性产出的计划，也就说不了在反馈下重新规划的事。

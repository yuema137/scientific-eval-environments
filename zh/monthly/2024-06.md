# 2024-06 月度报告

> [English](../../monthly/2024-06.md) | **简体中文**

> **覆盖范围：** 2024-06 首次公开的工作

## 本月概览

2024 年 6 月最明显的推进，是把 evaluation 往外部验证上推，而不是停在“答案听起来像对”。AssertionBench、GenoTEX、MatText、BioKGBench 和 NATURAL PLAN 都给系统加上了 oracle、simulator 或约束结构，于是模型想靠说得顺就拿高分，这条路越来越走不通。

## 这个月到底变了什么

### [Scientific Agent Benchmarks](../../topics/scientific_agents.md)

这组工作主要在回答一个更硬的问题：进到真实 scientific workflow 以后，benchmark 到底该怎么做，才不至于只是在测一层表面问答。

- [AssertionBench](../../works/assertionbench.md)：AssertionBench 评测大语言模型的硬件断言生成：100 个从 OpenCores 精选的 Verilog 设计，配以经形式验证的断言（来自 GoldMine 与 HARM 工具），考察 LLM 能否为数字硬件推断出功能正确的断言。
- [BioKGBench](../../works/biokgbench.md)：BioKGBench 是面向生物医学 AI agent 的知识图谱核查 benchmark：两项原子任务：科学主张验证（SCV）与知识图谱问答（KGQA）：组合成 agentic 的 KGCheck 任务，agent 借助 KGQA 与领域 RAG 找出大规模生物医学知识图谱中的事实错误。
- [GenoTEX](../../works/genotex.md)：GenoTEX 是自动化基因表达数据分析的 LLM agent benchmark：agent 按照计算基因组学的标准流程完成基因-性状关联问题的数据集选择、预处理与统计分析，评估对照生物信息学家的专家整理标注进行。
- [MatText](../../works/mattext.md)：MatText 是用大语言模型从晶体文本表示预测材料性质的 benchmark 框架：横跨九种表示、参数规模至 70B、数据规模至 200 万结构，记录了一种持续的「几何盲区」：LLM 能抓住类别模式却漏掉坐标信息，而专门的几何架构以显著优势胜过它们。
- [VHDL-Eval](../../works/vhdl-eval.md)：VHDL-Eval 是评测 LLM 生成 VHDL 代码的框架：202 个问题，由 Verilog 评测问题翻译为 VHDL 并汇总公开 VHDL 问题而成，在零样本、上下文学习与参数高效微调三种设定下评估。

### [Planning & Decision-Making Evaluation](../../topics/planning_decision_evaluation.md)

这组工作往执行前面再退一步，看的是 agent 当时选的下一步到底对不对。

- [NATURAL PLAN](../../works/natural-plan.md)：NATURAL PLAN 是一套包含 3,600 个实例的自然语言规划 benchmark，覆盖旅行安排、会面规划与日程协调；评估时，模型所需的工具信息会全部随 prompt 提供。

## 值得展开的 Topic

[Scientific Agent Benchmarks](../../topics/scientific_agents.md)、[Planning & Decision-Making Evaluation](../../topics/planning_decision_evaluation.md) 还是这个月最该连起来看的几页，但重点不在于把名字列出来。这些活跃 Topic 更适合当成一个月度故事一起看，而不是分散摆在几层架子上，因为这个月最有代表性的工作本来就在不断跨它们的边界。

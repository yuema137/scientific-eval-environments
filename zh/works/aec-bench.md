# AEC-Bench (2026)

> [English](../../works/aec-bench.md) | **简体中文**

## Overview

AEC-Bench 是一个建立在真实施工文档集之上的多模态 agent benchmark：九个任务族、三个作用范围层级共 196 个任务实例，由 agent 在沙箱化的 Docker 环境中经 Harbor 测评框架执行，再由各任务专属的自动验证器对结构化的发现结果判分。

## Summary

这个 benchmark 瞄准的是建设项目上真正吞掉工程师时间的文档工作：看大样详图、在整套图纸中追索索引与交叉引用、把技术规格书与图纸对照核查、审查报审资料。agent 在带 Bash 与命令行 PDF 工具的沙箱环境中作业，必须自己在文档空间里找路，而不是被喂进已抽取好的内容；结论以结构化的 JSONL 发现结果提交，由自动验证器对照 ground truth 判分。任务按所需上下文的多寡分组——一张图纸、一整套图纸、或整个项目——从而把上下文组装的失败与推理的失败分开。作者还在固定模型后端的前提下对工具层作了消融，以分离出文档解析本身的贡献。

## Tasks

九个任务族、三个作用范围层级共 196 个任务实例。图内（单页）推理（43 个实例）：详图技术审查（14），回答关于某个大样的局部技术问题；详图标题准确性（15），核查详图标题与所画内容是否相符；注释索引准确性（14），核查索引文字是否正确描述了它所指的构件。图集内（单套图纸的跨图推理）（89 个实例）：交叉引用解析（51），找出无法指向有效目标的引用；交叉引用追溯（24），找全引用了某个详图的所有源位置；图纸目录一致性（14），把目录条目与图签栏对照。项目内（跨文档推理）（64 个实例）：图纸检索（12），为一个查询定位到正确的文件、图纸与详图；规格书—图纸一致性（16），找出技术规格书与图纸之间的冲突；报审资料审查（36），评估报审资料是否符合技术规格书与图纸。文档是取自公共部门项目、可公开获取的 PDF 施工文档集，涵盖建筑、结构、市政、暖通、电气与给排水各专业。

## Domains

土木与结构工程：受评对象是真实的施工文档集——图纸、图纸目录、技术规格书与报审资料——而需要判断力的那几个任务族（详图技术审查、规格书—图纸一致性、报审资料审查）要求对照项目技术规格书给出符合性结论，这属于施工工程的审查工作。文档集横跨多个专业（建筑、结构、市政、机电），但受评的任务是工程文档核查而非建筑设计，因此未指派第二个领域。

## Evaluation

- agent 经 Harbor 测评框架在沙箱化的 Docker 容器中运行，每个任务配一份资产清单指明要取哪些文档，结果写入一个标准化的 JSONL 输出文件。
- 各任务专属的自动验证器把这些发现结果与已知 ground truth 对照判分：完整且正确的给满分，部分正确的给部分分，错误或缺乏依据的给零分。全程不用 LLM judge。
- **报告。** 在基础 harness 与叠加了 Nomic 文档解析工具的 harness 两种条件下评测了 GPT-5.4、GPT-5.2、Opus 4.6 与 Sonnet 4.6。结构化解析令依赖检索的任务提升约 20–32%，但对依赖视觉定位的任务略有拖累。图纸检索最高达到 100.0 reward（GPT-5.4 配 Nomic 工具），而报审资料审查最高只有 23.1，是最难的一族。作者的结论是，通用编码 agent 只能部分迁移到施工文档工作上，在空间定位与需要判断力的审查上都吃力；在报审资料审查这一族上，「正确的输出不仅取决于能否检索到证据，还取决于能否运用与专业审查标准相一致的领域判断和优先级排序」。

## Main Contribution

一个建立在真实项目文档上、以可执行方式验证的 AEC 文档工作 agent benchmark。它用一套作用范围层级把单图、跨图与跨项目推理区分开，并通过工具消融揭示 harness 的哪些能力会撬动哪些任务族。

## Key Design Ideas

- 三个作用范围层级（图内、图集内、项目内）把上下文组装变成一条显式、可测的轴线，而不是暗藏的混杂因素。
- 结构化的 JSONL 发现结果使自动验证与分级部分给分成为可能，避开了自由文本判分。
- agent 拿到的是带命令行 PDF 工具的终端沙箱，而非预先解析好的输入，文档导航因此本身就是受评任务的一部分。
- 固定模型、只变工具层（基础 harness 对比加装解析工具），从而把文档解析的贡献与模型能力分离开。

## Strengths

- 用的是取自公共部门项目、公开可得的多专业真实施工文档集，而非合成图纸。
- 验证器是确定性的，且支持部分给分，不依赖 LLM-as-a-judge。
- 数据集、agent 工具与测评 harness 均以 Apache-2.0 发布。

## Limitations

- 196 个实例的规模偏小，且各任务族之间数量悬殊（交叉引用解析有 51 个实例，图纸检索只有 12 个）。
- Repository note: 有几个任务族——交叉引用解析与追溯、图纸目录一致性、图纸检索——衡量的是文档一致性与检索，而非工程判断；真正涉及实质性工程结论的是详图技术审查、规格书—图纸一致性与报审资料审查这三族。
- Repository note: 论文未记录运行时长、token 或步数，因此无法据此比较不同 harness 配置的成本。
- Repository note: 名称与 AECBench（Liang 等，*Advanced Engineering Informatics* 2026）撞车，两者并无关联。

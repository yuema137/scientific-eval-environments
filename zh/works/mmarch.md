# MMArch (2026)

> [English](../../works/mmarch.md) | **简体中文**

## Overview

MMArch 是一个含 1,212 道题的多模态 benchmark，题目取自建筑与土木工程同行评议论文中的插图。它考察的是：模型能否把散落在一幅技术插图各处的视觉证据收拢起来，认出起支配作用的工程原理，再据以推出结论。

## Summary

MMArch 针对的是图注生成与图表问答类 benchmark 暴露不出来的一种失败模式：答案要求把一张工程图内部若干处分散的证据合起来，再结合领域知识作推理，而不是从图上读一个数。题目由一条刻意解耦的管线生成——planner 先把一个简短的参考答案定死，writer 才去写自由形式的问题，因此问题无法从事先写好的回答里反推出来。候选题目随后依次经过自动筛查、盲态对抗审查、双路答案核验，以及需要全体一致同意的专家评审。论文共评测 18 个开放权重与闭源多模态模型，最好的一个也只达到人类专家准确率的约一半。

## Tasks

1,212 道简答题，覆盖建筑与土木工程的十个子领域：结构工程、抗震工程、建筑物理、建筑检测、遗产保护、空间分析、建筑围护结构工程、城市规划、BIM 与数字建造，以及计算性设计。图源取自约 10,000 篇同行评议论文，出处为 SCI 收录期刊与 arXiv。参考答案是不超过十个 token 的短片段；问题为自由形式，不套模板。构建流程依次是：解耦的 planner–writer 管线（planner 先把答案冻结）；自动筛查，剔除仅凭正文、仅凭图注就能答出以及过于容易的题目（每题试八次）；由三个 agent 执行的盲态对抗审查，分别核查证据是否可见、支配性原理是否必需、有无捷径可走；双路答案交叉核对；最后由三位执业建筑师与工程师评审，三人一致同意才保留该题。`TODO(reference)` — 各子领域的题量只以图的形式呈现，正文没有列表。

## Domains

该 benchmark 横跨建筑学与**土木与结构工程**。土木/结构的归属是直接的：十个列名子领域中，结构工程、抗震工程、建筑检测、BIM 与数字建造占了四个，题目要求把工程原理用到结构与建筑系统的证据上。其余子领域（遗产保护、空间分析、城市规划、计算性设计、建筑物理、建筑围护结构工程）属于建筑学或建筑科学范畴，在本仓库中没有单独的规范领域；未指派其他科学或工程共同领域。

## Evaluation

评分指标是准确率（%），以冻结下来的简短参考答案为准，并对单位、同义表述、数值容差与可接受答案集合做归一化处理。所有模型均在 temperature 0 下解码，最大输出长度 2,048 token。人类专家小组给出上限参照。论文还给出一份错误分析，把失败归入五类——感知、原理、组合、证据定位与一致性——并通过消融实验说明链式思维与视觉提示带来的增益既小又不稳定。

## Typical Duration

单轮多模态问答；唯一明示的预算是每题最多输出 2,048 个 token。不涉及轨迹长度或墙钟时间预算。

## Main Contribution

作者把 MMArch 定位为第一个把多模态推理锚定在建筑与土木工程证据上的 benchmark：模型要做的是把分散的视觉证据与领域原理组合起来，而不是从图纸上识别或抽取信息。论文同时记录了与人类专家之间的巨大差距（最好的闭源模型约 52%，专家小组 94.57%）。

## Key Design Ideas

- 先定答案、后出题：planner 先冻结一个 ≤10 token 的答案，writer 再写问题；两者解耦，减少凭空捏造的问答对。
- 多级过滤，专门用来剔除仅凭正文、仅凭图注或走捷径就能答出的题目。
- 由三个独立 agent 执行的盲态对抗审查，分别核查证据可见性、原理必要性与捷径是否存在。
- 三位执业建筑师与工程师一致同意，作为最后一道关卡。
- 答案短而受限，配以单位／同义／容差归一化，因此评分全自动，不需要 LLM judge。
- 失败分类（感知、原理、组合、证据定位、一致性）与准确率一并报告。

## Strengths

- 题目取自真实的同行评议工程插图，而不是合成图或教科书示意图。
- 筛查管线直击多模态 benchmark 的通病——不看图也能答的题。
- 一致同意的专家验证加上 94.57% 的人类准确率基线，说明题目是可解的，差距出在模型身上。
- 评分是确定性的简答匹配，结果可复现。

## Limitations

- 属于静态简答问答：没有工具调用、没有仿真器、没有设计或验证交付物，因此测不到工程执行能力。
- 十个子领域把结构与土木工程同建筑学、城市规划、遗产保护混在一起；正文没有列出土木/结构在 1,212 道题中所占的份额。
- 十个 token 的参考答案限定了可问问题的复杂度，也把多步设计类输出排除在外。
- Repository note: 图源取自被主流数据库良好收录的期刊与平台上的论文，存在训练数据污染的风险，而论文的筛查环节并未直接检验这一点。
- Repository note: 所报告的分数绑定于 2026 年的模型阵容，会比题目集更快过时。

# ERI Benchmark (2026)

> [English](../../works/eri-benchmark.md) | **简体中文**

## Overview

Engineering Reasoning and Instruction（ERI）benchmark 是一套由分类体系驱动的指令数据集，含 57,750 条指令–回答记录，按九个工程领域（55 个子领域，化学工程在列）、七种任务意图与三个难度层级的受控笛卡尔积构建，随附校验脚本与一套用于给 LLM 和 agent 打分的评估框架。

## Summary

ERI 的设计立论是：通用 benchmark 诊断不了工程能力，因为混在一起的题目会掩盖失败究竟集中在哪里。于是覆盖度被处理成领域、任务意图与难度层级的受控组合：每个（领域，子领域，意图，难度）单元都分到固定条数的样本，任何一类高产的题型都无法主导总分。记录在这套分类体系下合成生成，再经 schema 校验、去重与抽样人工核验，最后由自动检查与基于评分细则的判分共同评分。作者跑了一项覆盖七个模型的基线研究，并配上一套校验协议，用以给「参考答案本身由 LLM 生成」所固有的幻觉风险划定上界。

## Tasks

57,750 条指令–回答记录，横跨九个工程领域、55 个子领域：土木、机械、电气、化学、环境、材料、航空航天、工业工程与消防工程。每个领域与七种意图类型交叉——定义（DEF）、解释（EXP）、计算（CALC）、比较（CMP）、设计/综合（DES）、故障排查（TRB）、规范/标准（CODE）——再与三个难度层级（本科、研究生、专业）交叉，得到 1,155 个唯一单元，每个单元生成 50 组指令–回答对。构建过程是合成的：生成模型（GPT-5 Mini）被喂入明确的（领域，子领域，意图，难度）四元组，并被约束只输出严格 JSON，每次调用返回五组对，每个种子查询十次；记录以 JSONL 存储，附带 `instruction`、`response`、`field`、`subdomain`、`type`、`difficulty` 等元数据。后处理依次做 schema 校验、按指令小写化哈希的精确去重、一个可选的 Sentence-BERT 式语义去重步骤，以及按长度的过滤，随后由一个更强的模型（GPT-5.1）对随机 10% 子集按五分制打质量分做核验。论文的数据集访问代码片段给出的公开划分为 45,415 训练 / 2,671 验证 / 5,343 测试。Benchmark 子集通过在留出划分上按元数据维度筛选来定义（例如只取 CALC 用于数值与单位检查，取 TRB 与 CMP 用于假设管理，取 DES 与 CODE 用于可行性与上下文敏感性）。

## Domains

化学工程是九个被明确列出的领域之一，含六个子领域：物料与能量衡算、化工热力学、反应工程、分离过程、过程控制与传递现象——都是化工/过程工程的核心内容；且结果按领域分别报告，因此化学工程这一片可以单独计分。该 benchmark 是货真价实的多领域数据集，因此共同领域还包括土木与结构（静力学、材料力学、结构分析、钢结构与混凝土设计、岩土、结构动力学、施工管理）、机械与航空航天（热力学、流体力学、传热、机械设计、动力学与振动、制造、暖通空调；以及空气动力学、飞行力学、推进、航空航天结构、轨道力学）、电气（电路、电子、信号与系统、电力系统、电磁场、控制系统）、材料科学（材料结构、力学性能、相图、失效分析、聚合物与复合材料、腐蚀）与环境科学（水处理、空气质量、水文、废物管理、环境影响）。此外还覆盖工业工程与消防工程两个领域。

## Evaluation

评估分三段：生成回答、多 judge 打分、指标汇总。七个受测模型各自在数据集的 10% 子样本上评估，子样本按领域、子领域、意图类型与难度层级分层（每个模型有超过 5,000 个被打分的条目）。第一层打分是自动的，直接作用于输出文本：标记空输出、拒答模式、意图要求给最终答案却缺失的情况，以及长度/格式异常；当指令中含有可解析为简单谓词的数值边界或可行性条件时，还会输出一个约束满足标记。第二层是针对推理质量与验证行为的细则打分（是否陈述并限定了假设、是否做了与意图相称的验证、是否遵守了约束、是否引入了无依据的前提），实现为 LLM-as-a-judge，使用固定提示词模板与结构化 JSON 输出。判分由来自三家厂商的三个模型组成评审团——Claude Haiku 4.5、GPT-4.1 Mini 与 Mistral Small 3——各自返回 1–5 分及一段简短理由；每个条目的最终分是三位 judge 的算术平均，共产生 115,962 次判分。judge 之间的 Spearman 相关系数在 0.70 到 0.80 之间，所有 judge 两两之间的「相差不超过一分」一致率均高于 85%。已报告的平均分为：GPT-5 4.48（σ = 0.49）、Claude Sonnet 4 4.31（0.66）、DeepSeek V3.1 4.30（0.68）、Mistral 7B 3.81（0.82）、Llama 3.3 70B 3.75（0.78）、Qwen 2.5 7B 3.27（0.92）、Llama 3.1 8B 2.96（0.85）。对所有模型而言，设计（DES）类都是最难的意图，定义（DEF）类最容易；跨领域的分差不大（GPT-5 在各领域之间跨度 0.23 分，Llama 3.1 8B 为 0.44 分），其中工业工程得分最高，航空航天工程与消防工程最难。若改用人工打分，论文建议取一个按种子分层的小子集，配至少两名独立评分者与一套分歧处理流程。

## Main Contribution

作者把 ERI 定位为第一个覆盖工程知识与推理广度、用以测量 LLM 能力的大规模评估工具，理由是现有 benchmark 要么考的是通识、要么只针对单一学科、要么采用无法体现开放式专业推理的选择题形式。除数据集本身外，他们还把这套「收敛式校验协议」——在管线的每一段做跨厂商三角互证、通过跨模型一致性做收敛效度分析、以前沿倒挂检测为幻觉划定上界——作为一个可复制的方法论模板，供那些人工整理 ground truth 成本高昂、难以规模化的领域构建 LLM 生成的评估数据集时参照。

## Key Design Ideas

- 覆盖度即「领域 × 子领域 × 意图 × 难度」的受控笛卡尔积，每个单元样本数固定，总分因此不会被最容易生成的那类题目主导。
- 把意图类型作为第二条约束维度，用以区分「知道一个领域」与「会做这个领域的事」，每种意图各有自己的成功判据（例如 CALC 要求给出单位，TRB 要求给出能区分不同假设的判别性检查，DES 要求显式识别约束）。
- 难度层级在生成时作为显式的条件属性给出，并写入记录元数据，因此可以逐模型追踪随层级上升的性能衰减。
- 两层打分：底层是确定性的自动检查（拒答、缺最终答案、机器可解析的约束违规），只有当约束无法机器核验时才上交给细则层。
- 多厂商评审团取平均分，以稀释任何单一厂商带来的系统性偏差；论文报告了各 judge 的偏移（Claude Haiku 4.5 最严，比 3.84 的总平均低 0.41；Mistral Small 3 最宽松，高 0.29；GPT-4.1 Mini 接近中性，高 0.12），并表明模型排名在不同 judge 之下保持稳定。
- 刻意让生成模型、受测模型与 judge 分属不同厂商，以打破「同一个系统既出题、又答题、又判分」的循环性。
- 以前沿倒挂检测为幻觉划界：前沿模型得分不高于 3.0 的条目被视为疑似劣质参考（占 1.7%），而小模型反超前沿模型的情形被当作参考答案有幻觉的最强信号（分数倒挂率低于 0.1%）。

## Strengths

- 元数据 schema 使每个报告出来的分数都能回溯到领域、子领域、意图与层级，从而支持切片级的失败归因，而不只是一个总分。
- 判分在三家厂商之间做了三角互证，并报告了 judge 间一致性统计；论文还量化了单个 judge 的偏差，而非默认 judge 中立。
- 合成 benchmark 固有的参考答案质量问题得到了实证处理：68.8% 的条目在三个前沿模型上都拿到 4.0 及以上，跨模型标准差偏低（平均 σ = 0.74），只有 0.7% 的条目分歧较大（σ > 1.5）。
- 发布包中含分类体系规范、schema 校验脚本、去重与过滤的清洗工具，以及一套能复现自动检查与报告结构的评估框架，报告格式带版本号以便纵向比较。
- Limitations 一节把该 benchmark 不能证明什么写得很清楚：论文声明 ERI 不应被用来主张合规性、安全认证，或高风险工程决策的自主控制就绪度。

## Limitations

- 参考答案由 LLM 生成，未经人工核验；人工核验的「金标准」校准子集被列为 ERI-V2 的路线图条目，而不是随 V1 一同交付。
- 记录反映的是生成模型训练数据在某个固定时点的知识状态，因此规范类（CODE）与设计类（DES）条目可能引用已被取代的资料，限制了该数据集作为当前专业实践参考的价值。
- 作者指出，基于提示词的构建方式会过度呈现「干净」的题面，而对现实中杂乱的约束呈现不足；且针对 benchmark 做优化会带来应试化的动力学。
- 覆盖面上遗漏了生物医学、核工程等学科，软件工程也仅以 CODE 类条目形式出现；即便在已纳入的领域内，子领域清单反映的也是分类体系设计时的显著性，而非对专业相关主题的原则性抽样。
- Repository note: 化学工程占 55 个子领域中的 6 个，即 1,155 个单元中的 126 个，按每单元 50 条记录计约 6,300 条生成记录——分量可观，但在整个 benchmark 中仍属少数，因此 ERI 是一个带化学工程成分的宽口径工程 benchmark，而不是化学工程 benchmark。
- Repository note: 其中的化学工程条目是教科书式的指令–回答对，内容围绕衡算、热力学、反应工程、分离、过程控制与传递现象；不涉及任何流程图搭建、仿真器在环或装置操作类任务。
- Repository note: 尽管它被表述为「面向基础模型与 agent」的数据集，V1 的评估其实是单轮文本打分——没有执行任何工具调用、环境交互或轨迹；用于评估 agent 式管线的工具轨迹扩展仅被列为未来工作。
- Repository note: 论文访问代码片段中印出的公开划分规模（45,415 / 2,671 / 5,343）合计 53,429，少于生成的 57,750 条记录，这与文中描述的校验和去重过滤是吻合的，但正文并未明确对账。TODO(reference)

# TRIP-Evaluate (2026)

> [English](../../works/trip-evaluate.md) | **简体中文**

## Overview

TRIP-Evaluate 是一个开放的多模态 benchmark，含 837 道单选题，用于评估大语言模型与多模态模型在交通领域的能力。它按"角色–任务–知识"分类体系组织，四个角色中包含一个规划与设计角色，涵盖几何设计审查、通行能力评估、需求预测与交通安全审计。

## Summary

作者认为，交通领域的工作规则密集、计算密集、安全攸关，且天然是多模态的，因此笼统的通用 benchmark 几乎说明不了一个模型能否正确适用某条法规、能否完成一次可核验的工程计算，或者能否读懂一个交通场景。TRIP-Evaluate 给出的回应是一套格式固定、横跨文本、图像与点云的题目，配以三级的"角色–任务–知识"分类体系，外加能力、模态与难度标签，使一个单一的准确率数字可以拆解成可解释的失败切片。该 benchmark 还统一了题目构建、质量控制、提示、解码与评分的规范，并定义了确定性的点云渲染方案，从而让结果在不同模型与不同版本之间可比。论文把它定位为面向模型选型、回归测试与部署风险评估的诊断工具，而不只是一张排行榜。

## Tasks

核心版本含 837 道题：文本题 596 道、图像题 198 道、点云题 43 道。每道题都是单选题，有唯一正确答案与四个选项（A/B/C/D），并各带一个解释字段，注明所依据的法规条款或计算公式。分类体系的第一级是角色：车辆（171 道——感知、定位、规划、控制、行车安全），交通管理（281 道——信号控制、运行监测、事件处置、设施养护、执法合规），出行者（191 道——出行规划、出行决策、可靠性、信息咨询），以及规划与设计（194 道——几何设计审查、需求预测、通行能力评估、交通安全审计）。角色之下，benchmark 又定义了 16 个任务域与 226 个知识点。题目另按能力标注（知识记忆 118 道、逻辑推理 200 道、数值计算 255 道、场景理解 264 道），以及按难度标注（易 167 道、中 456 道、难 214 道）。图像题以一张图配题干与选项的形式呈现；点云题则以两幅确定性渲染图——一幅俯视图与一幅正视图——随题干一同给出。题目构建走的是迭代、带版本的流程，设有四条质量控制规则：每道题必须有唯一且可审计的答案，并记录所依据的条款或公式；干扰项采用"近似错误"策略，每个错误选项引入一处可辨识的错误；选项长度偏差通过约束最长与最短非空选项长度之比来控制，要求 r ≤ 1.25（在写明的条件下另留 1.25 < r ≤ 1.35 的软区间）；答案分布与版本一致性则通过 A/B/C/D 均衡检查、重复筛查、schema 检查与回归修复来监控。

## Domains

土木与结构工程，切入点是交通与基础设施工程。规划与设计角色是其中最清晰的土木切片——几何设计审查的知识点涉及线形与交叉口几何，通行能力评估则以 Highway Capacity Manual 的服务水平概念为依据——而交通管理角色涵盖信号配时、道路标志标线标准、路侧设备与法规解读，这些同样关乎实体道路基础设施的设计与运行。论文把最难的一块切片表述为一条由公式、量纲一致性、边界条件与约束校核构成的"工程可核验链"，且有一位作者隶属土木与环境工程系。车辆角色的知识点涵盖感知、SLAM、路径规划、横纵向控制与 V2X 通信，据此指派机器人学作为共同领域是成立的；而出行者角色（出行行为、驾驶心理、车内 HMI）则两个领域都不属于。benchmark 中不涉及建筑、桥梁或基础这类结构工程内容。

## Evaluation

每道题都在统一的核心提示词、固定的解码与采样设置下呈现，并要求模型只输出 A/B/C/D 中的一个字母；异常输出（空答案、非 A/B/C/D 字符串、多个字符）由一套统一规则处理，要么直接判错，要么取第一个有效选项，同时作为稳定性指标记录在案。主指标是逐题准确率。除总体准确率外，benchmark 还分别按角色、任务域、知识点、能力、难度与模态报告准确率，并记录 benchmark 与提示词版本、解码参数以及异常输出处理规则，使结果在版本更迭后仍可审计。纯文本模型与多模态模型分开计分，前者在文本子集上、后者在完整多模态集上。受评阵容涵盖推理导向的与闭源的系统（DeepSeek-R1、Gemini-3-flash-preview、Claude Sonnet 4.6、Claude Sonnet 4.5、Qwen-max）、开放权重多模态模型（Qwen2-VL-72B-Instruct、Qwen3-VL-8B-Instruct、gpt-oss-120b、gpt-oss-20b、Llama-3.2 视觉指令微调系列），以及纯文本或专用模型（DeepSeek-V3.2、Gemma-2-27b-it、Gemma-2-9b-it、Qwen3-8B、Qwen2.5-Coder 指令模型）。报告的头条结果为：在完整多模态集上，只有 Gemini-3-flash-preview 的总体准确率达到或超过 85%，为 88.8%；在纯文本子集上，Gemini-3-flash-preview 为 91.3%，DeepSeek-R1 为 90.8%。相对文本题，点云题对每一个受评模型都带来约 29.7 到 57.5 个百分点的系统性折损。数值计算是最弱的能力切片，文本基线准确率仅 45.6%；在难题上，DeepSeek-V3.2 掉到约 49.6%，Qwen-max 掉到约 47.8%。

## Main Contribution

作者把 TRIP-Evaluate 作为一个开放的多模态交通 benchmark 提出，自述两项贡献：一是分层的"角色–任务–知识"组织方式，配合能力、模态与难度标签，把评估结果映射到业务责任边界与可枚举的能力目标上，从而把单一分数变成可操作的诊断信号；二是基于俯视图与正视图渲染的确定性点云评估方案，为三维交通理解提供了一个标准化、可审计的切入口。

## Key Design Ideas

- 分类体系从交通*职能*（角色）而非学科主题出发，因此结果对应的是真实工作流与责任边界，而不是学术分类。
- 每道题都保留解释字段，注明答案背后的法规条款或公式，既便于人工审计，也为将来扩展到基于解释的评分留好接口。
- 干扰项按"近似错误"策略构造，每个错误选项都编码一处可辨识的错误——漏掉某个条件、边界弄错、概念混淆——因而错误分析能定位到具体失误。
- 选项长度偏差被当作一项可测量的构建约束，设有明确的比值阈值，而不是停留在非正式的编辑准则上。
- 点云被转换成两幅确定性渲染图，投影方式、裁剪区域与栅格化全部写明，因此多模态结果不依赖某个不透明的点云特征提取器。
- 只有当视觉载体是解题所必需时，一道题才计为多模态；装饰性的图像被排除在外，以免引入人为的评估噪声。
- 论文把"工程可核验链"（公式、单位、边界条件、约束校核）与"安全语义链"（场景理解、路权、规则适用性、空间关系）分开，并表明二者在不同压力下退化：后者受模态影响，前者受难度影响。

## Strengths

- 切片式设计一路贯彻到了结果层：准确率按角色、能力、难度与模态分别报告，知识点层面的帕累托分析还能指出每个角色的错误主要集中在哪几个知识点上。
- 模态覆盖是货真价实的三路，包含大多数偏语言的领域 benchmark 都不做的点云子集。
- 构建与评分协议记录得足够细——提示、解码、异常输出处理、版本日志——足以复现。
- 跨四个开放模型族做了参数规模缩放检验，用以说明该 benchmark 区分的是模型容量差异，而不是在测噪声。
- 模型覆盖面广，推理导向、多模态与纯文本系统都被纳入同一套协议下评测。

## Limitations

- 837 道题要摊到四个角色、16 个任务域与 226 个知识点上，落到单个知识点上的样本非常稀薄；点云子集只有 43 道题，论文自己也指出部分能力切片的样本量小到只能把结论当作趋势来读。
- 作者声明该 benchmark 是离线且静态的，因此无法反映分布偏移、噪声输入、罕见边缘情形或实时性约束，其涉及的法规与标准也具有地域性。
- 结果基于单次评测运行，没有误差棒——这一点见于论文自己的图注。
- Repository note: 所有题目都是四选一的选择题，因此该 benchmark 衡量的是交通知识与闭式推理，而不是 agent 行为；其中没有工具使用、没有多步轨迹、也没有环境，论文把闭环评估列为后续工作。
- Repository note: 只有规划与设计角色以及交通管理角色的一部分属于土木基础设施工程；车辆与出行者角色的内容分别属于自动驾驶与出行行为，因此土木工程在整个 benchmark 中占的是相当可观的少数份额，而非全部。
- Repository note: 论文称已开源 TRIP-Evaluate，但预印本中没有给出任何仓库或数据集 URL，因此其发布位置无从核实。

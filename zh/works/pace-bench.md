# PACE-Bench (2026)

> [English](../../works/pace-bench.md) | **简体中文**

## Overview

PACE-Bench（Physics Adaptation via Code Evolution）考察自演化 agent 在世界从脚下变掉之后能否恢复。它的 144 个任务各自把一个源物理环境与一个变异后的目标环境配成一对，两者目标与接口相同；在源环境中成功的代码化设计到了目标环境中会失败，agent 必须在有限的尝试预算内，借助沙箱的诊断反馈把它逐步修好。

## Summary

现有的自演化 agent 评估都在固定执行条件下做优化，从不检验条件变了之后会怎样。PACE-Bench 从构造上堵住这个缺口。一个任务的起点是一份能用的解——一段定义 `build_agent()`（结构装配）与 `agent_action()`（控制逻辑）的 Python 程序——它在源 Box2D 环境中是成功的。目标环境的目标与接口都不变，只变异摩擦系数、材料强度、重力、力上限这类物理参数，而源设计在那里会失败。agent 要把程序改造成在目标环境中可用的设计，依据是一份结构化诊断反馈：它报告哪里出了问题，但不给出该怎么改。作者比较了来自四种范式的十种自演化方法，结果显示这个 benchmark 远未饱和。两个结果撑起了全文的论点：有仿真器兜底的反思比未经验证的自我修改更可靠；而在全文最扎眼的一次实验里，把究竟哪些物理量变了原原本本告诉 agent，也抬不高天花板——这把瓶颈定位在机制的重新设计上，而不是参数的推断上。

## Tasks

**36 个基础任务**衍生出 **144 个源到目标的适配对**（每个任务 4 对），在**六个物理领域间均分，每个领域 6 个任务**：静力学与平衡、运动学与连杆、动力学与能量、颗粒与流体相互作用、控制论与控制、非常规物理。每个任务的四对构成逐级升高的阶段，**第 1–4 阶段分别变异 2 到 10 个参数**。仿真器是 **Box2D** 二维刚体引擎，运行在 **60 FPS**。

## Domains

**Physics。** 六个任务族在字面意义上就是物理分支——静力学、运动学、动力学、颗粒与流体相互作用、控制，以及一个非常规物理族——成功要求在物理参数改变后就机制本身作出推理，并由刚体仿真验证。不指派工程类共同领域：这些设计是仿真中的二维机构，而非对照任何工程规范或制造约束评判的实物。

## Evaluation

尝试预算为**每个源到目标对 20 次**。每次尝试之后，agent 收到结构化诊断反馈：约束满足比例（v）、位于 **[−100, 100]** 区间的任务分数（s），以及一份诊断报告（d），列出峰值关节力、失败时刻这类有物理含义的量——但刻意不给出修改建议。结果以 **Pass@2** 与 **Score@2** 报告。

论文比较了**四种范式下的十种方法**：基于上下文（Vanilla、Reflexion、Self-Refine）、记忆增强（ACE、ExpeL、ReasoningBank）、推理期搜索（Tree-of-Thoughts、CodeEvolve）、基于参数（SEAL、RAGEN、TTT-Discover）。

benchmark 远未饱和。在全量 benchmark 上，**Reflexion + Qwen3-14B 的 Pass@2 只有 35.9%（Score@2 为 28.0）**，Vanilla + Qwen3-14B 为 **32.0% / 25.5**。在静力学子集、完整预算下，**GPT-5.5 达到 66.7% Pass@2（Score@2 为 78.1）**，**Qwen3-32B 为 37.5%（28.4）**。逐方法看，Tree-of-Thoughts 的 Pass@2 为 **20.3%**，但以 **57.8 Score/Hour** 在效率上领先；ACE 为 **25.0%**；Self-Refine 塌到 **7.1%**。分类别难度差距很大：非常规物理最容易解，Pass@2 为 **56.3%**；动力学与能量最难，为 **12.5%**（均为 Qwen3-14B + Vanilla）。

变更暴露实验把改动的变量与取值原样告知（CE），与隐藏它们（CH）作对比。暴露**没有帮助，多数情况下反而有害**：Reflexion-14B **17.9% → 14.6%（−3.3）**，Vanilla-14B **17.0% → 9.8%（−7.2）**，只有 ACE-4B 是唯一受益者，**6.0% → 12.0%（+6.0）**。

## Main Contribution

一个把难度来源放在环境的受控变更、而非任务新颖度上的适配 benchmark，它单独隔离出「一份可用的设计在其前提被打破之后能否修好」这项能力——以及随之而来的反面结果：把变了什么告诉 agent 并不能抬高天花板，这把瓶颈从参数推断（know what）重新框定为机制重设计（know how）。

## Key Design Ideas

- 每个任务都从一份**可用**的解出发，因此测的是前提被打破之后的恢复能力，而不是从零开始解题。
- 源与目标共享目标与接口，除物理之外一切不变，变异因而成为失败的唯一解释。
- 诊断反馈有物理含义但不作指示：它报告峰值关节力与失败时刻，不说该改什么。
- 每个基础任务四个逐级阶段，从变异 2 个参数升到 10 个，构成难度梯度，饱和点可以被定位而不只是被观察到。
- 变更暴露消融是一次上界探测：把参数改动的真值直接交给 agent，就能把「没推断出变了什么」与「重新设计不出机制」分开。
- 在同一套任务上比较四种迥异的自演化范式，使范式层面的结论——记忆把 agent 锚在早期设计上、宽树搜索只探索不收敛——具备可比性，而不停留在轶事。

## Strengths

- 成败由刚体仿真器依据明确的约束满足比例判定，而不是 LLM 评判器。
- 变更暴露实验是对论文自身最可能解释的一次认真反驳，而且即便效果多为负面，结果依然照实报告。
- 分类别结果单列，非常规物理与动力学能量之间四倍的差距因而可见，而不是被汇总数掩盖。
- 十种方法、四种范式的覆盖面，足以支撑范式层面而非方法层面的论断。
- 效率与准确率并列报告（Score/Hour），靠多花时间取胜的方法不会被记作绝对更优。
- 代码与数据以 CC BY 4.0 公开。

## Limitations

- 全部实验都在二维 Box2D 中进行。作者直言结论未必能迁移到三维环境或真实机器人。
- 20 次的尝试预算是固定的，限定了交互时程，天花板在更多尝试下能抬多高仍未可知。
- 受算力所限，前沿模型、参数披露与视觉反馈这几项研究只覆盖了部分领域与方法，最强模型并未在全量 benchmark 上评测——GPT-5.5 的 66.7% 是静力学子集上的数字，与全量结果不可比。
- 每对的绝对墙钟与 token 开销未列表（上文记为 `TODO(reference)`）。
- Repository note: 变异改的是既有仿真的参数，而不是物理模型的结构，因此这里的「物理适配」指的是在同一个仿真器内适配不同参数取值，而非适配另一种物理机制。

## Related Works

- [Gravity-Bench-v1](./gravity-bench.md) — 物理发现任务，环境可以违反已知定律，观测预算计入评分，测的是对物理的推断而非物理改变后的恢复。
- [SimulCost](./simulcost.md) — 面向仿真参数调优的成本感知评估，同样采用有预算的迭代框架，但任务是参数拟合而非机制重设计。
- [EngDesign](./engdesign.md) — 由仿真对照规格评判的工程设计，设计从零产出，而非在环境变化后修复。
- [AutoWorldModel-Bench](./autoworldmodel-bench.md) — 同样在固定预算下交给 agent 一份可用工件去改进，对象是学习得到的世界模型而非物理机构。

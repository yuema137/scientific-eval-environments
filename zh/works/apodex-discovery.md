## Overview

Apodex Discovery 由一组可执行的「基于现实」的环境与一套配套的过程评分 rubric 组成，用于评估 AI 系统在真实世界发现问题上的表现。20 个问题选自一次覆盖 561 个行业的调研，每个问题都落成一个带工具、数据与隐藏验证器的有状态环境；求解者的轨迹则在不知道结果的前提下，按六个过程维度打分。

## Summary

论文的立论类比是阿波罗计划：只要问题、工具与成功判据都被明确下来，前沿模型就能解决很难的题目，因此瓶颈在于「把问题说清楚」，而不在模型本身。Apodex 据此给出三样东西。其一是一套问题勘察流程：调研 561 个行业，寻找同时具备技术可行性、价值与商业可及性的问题，从 423 个候选收敛到首批发布的 20 个。其二是一层环境抽象，把每个问题变成有状态的交互底座——工具、数据、算力资源与实验接口——它会针对求解者的动作返回新的观测，同时从结构上杜绝隐藏真值流向求解者。其三是一套过程 rubric，评的是求解者**怎么做**而不只是**做出了什么**，且评判时既不知道结果，也不知道求解者是谁。作者报告了腺相关病毒衣壳设计与药物重定位两项结果，两次比较的参照物都在系统之外。

## Tasks

首批发布 **20 个问题**，来自一支 **十人团队历时两个月、横跨 561 个行业**的调研所识别出的 **423 个候选**，筛选依据三个维度：技术契合度（推理深度、可验证性、可执行性）、价值（里程碑式的科学结果，或足够大的市场）、商业可及性（能否超出单一客户而规模化）。这些问题分布在**十个领域**：生物信息学与基因组医学；面向科学推理的基础模型；科学 HPC 代码生成与优化；医疗 IT 与数字健康；气象驱动的大宗商品与能源预测；结构与土木工程服务；芯片设计与验证（EDA）；市场数据与金融指数；材料发现、设计与验证；工业自动化与控制。

每个问题都落成一个可运行的环境，自带数据、预算与隐藏验证器，并通过固定的 episode 接口把表现归因到求解者的具体组件。

## Evaluation

轨迹按六个过程维度打分，摘要中称之为 **HDS6**，正文则用助记词 **TRACES**：**Tools**（选择、调用并正确解读外部工具）、**Repair**（对验证反馈或观察到的失败作出回应，改正根因，并确认修好了）、**Alternatives**（把彼此竞争的假设摆到明面上，并随证据积累在其间作出裁断）、**Coherence**（在长时程中维持状态、约束与逻辑一致性）、**Evidence**（把论断落在观测、工具输出、数据、实验或参考文献上）、**Scope**（指明结论在什么条件下成立，以及越过哪条边界就不该再套用）。

评分有两种方法。子 rubric 法把 **25 项子能力（每个维度 3–5 项）**放在 **0/1/2** 的序数档位上打分。承重步骤法则构建轨迹依赖图，识别出关键步骤，再把每一步单独重解一遍，得到连续的差距分。两者都以**盲过程验证**方式进行——不知结果，且隐去求解者身份——另有一道诚信闸门专门检测虚构的工具调用与编造的结果。

过程分与结果分被报告为大体一致但并不重合：**总体 Spearman ρ = +0.51**，按环境分布在 **+0.24 到 +0.65** 之间。

已报告的结果：在衣壳设计上，**Apodex 在全部四项任务上都超过该任务层面已发表的最好水平 7%**（活性预测、嗜性预测、结构预测、生成式设计）。在药物重定位上，加入面向该任务的生物医学环境后，**GPT-5.5 的平均归一化预测分提高 2.5 分，GPT-5.6-sol 提高 7.6 分**，对照组是同一个闭卷骨干模型。

## Main Contribution

一层让真实世界发现问题变得可执行、可验证的环境抽象——隐藏真值从结构上与求解者隔离——配上一套不知结果即行评判的过程 rubric，以及随之测得的一个数字：过程判断与结果判断只是中度相关（ρ = +0.51），这正是论文主张两者都要评的依据。

## Key Design Ideas

- 隔离原则是结构性的而非程序性的：隐藏真值由环境的构造方式阻断在求解者之外，而不是靠要求求解者别去看。
- 过程验证在两个意义上都是盲的——验证方既不知道结果，也不知道轨迹出自哪个求解者——因此过程分无法从成败反推出来。
- 同一批轨迹上并行套用两种独立评分法：序数式子 rubric 档位，以及把关键步骤单独重解一遍的承重步骤连续分。
- 诚信闸门专门盯住虚构的工具调用与编造的结果，把轨迹层面的不诚实当作一种独立的失效模式，而不是当作质量偏低。
- 问题勘察阶段把商业可及性与科学价值一并纳入筛选，这在 benchmark 中并不常见，也正是十个领域跨度如此之大的由来。
- 报告过程—结果相关性本身就是一项设计选择：ρ = +0.51 意味着两者关联到足以互相印证，又相异到谁也替代不了谁。

## Strengths

- 两项已报告的结果都锚定在系统之外的参照物上——衣壳设计对照已发表的最好水平，药物重定位对照去掉环境的同一骨干模型——而不是对照另一个 agent 或自我评估。
- 药物重定位那组对比是一次干净的消融：同一模型、同一问题，只加或减环境，测得的增益因而可归因于环境本身。
- 隐去身份的盲过程验证，比 agent 评估中常见的「知道结果再评过程」要严格。
- 环境可执行、有状态、带隐藏验证器，任务因此不是静态题库。
- 筛选漏斗有据可查（561 个行业 → 423 个候选 → 20 个问题），标准也写明了，发布内容的构成可稽核。
- 报告过程分与结果分只是中度相关，这个发现让论文自己的评分叙事变得更复杂，而它仍连同分环境的取值范围一并给出。

## Limitations

- 定量结果只覆盖 20 个问题中的 2 个。其余 18 个环境有描述，但本文没有给出对应的 agent 表现。
- 分领域的问题数没有给出，导致所点名的十个领域中大多数无法进入领域轴（上文记为 `TODO(reference)`）。
- 受评模型没有被完整列举；点名的只有 GPT-5.5 与 GPT-5.6-sol，过程验证则由未具名的 agentic 流程完成。
- 该指标在摘要中叫 HDS6、在正文中叫 TRACES，论文没有对这两个名字作出统一。
- 各问题的预算未报告，因此取得上述增益时的资源条件无法据论文复现。
- Repository note: 访问入口是一个与商业实体关联的项目网站（discovery.apodex.com），而非开放的代码发布，论文的许可声明也只涉及 arXiv 投稿本身。这些环境能否自由获取，此处无法确认。
- Repository note: 衣壳设计的 7% 被描述为在四项任务上超过该任务层面已发表的最好水平；就所见内容而言，论文没有给出这四项各自的基线数值，因此这个汇总值无法拆解。

## Related Works

- [LAB-Bench](./lab-bench.md) — 带专家基线的生物学研究能力评估，采用静态题型，而非带隐藏验证器的可执行环境。

- [AutoResearchEval](./autoresearcheval.md) — 同样评研究过程而不只评结果，用的是标注轨迹上的失效分类体系，而非盲评 rubric。

- [Beyond Final Scores](./beyond-final-scores.md) — 面向长时程 agent 运行的过程测量，由执行信号确定性算出，而非靠盲评 rubric 判定。

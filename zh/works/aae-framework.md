# Autonomous Action Execution (AAE) Framework (2026)

> [English](../../works/aae-framework.md) | **简体中文**

## Overview

AAE 框架是一套四层多 agent 架构，用于把 LLM 推理安全地引入工业过程控制：LLM 只出现在仅做观察的 Monitor 层，模型提出的每一个动作都要交由确定性校验器审查，而校验器沿装置的 P&ID 拓扑做图遍历。评估由三部分构成——分级基线阶梯、针对人工构造提案的错误注入研究，以及横跨五个流程装置场景的重复运行稳健性研究。

## Summary

论文的出发点是：LLM 具有非确定性、容易产生幻觉，又缺乏内在的物理理解，把它直接部署到安全攸关的过程自动化中是不可接受的；全文围绕「如何安全地引入 LLM 推理」提出五个研究问题来组织贡献。架构上，它给出一套四层多 agent 设计——LLM 推理只出现在仅做观察的 Monitor 层，安全攸关的决策交由确定性的 Verification 与 Execution agent 作出。为了给这一层提供输入，论文引入一个带可插拔分析器的文本级聚合框架，把 SCADA 状态、时序测量、管道仪表流程图（P&ID）与标准操作规程（SOP）统一转写为上下文丰富的文档。其余研究问题都落在评估上：一套以 P&ID 为依据的自动校验方法、一组量化管线中各组件增量价值的分级基线对照，以及一项跨场景的泛化性研究。

## Tasks

评估覆盖五个工业场景：三个取自 Tennessee Eastman Process（TEP）benchmark（Downs & Vogel, 1993），论文以其作为社区标准的验证依据；另外保留 PolyReactor 与 Dryer 两个场景，用来划定性能边界——从零幻觉的最好情形，到 70% 安全违规的最坏情形。这些场景兼有连续与间歇过程，P&ID 复杂度各不相同。另有两组任务驱动具体测量：一是覆盖校验器各类失效模式的错误注入研究，用 43 条人工构造的提案；二是 N = 50 次 LLM 运行的统计稳健性研究。分级基线阶梯（B0–B3）通过改变供给模型的聚合装置上下文多寡，使管线中每个组件的贡献都能被单独记账。

## Domains

化学工程——工业过程控制与过程安全。场景均为化工装置：Tennessee Eastman Process、一台聚合反应器（PolyReactor）和一台干燥器，兼含连续与间歇操作。受评对象是针对装置设备提出的控制动作，需对照 P&ID 拓扑校验位号是否存在、是否可执行、失效状态是否一致、下游影响如何——属于装置操作与功能安全任务，而非化学任务。出版方标注的关键词为多 agent 系统、大语言模型、工业过程控制、功能安全、P&ID 校验与 SCADA。

## Evaluation

判分单位是 LLM 提出的单个动作，而不是端到端的任务得分。以 P&ID 为依据的校验器在 P&ID 拓扑上做图遍历，逐条核验提案的物理一致性——位号是否存在、是否可执行、失效状态是否一致、下游影响如何；结构性检查之外，再叠加一份按场景定制的禁止动作细则。校验器自身的质量，由一项覆盖 43 条人工构造提案的错误注入研究来衡量：论文报告校验层在所覆盖的失效模式上取得 100% 召回（零漏检）。稳健性则在 N = 50 次 LLM 运行上测量：即便 LLM 在 10%–70% 的运行中提出不安全动作，论文仍报告在所评估的场景下，确定性校验层拦下了所覆盖类别（结构性非法，或属细则明令禁止的动作）中的每一条非法提案。B0–B3 基线阶梯负责把各个上下文增强组件的增量贡献分别归因。

## Main Contribution

论文明确给出的核心结论是：在流程工业中以架构约束的方式引入 LLM 顾问能力，本质上是一个架构问题；分离关注点、独立保护层、确定性安全逻辑这些成熟的系统工程原则，能在流程工业部署 LLM 顾问系统时，针对所覆盖的那些校验层失效模式提供确定性的把关。

## Key Design Ideas

- LLM 推理被限制在只做观察的 Monitor 层；作安全攸关决策的 Verification 与 Execution agent 是确定性的，于是不可靠的那个组件永远不掌握执行权。
- 聚合框架借助可插拔的分析器，把异构的装置数据（SCADA 状态、时序、P&ID、SOP）统一归一化为文本文档，于是上下文构建成了一个可单独测试的组件。
- 校验的依据是装置自身的工程资料：在 P&ID 上做图遍历，核验位号存在性、可执行性、失效状态一致性与下游影响，而不是指望模型自己去推理物理结构。
- 分级基线阶梯（B0–B3）内建于评估之中，使每个上下文增强环节的贡献都能单独记账，而不是只报告完整管线的成绩。
- 用人工构造的非法提案做错误注入，把校验器的覆盖度变成一个可测的召回数字，而非默认成立的性质。
- 以 Tennessee Eastman Process 作为共用的参考装置，使五个场景中的三个建立在社区标准模型之上。

## Strengths

- 校验器的表现是用对抗方式测出来的——43 条刻意构造的错误提案，而不是只看 LLM 恰好产出了什么。
- 稳健性研究覆盖很宽的幻觉区间（N = 50 次运行中 10%–70% 的不安全提案），因此安全性主张既在模型表现好时受检，也在表现差时受检。
- 五个场景中有三个立足于 Tennessee Eastman Process，给出的是外部可辨识的过程模型，而非完全自制的试验台。
- 论文自己就把结论的适用范围划清楚了：召回率是就所覆盖的失效模式而言，结论也限定在所评估的合成场景之内。

## Limitations

- 场景是合成的；论文把可移植性的说法限定在「所评估的合成场景之内」，因此并未提供真实装置部署的证据。
- 100% 召回只适用于所覆盖的类别——结构性非法的提案与细则中定义的禁止动作——对于结构合法、又未被细则枚举的不安全提案则未置一词。
- Repository note: 由于 LLM 在架构上被限制为只做观察，评估实际测的是确定性校验器的覆盖度，而非任何 agent 的任务完成能力，因此它更像一次验证器评估，而不是 agent benchmark。
- Repository note: 可获取的记录中无法核实场景、43 条注入提案或校验代码是否公开发布，其中也未标明所评估的 LLM 型号，复现因此受限。
- Repository note: 该工作由工业界单位（Siemens AG Austria）单人署名，出版方页面上记录了作者声明的利益冲突。

# CEQuest (2025)

> [English](../../works/cequest.md) | **简体中文**

## Overview

CEQuest 是一个含 164 道题目的 benchmark，考察施工图纸解读与工程造价估算。题目由领域专家依据造价估算教材与图纸解读指南编写，并用于在准确率、评测耗时与模型规模三个维度上比较五个 LLM。

## Summary

论文认为，MMLU、HellaSwag 这类通用 LLM benchmark 反映不出建筑施工所需的推理能力；而 FloorPlanCAD 等已有的建筑类数据集针对的是视觉符号识别，并非施工从业者真正在做的文字推理与造价估算。论文把 CEQuest 定位为填补这一空白的试点 benchmark：题目经过精选，覆盖从最基础的读图能力，到跨图纸的空间对照，再到工程量计算与造价估算这一进阶过程。作者在其上评测了五个 LLM——四个通过 Ollama 本地部署的开放权重模型，加上通过 OpenAI API 调用的 GPT-4.1——每次运行重复五遍，以均值 ± 标准差报告。作者称没有模型的准确率超过 80%，并指出两种反复出现的失败模式：无法稳定遵守要求的作答格式；以及估算结果在数值上看似合理，却违背行业实务规范。

## Tasks

共 164 道题目，全部由领域专家收集与设计，参考材料包括造价估算教材、图纸解读指南以及施工教育中的真实教学实践。题型有两种：101 道多项选择题（62%），每道给出三到六个带标号的选项；以及 63 道判断题（TRUE/FALSE，38%）。题目按施工图纸解读与估算的渐进学习阶段划分为五个主题领域：**General Construction Knowledge**（对施工流程的宏观概念理解）；**Drawing Element Identification**（比例、标注、说明、图例、材料，以及墙、门等建筑构件）；**Drawing Organization and View Types**（平面图、剖面图与详图，投影关系，图纸编排）；**Spatial Reasoning and Cross-referencing**（同一视图内建筑构件的空间关系，以及跨多张图纸串联信息，例如把平面图上的一道墙对应到它的剖面详图）；**Quantity Takeoff and Estimating**（解读尺寸数据，计算数量、长度或面积并完成造价估算）。数据集统计如下：平均每题 3.59 个选项（最多 6 个），每题 1.69 句（最多 3 句），每题 14.29 个 token（最多 67 个），每个选项 1.97 个 token（最多 8 个）。数据集以结构化 JSON 存储，每条含题号、题干、正确答案，多项选择题另附选项列表。论文没有以数字形式给出各主题领域的题量，只在图中呈现；各领域的具体分布为 `TODO(reference)`。

## Domains

土木与结构工程。受评目标是建筑项目上的施工工程作业：阅读并交叉对照施工图纸、识别图纸元素与视图类型、依据尺寸数据完成工程量计算与造价估算。这落在该领域中施工工程、计划、进度与工程量/造价估算的范围内。论文给出的失败案例是一道混凝土楼板体积计算题（5.33 立方码），模型选了最接近的整数，而行业估算实务要求向上取整——考的是估算实务判断，而不是就文档论文档的阅读理解。作者来自 Florida International University 与 University of Florida。评测中不涉及结构分析、构件设计或规范符合性校核，因此不另行指派共同领域。

## Evaluation

单轮问答，按答案精确匹配评分。作者实现了与 OpenAI API 集成的评测函数，负责向模型提问、解析输出并计算指标。共报告三项指标：**准确率**（答对题目的百分比）、**执行/评测耗时**（模型跑完整套题目的总 wall-clock 时间）与**模型规模**（存储体积或参数量）。各模型的提示词固定一致，多项选择题统一使用「Please answer with only the letter of the correct option (A, B, C, D, E, or F).」。每组实验重复五次，以均值 ± 标准差报告。受评模型及结果为：Gemma3:4b（3.3 GB）61.83 ± 0.30%，耗时 11.04 ± 0.73 秒；Phi4:14b（9.1 GB）64.02 ± 0.55%，耗时 70.00 ± 4.06 秒；LLaVA:34b（20 GB）62.56 ± 1.06%，耗时 29.24 ± 4.36 秒；Llama 3.3:70b（43 GB）65.37 ± 0.60%，耗时 175.00 ± 2.52 秒；GPT-4.1 为 75.37 ± 1.13%，耗时 86.26 ± 5.21 秒（API 调用时长；模型规模未公开）。开放权重模型经 Ollama 本地部署，硬件为 AMD Ryzen Threadripper PRO 7965WX CPU、256 GB 内存与两块 NVIDIA RTX 3090 GPU。作者称该评测框架可扩展到新的模型、指标与建筑数据类型。

## Typical Duration

单轮问答，没有多步轨迹。各模型跑完全部 164 道题的 wall-clock 时间从 11.04 秒（Gemma3:4b）到 175.00 秒（Llama 3.3:70b）不等；GPT-4.1 耗时 86.26 秒的 API 时间。论文未报告单题的 token 预算。

## Main Contribution

作者自述的三项贡献：开发并公开发布 CEQuest，作为施工图纸解读与造价估算问答的 benchmark；在其上从准确率、执行耗时与模型规模三方面对五个不同的 LLM 做出全面的实证评测；以及给出关于当前 LLM 在建筑施工领域能力与局限的可操作洞察，进而论证开发施工专用模型的必要性。

## Key Design Ideas

- 主题领域按施工图纸解读与估算的渐进学习阶段设置，整套题目从最基础的读图能力一直延伸到工程量计算，而不是只考单一能力。
- 题目由领域专家依据造价估算教材与图纸解读指南编写，而非爬取而来；题型兼用多项选择与判断两种。
- 评测在准确率之外同时报告评测耗时与模型规模，让准确率、算力与规模之间的权衡显式可见，而不是只给一个准确率。
- 所有实验重复五次并报告均值 ± 标准差，运行间的波动因此得以如实呈现，而不是压缩成单个数字。
- 各模型使用完全相同的固定提示词；评测框架在设计上也预留了扩展新模型、新指标与新建筑数据类型的空间。

## Strengths

- 题目出自专家编写而非自动生成：每一条都由领域专家参考造价估算资料与教学实践收集和设计。
- 给出了一次真正的多模型横向比较，涵盖四个规模差异很大的开放权重模型加一个闭源模型，且提示词完全一致。
- 重复运行并报告标准差，同时给出算力/规模这一维度——对一个小规模的领域问答集来说并不常见。
- 错误分析具体且扎根领域，把格式遵循的失败与估算判断的失败（混凝土工程量取整那一例）区分开来。
- 数据集与评测代码在开放仓库中发布。

## Limitations

- 论文明确把 CEQuest 称作试点研究；164 道题分摊到五个主题领域后各领域样本量偏小，且分领域结果未以数字形式报告。
- 所有题目都是多项选择或判断题，因此 benchmark 衡量的是认出正确选项，而不是做出一份估算——模型不必真的完成工程量计算也可能得分。
- 评测中不涉及 agent、工具使用或多步轨迹，只是对照静态标准答案的单轮问答。
- 作者自己也指出模型经常偏离要求的作答格式，这使准确率这一指标把格式遵循与领域知识混在了一起。
- 作者列出的后续工作——扩充数据集、微调、检索增强与多模态学习——说明当前版本尚未涉及多模态的图纸输入。
- Repository note: 尽管论文以「施工图纸解读」作为立意，发布的数据集却只包含 JSON 形式的题干文字与选项，且报告的题干长度（平均 14.29 个 token）表明题目都是很短的文本条目；任务输入中并未描述任何图纸图像，尽管受评模型之一（LLaVA）是视觉语言模型。
- Repository note: 论文使用 ACM 模板，发表出处与 DOI 字段仍是占位符，因此无法核实其同行评审发表信息。

## Related Works

- [DrafterBench](./drafterbench.md) — 另一个基于施工文档构建的土木工程 benchmark，但评分对象是产出的图纸修改，而非关于图纸的问答。

- [PE Civil Bench](./pe-civil-bench.md) — 执业资格考试风格的土木工程题目，同样取材于专业参考资料。
- [Civil-Eval](./civil-eval.md) — 源自考试的土木工程知识 benchmark，单轮评分设计与之相仿。

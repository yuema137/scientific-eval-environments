# AutoResearchEval (2026)

> [English](../../works/autoresearcheval.md) | **简体中文**

> **首次公开：** 2026-08-14 · **来源：** [arXiv 首次提交](https://arxiv.org/abs/2608.14905)

## Overview

AutoResearchEval 是对端到端自主研究 agent 的一次诊断式评估：100 个任务取材于已发表的前沿科学，覆盖从构思到复查的完整研究生命周期。它不按最终分数给系统排名，而是对 800 条完整轨迹做过程级标注，并把结果整理成 ARFT——一套由实证归纳出的 45 种失效模式。

## Summary

作者观察到，现有的 AutoResearch 评估只报告表现，不透露过程：任务范围窄，分数说不出 agent 在哪一步垮掉，失效诊断既缺乏系统覆盖，也看不到中间产物。AutoResearchEval 转而正面回答诊断问题。任务取材于已发表的前沿科学，覆盖六个生命周期阶段；八种 harness–模型组合各自跑完全部 100 个任务，产出 800 条带过程级标注的轨迹。这些标注被归并成 ARFT，按生命周期阶段与根因两个维度交叉归类失效。为了让这种细粒度归因在这一规模上还负担得起，作者构建了一条经人类校准的 agent-as-a-judge 流水线，它检查的是完整轨迹与中间产物，而不是最终答案。核心发现是收敛的：所有配置下的失效模式都指向同一处缺口——缺少元认知回路，也就是把产出与所掌握的证据相互核对、发现对不上就修正、并回头质疑所走路径是否站得住的能力。

## Tasks

**100 个任务**，从九个领域的 **5,878 个初始候选**中筛出，保留七个科学领域。任务分为**开放式发现（n = 70）**与**目标锚定的优化（n = 30）**两类。每个任务都要走完六个阶段的完整研究生命周期：**A — 构思与规划**、**B — 检索与综合**、**C — 执行与实现**、**D — 分析与解读**、**E — 撰写与记录**、**F — 自我验证与复查**。`TODO(reference)` — 各领域的任务数只出现在图中，正文没有给出数值，因此每个领域切片的规模无法引用。

## Evaluation

**八种 harness–模型组合**产出 **800 条轨迹**：Claude Code 分别搭配 opus-4.8、claude-sonnet-5、qwen3.7-max、glm-5.2、minimax-m3 与 deepseek-v4-pro；Codex 搭配 gpt-5-mini；Gemini CLI 搭配 gemini-3.5-flash。

评分是诊断性的而非比较性的——**论文没有给出任何按模型排列的性能表**。轨迹对照 **ARFT** 打标签，后者把 **45 种失效模式**放在两个正交维度上：生命周期阶段（A–F，外加跨阶段层 X），以及根因支柱，每种模式恰好归入一根支柱——**R1 接地与忠实性（12 种）**、**R2 认知深度与适应性（13 种）**、**R3 科学诚信与对齐（13 种）**、**R4 工程稳健性（7 种）**。

归因由 **agent-as-a-judge** 完成，在 **50 条验证轨迹**上校准，模式层面达 **κ = 0.75**，分类体系层面达 **κ = 0.83**，而单次调用的 LLM-as-a-judge 基线只有 **κ = 0.53 / 0.62**，模式层面召回率相差 **+17.2**。800 次分析共记录 **12,712 次模式命中**；出现最频繁的单一模式 **F.4（未纠正的自我认知）出现在 82.5%** 的分析中，三根认知支柱 R1–R3 合计占全部命中的 **92.1%**。

## Main Contribution

把自主研究 agent 的评估从打分转向诊断：一套横跨生命周期的任务集、一份带根因归因的实证失效分类体系，以及一个经验证的评判器让轨迹级标注在成本上成立——由此得出的结论是，同样的失效模式在全部八种配置（含最强模型）中反复出现，这把缺口定位在模型层面，而非某个特定脚手架上。

## Key Design Ideas

- 任务按研究生命周期阶段而非能力项组织，因此一次失效可以归因到它发生在研究过程的哪一段。
- ARFT 的双轴结构把失效**发生在哪里**（阶段）与**为什么发生**（根因支柱）分开，并强制每种模式只归一根支柱，命中计数因而可解释。
- 评判器读的是完整轨迹与中间产物，而不是最终输出，这正是过程级归因得以成立的前提。
- 评判器校准对照人工标注，并设有同任务的 LLM-as-a-judge 对照组，因此「产物感知式评判带来多少增益」是分离出来的，而不是断言出来的。
- 任务集固定、只变换八种 harness–模型组合，这才使模型层面的结论成立：若缺口只属于某个脚手架，就不会在所有组合中同时出现。
- 论文标出了自身推断的边界，明确指出编排层面的干预能否弥合这道元认知缺口，是本工作没有测试的开放问题。

## Strengths

- 在这个规模上做到如此诊断深度并不常见：800 条完整标注、可见到产物层面的轨迹，而不是更大任务集上的汇总分数。
- 失效分类体系由观察到的轨迹归纳而来，而非事先设定，并且给出了各类别的规模。
- 评判器对照人类校准且设有对照条件，相对基线的召回增益被量化。
- 同时变换 harness 与模型、覆盖八种配置，支撑起一个单配置研究做不出的「缺口在哪一层」的判断。
- 作者直说自己的设计不能确立什么，把已支撑的模型层面归因与未测试的编排问题分得很清楚。
- 任务筛选从 5,878 个候选收敛到 100 个，保留下来的集合反映的是明示的筛选标准，而非就便取材。

## Limitations

- 尽管声明已公开发布，正文却没有仓库地址，工件目前无从定位（上文记为 `TODO(reference)`）。
- 分领域任务数没有给出数值，这既导致本工作无法进入任何领域页，也让「七个科学领域」的说法在细节上无法核验。
- 论文不报告比较性性能表，因此这项工作无法用于给系统排名——这是设计使然，但也限制了它作为排行榜复用的可能。
- ARFT 建立在八个系统之上，作者指出这些模式未必穷尽失效空间。
- 墙钟与 token 预算固定，意味着资源压力无法与失效成因分离开来。
- 作者说明，即便做了去标识处理，数据污染仍无法完全排除——这是所有建立在真实已发表科学之上的 benchmark 共有的风险。
- 评判器一致性只给了总体数值；作者说明分模式、分支柱的一致性目前尚未报告。

# DrafterBench (2025)

> [English](../../works/drafterbench.md) | **简体中文**

## Overview

DrafterBench 是一个开源 benchmark，考察 LLM agent 做土木工程施工图修改：以十二类修改任务和 46 个自制图纸操作工具构建出 1,920 道题，判分读的是记录下来的操作链，而不是渲染出来的图纸。

## Summary

作者走访了十余家北美建筑施工企业，据此认定图纸修改——用他们的话说——是「土木工程中最需要自动化、最耗人力也最缺技术含量的任务之一」，于是把它做成了一个 agent benchmark。任务取自设计院与施工企业提供的 100 多份真实修改文件，以自然语言修改指令的形式下达给模型，操作对象是 PDF 图纸中的文字、表格，以及线条、钢筋、柱子这类矢量图元。除普通的函数调用外，benchmark 还刻意考察两件事：agent 能否在指令不规整、含糊或信息不全时照样把活干完，以及它会不会自觉遵守指令中根本没写的制图惯例——论文称之为隐性惯例意识（implicit policy awareness），例如按公司命名规则保存修改后的文件。判分完全自动：一套镜像函数在不改动文件的前提下记录操作路径，因此比对的是 agent 的操作链与参考操作链，不必人眼去看渲染出的 PDF。

## Tasks

1,920 道题。十二个任务类型来自三类对象元素（文字、表格、矢量图元）与四种修改操作（添加内容、修改内容、位置映射、格式更新）的交叉——例如在目标区域添加文字、删除目标线条、替换或清空表格单元、更改文字颜色、字体与字号。每个任务类型再与五个二值指令控制变量交叉：语言风格规整/不规整、数值精确/含糊、信息完整/不完整、每条指令单对象/多对象、每个对象单操作/多操作，每种组合生成五道题（12 × 2^5 × 5 = 1,920）；第六个控制变量——函数流水线复杂度——则随任务类型而变。agent 可调用 46 个基于 PyMuPDF、Reportlab、OpenCV 与 pytesseract 实现的定制图纸修改函数。所有任务都经人工核验，确认其具有实际适用性。

## Domains

土木与结构工程：任务全集是土木工程施工图，以及设计院与施工企业在设计与施工两个阶段之间跑的那套图纸修改流程，图纸对象中包含钢筋、柱子等结构图元。未指派共同领域——该 benchmark 评的是文档层面的工程生产作业，而非对某个实体结构的分析。

## Evaluation

- 两级自动判分。第一级是代码可执行性，0 分或 30 分。第二级是六个子任务上的目标完成度，每个按 (TP − FP) / (TP + FN) 计算，折算到 70/6 分。执行计划另按 agent 记录的操作链与参考链的交并比打分。综合分取任务均分再减去一项针对薄弱子任务的惩罚，从而把各项都过硬的 agent 与偏科的 agent 区分开。
- 结果既给总分，也按各个指令控制变量分别报告——措辞规整与否、细节精确与否、指令完整与否、对象数与操作数的多寡。
- **报告（论文）。** OpenAI o1 平均分 81.92 / 综合分 79.90；Claude 3.5 Sonnet 76.27 / 73.79；DeepSeek-V3-685B 76.05 / 73.09；Qwen2.5-72B 74.77 / 72.05；ChatGPT-4o 74.49 / 71.76；Llama 3-70B 70.67 / 67.55。面对精确、完整的指令时，模型得分明显高于含糊或有错的指令。
- **报告（官方仓库排行榜）。** 论文发表后又补入了更新的模型：o3-2025 平均分 86.03，gpt-4.1-2025 80.16，o4-mini-2025 79.93。

## Main Contribution

一个把 LLM agent 放到真实土木工程作业上、而非合成工具使用场景中的 benchmark。它把性能拆解为作者认为这份工作真正需要的四项能力——结构化数据理解、函数执行、指令遵循，以及指令质量下降时的批判性推理——并且评测读的是操作链，判分无需人眼检视修改后的图纸。

## Key Design Ideas

- 镜像函数在不碰文件的前提下记录操作路径，被计分的对象因此是轨迹，而不是渲染出的 PDF。
- 指令质量是受控变量：含糊、缺信息、措辞不规整三者可独立开关，分数一旦下滑就能归因到某个具体的指令缺陷。
- 隐性惯例意识纳入计分——想把题做对，就得用上指令里从未言明的制图惯例。
- 工具集与任务生成器均开放且可扩展，使用者可以自行注册新的修改函数或任务类型。

## Strengths

- 任务源自北美设计与施工企业提供的 100 多份真实修改文件，并经人工核验。
- 判分确定且全自动，并按能力与控制变量分项给出，而不是一个通过率了事。
- MIT 许可，数据集公开，排行榜持续维护。

## Limitations

- 指令只规定改什么，没有任何一道题要求作出结构判断或规范符合性判断，因此土木工程知识主要以制图惯例的形式被考察，而非设计或校核。
- 含糊与信息不全这两种条件本身没有唯一确定的 ground truth，论文也指出推理模型有时会把含糊指令当成错误，而不是设法把含糊之处解决掉。
- Repository note: 图纸对象是 PDF 中的文字、表格与矢量图元，而非分析模型或 BIM 模型，因此该 benchmark 衡量的是文档层面的自动化，不是设计校核。
- Repository note: 论文未公开单任务的 token 或步数预算。

# SGR-BIM (2026)

> [English](../../works/sgr-bim.md) | **简体中文**

## Overview

SGR-BIM 是一个图驱动的多 agent 框架，用来对照 IFC 建筑模型核查几何密集型的建筑规范条文。随框架一同发布的还有一套专门构建的评测集：五个 IFC 模型上的 679 道经专家核验的消防合规查询，配一套四维评分细则；五个 agent 基线——含 CAMEL、MetaGPT 与 AutoGen——在完全相同的工具权限与推理设置下同台比较。

## Summary

自动合规审查早就能处理属性级的规则（「这面墙的材料是不是 X？」），一碰到几何密集型条文却卡住：要得出结论，得把好几条条文串起来推，还要在 IFC 实体之间来回穿行——比如判定疏散门所需净宽，先得推断建筑的使用性质分类，再查人员密度系数，把房间面积加总，最后才轮到比对某扇门的尺寸。论文认为静态规则模板表达不了这种多跳链条，于是提出 SGR-BIM：动态构建一张跨模态知识图谱，把用户意图、规范语义与 IFC 几何对齐到一起，再由五个 agent（意图、模型、规则、分析、响应）在这张共享图上协同推理。为了度量效果，作者构建了 679 道消防查询的评测集，标准答案由专家产出，所有系统都按一套三档准确率量表外加三个定性维度打分。SGR-BIM 的总体准确率达到 84.3%，同样拥有完整工具集的单 agent 为 75.7%，通用多 agent 框架则在 64.9%–73.2% 之间。

## Tasks

679 道题，源自基于 BIM 的设计审查场景，构建在五个按使用性质与规模挑选的 IFC 模型上：两栋多层住宅公寓楼、一栋宿舍、一栋商业办公楼和一座工业厂房。模型取自公开来源，再由一支三人 BIM 团队精修（三人 BIM 经验均在一年以上，其中一位是行业从业者）。出题采用半结构化流程：领域专家先逐个分析 IFC 模型，围绕关键的规范与几何推理难点写出种子问题，再由 LLM 扩写以增加覆盖面与多样性，最后由专家团队逐题人工审核确认。标准答案则完全由领域专家在联合分析规范条文与对应 BIM 模型后给出。题集分属两个工作流阶段、四个类别：设计阶段的 **Rule** 类问几何相关的规范条文（113 题，例如防火分区的最大允许面积），**Rule Requirement** 类问某个具体构件必须满足什么（189 题，例如规范对某扇门要求的净宽）；审查阶段的 **Model** 类从 IFC 模型中取几何或空间事实（240 题，例如某个房间位于哪一层），**Check** 类问某个构件是否合规（137 题，例如这部楼梯是否满足规范）。难度从三个维度刻画：Rule 类中有 79.65% 的查询需要同时解读两条及以上不同的规范条文；另外三类里几何计算占 53.97%–85.40%；而关联依赖（需要在两个及以上 IFC 实体间沿拓扑或逻辑链路导航）在 Rule Requirement、Model 与 Check 三类中分别达到 10.05%、40.00% 与 44.52%。查表操作在四类中都有出现，并且每个建筑模型的每个类别都设有 1–2 个条件例外，用来考察常规规则被取代的边界情形。

## Domains

土木与结构工程。受评目标是对照建筑规范条文对建筑做设计校核：防火分区面积、疏散路径与疏散距离、由使用性质分类与房间面积推出的容纳人数、楼梯与走道宽度、各类净空与疏散门尺寸，全部要对照 IFC 几何核查。按本领域的范围界定，这属于设计规范符合性与规范审查，也落在其 BIM/IFC 条款之下；受评任务是工程校核，而不是 BIM 建模，也不是以空间布局本身为目的的规划。论文出自 University of Hong Kong Department of Urban Planning and Design 与 HKUST Department of Civil and Environmental Engineering。评测不涉及结构分析、传力路径或构件设计，因此不指派机械与航空航天或材料科学作共同领域；这些任务是建筑规范校核，不是结构力学。

## Evaluation

评测定义了四个维度。**Accuracy** 是主指标，按三档量表打分：只有当回答既得出正确结论、又识别出全部起控制作用的规范变量以及具体情形下的边界条件时，才计 1（完全正确）；若识别对了规范机理或 IFC 实体，但结论不够精确、漏掉阈值或边界情形，则计 0.5（部分正确）；若结论与推理路径双双出错或属于幻觉，计 0。**Coherence**、**Relevance** 与 **Explainability & Reasoning** 三项按公开准则以 0–1 打分（不出现突兀的引用或裸露的 GUID、单位正确、直接作答不跑题、推理链透明且对例外情形有交代）。Accuracy 由人工评分；三个定性维度由一个独立的 LLM judge 产出（DeepSeek-3.2，判分 prompt 中抹去了系统名与基线名），再经人工检视核验；judge 与评审之间、或评审彼此之间出现分歧时，由各方协商达成共识后定论。所有系统在完全相同的工具权限与推理设置下运行，默认后端为 DeepSeek-3.2，temperature 取 0；整个实验只跑一遍，理由是解码确定，且 679 题的标注成本高。基线刻意排成一条能力阶梯：Basic-tool Agent（只有规范文本与 BIM 属性检索）、Enhanced-tool Agent（SGR-BIM 所用的完整领域工具集，用于把工具可用性与协同机制分离开），以及 CAMEL、MetaGPT 和 AutoGen 三个多 agent 框架。总体平均分：SGR-BIM 84.3，Enhanced-tool Agent 75.7，CAMEL 73.2，AutoGen 70.2，MetaGPT 64.9，Basic-tool Agent 19.1；分类别看，SGR-BIM 在 Rule、Rule Requirement、Model 与 Check 上分别为 90.7、78.6、87.9 与 80.7。基于逐题结果的 Tukey HSD 两两检验显示，SGR-BIM 显著优于每一个基线，包括 Enhanced-tool Agent（+0.0862，p = 0.0008）；而 CAMEL 与 AutoGen 相对 Enhanced-tool Agent 没有显著差异。定性维度上，SGR-BIM 总体的 coherence 为 93.7、relevance 98.4、explainability 99.3，Enhanced-tool Agent 对应为 79.2 / 96.7 / 70.4。对 135 条未拿满分的回答（占题集 19.9%）作误差分析，失败归为五类：回答不完整（42.2%）、推理与推断出错（24.4%）、对模型或规范信息理解不足（14.8%）、工具或系统层面的故障（14.8%）、误解用户意图（3.7%）。另有一项后端替换研究在子样本上用 GPT-4o 重跑 SGR-BIM，同一子样本上总体得 74.2，而 DeepSeek-3.2 为 87.6，差距最大的是几何密集的 Check（51.7 对 85.0）与 Rule Requirement（57 对 76.7）两类。

## Main Contribution

作者把 SGR-BIM 定位为一种面向自动合规审查的图式语义推理范式：用一张在查询时动态构建的跨模态知识图谱取代僵硬的规则模板，把用户意图、规范语义与 IFC 几何对齐，使多跳的几何规则链条得以走通，推理过程也可供检视。随附的实证主张是，弥合差距的并不是笼统的多 agent 协作——通用框架（CAMEL、AutoGen）在统计上与一个工具齐备的单 agent 无从区分，只有显式的跨模态对齐才带来显著提升。

## Key Design Ideas

- 跨模态知识图谱在查询时才构建，把自然语言的用户意图、叙述性与表格化的规范条文以及 IFC 实体统一到同一个推理空间，而不是把规则预先编译成固定模板。
- 五个角色化 agent（意图、模型、规则、分析、响应）在共享图上协作，中间的实体关联对每个角色都可见。
- 检索工具是确定性的：规范查询与 IFC 几何查询都封装成对预处理数据源的普通函数，刻意不用 RAG 与 SPARQL，以保证测出的差异反映的是推理与对齐能力，而非检索质量。
- 基线阶梯的设计目的是拆开三份互不相同的贡献——工具可用性、多 agent 协同、跨模态对齐——而不是给出一个笼统的对比结论。
- 三档准确率量表对那些结论正确、却没能指出控制变量与边界条件的回答不给满分，从而把碰巧答对或浅层答对与真正的规范理解区分开。
- 题目难度用显式的结构属性刻画（涉及几条规范来源、是否需要几何计算、有无关联依赖），并且每个模型的每个类别都埋了 1–2 个条件例外，制造出默认规则被取代的边界情形。
- 评分通道分开：Accuracy 由人工评分，定性维度由 LLM judge 在系统身份匿名的条件下判分，再经人工复核。

## Strengths

- 评测集扎根于五个不同建筑类型的真实 IFC 模型，标准答案由专家撰写，因此答案取决于模型的实际几何，而非对规范条文的记忆。
- 基线中含三个独立发表的多 agent 框架，且工具权限与后端完全一致，这比只做自家系统的消融更有说服力。
- 用 Tukey HSD 对逐题结果检验显著性，并且论文如实交代了哪些差异**并不**显著，包括其中两个多 agent 对照。
- 误差分类是在全部未满分回答上算出来的，而非手挑样本，并按题目类别分别拆解。
- 后端替换研究把框架的贡献与底层模型的贡献分开，显示绝对准确率虽有变化，排序依然保持。

## Limitations

- 源代码与题目数据集均未发布：数据可用性声明称两者「将在合理请求下提供」，因此这 679 道题目前无法作为公开 benchmark 使用。
- 整个评测只在 temperature 0 下跑了一次，理由是解码确定且标注成本高；论文未给出跨轮次的方差估计。
- 作者自己指出，工具齐备的单 agent 已能应付 75% 以上的查询，因此该框架的优势集中在较难的题目上，在简单题上收益递减。
- 检索被刻意简化——对预处理数据源作确定性函数调用，而非 RAG 或 SPARQL——因此结果并不能说明在规范文本与 IFC 数据杂乱、未建索引时的端到端表现。
- 面对大型高密度 IFC 模型（高层医疗建筑、复杂工业厂房）的可扩展性未经检验；作者预期图对齐的搜索空间与协同所需的记忆都会非线性增长。
- Repository note: 论文只把验证领域笼统描述为「消防规范」，既未点明适用法域，也未指明条文取自哪一部具体规范文件，因此标准答案的规范依据无法独立核查。TODO(reference)
- Repository note: 这个 benchmark 没有名字，且内嵌在一篇框架论文里——评测集是为验证 SGR-BIM 而构建的，四个题目类别中有两个（Rule、Model）考的是规范查阅与 IFC 事实检索，而非合规结论，因此真正构成端到端工程校核任务的只有 137 道 Check 题，外加部分 189 道 Rule Requirement 题。
- Repository note: 三个定性维度只报告了 SGR-BIM 与 Enhanced-tool Agent 的结果，未涵盖那三个多 agent 基线，因此 coherence 与 explainability 的对比范围比准确率对比要窄。

## Related Works

- [StructureClaw](./structureclaw.md) — 同样给规范校核打分的结构工程 agent benchmark，但走的是求解器执行与严格工件匹配，而非专家评分。

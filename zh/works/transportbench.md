# TransportBench (2024)

> [English](../../works/transportbench.md) | **简体中文**

## Overview

TransportBench 是一个含 140 道本科交通工程题目的数据集，题目取自 University of Illinois 的两门土木工程课程，配以人类专家评分，用于测量七个商业与开放权重 LLM 的准确率、答案一致性与推理行为。

## Summary

论文要问的是：面对本科交通工程课程所教的规划、设计、管理与控制问题，现有 LLM 能走多远——并且把这当作一个测量问题来处理，而不是一次应用演示。题目取自 UIUC 反复开设的两门课程，改写成纯文本形式，由七个模型零样本作答，再交人类领域专家核对。除单次作答准确率之外，研究还加了两个维度：一是答案一致性，既看重复试验之间是否一致，也看在「请仔细检查你的解答」这一追问下是否一致；二是对错误答案与正确答案背后推理链的定性分析。作者报告，得分最高的模型也只做对了约三分之二的题目，而且准确率与一致性并不同步——最准的那个模型，恰恰也最容易被说服而放弃正确答案。

## Tasks

140 道题分两种形式：73 道判断题，其余为一般开放式问答。论文报告的分主题构成为：事实 22 道、交通经济 5 道、驾驶员特性 5 道、车辆运动 11 道、几何设计 10 道、交通流与控制 15 道、交通规划 8 道、效用与方式划分 6 道、交通网络 3 道、公共交通系统 55 道。题目来自作者之一在 University of Illinois Urbana-Champaign 讲授的两门课程——CEE 310（交通工程导论，三年级课程，已开设 14 次）与 CEE 418（公共交通系统，四年级课程，已开设 11 次），其中 CEE 418 的许多题目源自该教师参与编写的教材。原题中的图一律换成文字描述，因此发布的题集是纯文本的，无需多模态输入。

## Domains

土木与结构工程：题材是设在土木工程系内讲授的交通系统工程，题目关心的是实体交通基础设施及其运行——公路几何设计、车辆运动与制动/滚动阻力力学、交通流与控制、交通网络分析、交通规划与方式划分，以及公共交通系统设计。没有其他标准领域构成实质成分；公交规划与方式划分类题目倚重运筹学式的建模，但每道题的对象始终是一项交通设施或服务，因此在领域归类上划入土木/基础设施工程，而非另立一个领域。

## Evaluation

模型回答通过各模型的网页界面零样本收集，正确性由领域专家人工标注判定，专家同时审查最终答案与所给出的推理。140 道题的总体准确率以答对题数报告：Claude 3.5 Sonnet 67.1%（94/140）、Gemini 1.5 Pro 63.6%（89/140）、GPT-4o 60.0%（84/140）、Claude 3 Opus 59.3%（83/140）、GPT-4 55.0%（77/140）、Llama 3.1 55.0%（77/140）、Llama 3 42.1%（59/140）。另有一项一致性研究，对 73 道判断题各做五次独立试验，报告 Mixed Response Rate——即模型未能每次都给出同一答案的题目占比。Claude 3.5 Sonnet 的判断题准确率最高（75.6%），mixed-response rate 最低（8.2%）；GPT-4 与 GPT-4o 的零样本 mixed-response rate 则高得多（23.3%）。第二套自检式一致性协议会再次提示模型、要求它检查自己的解答：Claude 3.5 Sonnet 把 16 道原本答对的题改成了错的，GPT-4 与 GPT-4o 只改错 4–6 道；作者据此论证零样本一致性与自检一致性是两种不同的性质。推理分析是定性的，识别出若干反复出现的行为，包括推理有误却得出正确结论（例如用一个忽略车辆周转的稳态论证去算公交车队规模）、对是否要求先给推理再下结论颇为敏感，以及一些细微的概念混淆，如空间车头间距与时间车头间距、调和平均车速与算术平均车速，以及忽略随速度变化的滚动阻力。

## Typical Duration

N/A — 题目为单轮问答，没有交互式环境或工具使用；论文未报告任何单题 wall-clock 时间、轨迹长度或 token 预算。唯一说明的重复次数预算，是一致性研究中每道判断题五次独立试验。

## Main Contribution

作者把 TransportBench 定位为首个专门为测试 LLM 交通系统工程能力而编制的 benchmark 数据集，并把贡献表述为准确率、一致性与推理行为三部分构成的评测，而非单一的排行榜数字。他们着重强调的发现是：模型的总体准确率并不能预测其行为稳定性——Claude 3.5 Sonnet 表现得最为鲜明，它准确率同类最佳，却极易在被要求复核时放弃正确答案。

## Key Design Ideas

- 题目取自长期开设的大学课程（分别开过 14 次与 11 次），而非为 benchmark 现编，难度因此以真实的本科课业为标尺。
- 两种答题形式刻意分开：判断题便于低成本地做重复试验、测量一致性；开放式问答则迫使模型给出完整的解题过程。
- 图形换成文字描述，使 benchmark 成为纯语言推理测试，排除读图能力这一混淆因素。
- 由人类专家对答案与推理一并评分，而不用自动字符串匹配或 LLM-as-judge。
- 一致性用两种不同方式衡量——重复独立采样（Mixed Response Rate）与自检追问下的答案稳定性——论文表明二者不可互换。
- 推理行为分析与准确率并列报告，包括正确答案出自错误推理的情形。

## Strengths

- 十个带标签的主题类别，使人能看出模型在课程的哪些部分失手，而不是只得到一个总分。
- 由人类领域专家评分，而 benchmark 规模（140 题）小到足以支撑这种做法，从而避开 judge 模型的偏差。
- 自检协议探到了单次准确率看不见的一种失效模式——在普通的人类追问下退化——并由此得出一份与准确率表格相反的具体排名。
- 题面、答案与评测材料在 GitHub 与 Hugging Face 上公开发布，并配有项目页。
- 错误分析点名了具体的领域混淆（空间与时间车头间距、调和与算术平均车速、随速度变化的滚动阻力），而不是笼统地说「推理错误」。

## Limitations

- 作者指出题集只覆盖本科层次，因此可能低估模型在研究生或职业交通工程工作上的差距；开放式题目的单次试验准确率也带有采样随机性。
- 主题覆盖严重不均：公共交通系统一项就占了 140 题中的 55 题，交通网络却只有 3 题，总分因此被一门课的内容主导。
- Repository note: 这是一个静态的文本问答 benchmark，不是 agent 评测——回路中没有工具调用、代码执行、交通仿真器或设计软件；作者把由外部编程与仿真平台支撑的工具型 LLM agent 列为未来工作，而非本 benchmark 的组成部分。
- Repository note: 用文字描述替换图形，抹去了几何设计与网络类题目中固有的读图环节，因此分数与同样的题目出给学生时的情形并不直接可比。
- Repository note: 回答通过各模型的公开网页界面收集，temperature 等解码设置未加说明，结果也绑定在 2024 年中期可用的模型快照上。TODO(reference)

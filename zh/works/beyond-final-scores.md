# Beyond Final Scores (2026)

> [English](../../works/beyond-final-scores.md) | **简体中文**

> **首次公开：** 2026-08-13 · **来源：** [arXiv 首次提交](https://arxiv.org/abs/2608.13417)

## Overview

在 36 个长时程 AI 研发任务上对七个前沿模型做的一次系统评估，出发点是：最终分数既看不出进展在哪里得到、又在哪里丢掉，也说不清积累下来的经验有没有改善后续决策。工作贡献了一套刻画运行内行为的确定性规则化过程指标，以及一组把任务内与跨任务的经验复用单独隔离出来的受控反事实实验。

## Summary

任务取自 AutoLab：每个任务提供一个目标、一份正确但刻意做得不够好的起始工件、一份专家撰写的参考解、一个墙钟预算和一个自动验证器，agent 要做的是把工件反复改好。作者在这个底座上搭了两件工具。其一是三组规则化指标，全部由验证器结果与记录下来的轨迹信号确定性地算出，不经 LLM 判定，用来刻画 agent 如何构思方案、能否可靠地把方案落地、以及如何应对反馈。其二是一对关于经验的反事实实验：在运行内部，于中途某个分叉点抹掉 agent 累积的上下文而保留其解，再把分叉后的第一次提交与未抹除的分支对比；在运行之间，把从已解决源任务中提炼的经验，在留出目标任务上给或不给。结论是当前 agent 更像工程优化器而非自主研究者——擅长构思并实现可行方案，但跨轮次波动很大，最强的解多半是在改造或组合既有技术，真正的方法学新意极为罕见。

## Tasks

**取自 AutoLab 的 36 个任务**，分四族：**模型开发（7）**、**系统优化（15）**、**谜题与挑战（10）**、**CUDA（4）**。每个任务提供目标、一份正确但不够好的起始工件、一份专家参考解、一个自动验证器，以及 **2–12 小时**的墙钟预算。分数归一化到 **[0, 1]**，每个受评检查点都可获得验证器反馈。评测总量为 **756 条 rollout**（36 任务 × 7 模型 × 3 轮）。

## Domains

**AI & Machine Learning Research。** 任务族分别是模型开发、系统优化、CUDA 内核工作与算法挑战——被改进的工件是机器学习模型或围绕它的系统代码，验证器度量的是其性能。不指派科学类共同领域：这项工作评估的是在 AI 工件上的研发能力，而不是任何自然科学问题。

## Evaluation

总体表现以 **avg@3 / best@3** 报告：Opus-4.7 **0.739 / 0.790**，GLM-5.2 **0.682 / 0.757**，GPT-5.5 **0.663 / 0.772**，Gemini-3.1-Pro **0.652 / 0.750**，Kimi-K2.7-Code **0.587 / 0.729**，LongCat-2.0 **0.572 / 0.674**，DeepSeek-V4-Pro **0.502 / 0.668**。七个模型于 2026 年 6–7 月通过当时可用的厂商 API 评测。关于可靠性的发现直接落在这两列上：最强与最弱之间的差距在 **avg@3 上是 0.237，在 best@3 上只有 0.122**，可见相当一部分表面上的能力差异其实是跨轮次波动，而非天花板之别。

三组确定性指标刻画运行内的行为。**C1 方案构思**以运行至今的最佳验证器分数为代理，衡量所选方向能否很快抵达一个好的解，并映射到共同时程上，使高度与「早」同时被奖励，后续失败也无法抹掉此前的发现。**C2 执行**先检查工件能否跑通且正确，再按此前与代码相关的构建失败次数对成功交付作有界折扣。**C3 反馈控制**把保持度（终末分数与最高步分数之比）与恢复度（恢复幅度与转折次数）合起来，并对隐藏的试错加以惩罚。Opus-4.7 在这三项上的读数为 **0.612 / 0.967 / 0.920**。

经验复用以反事实方式测量。**任务内**：在运行中途的分叉点抹掉累积的上下文、磁盘笔记与代码注释而保留解，再比较分叉后的第一次提交。任务内经验总体上有帮助，平均增益从 **+0.0362（Opus-4.7）到 +0.1454（LongCat-2.0）**——越弱的模型越依赖它。**跨任务**：从四个已解决的源任务（每族一个）提炼经验，在 **19 个目标任务上给或不给，最终保留 32 组用于分析**。这里初始表现并不预示改进幅度：基线最弱的 **DeepSeek-V4-Pro 收益最大（+0.093 avg@3）**，而较强的 **Gemini-3.1-Pro 反而下滑（−0.017 avg@3）**，且自生成的经验优于跨模型迁移。

另有两项发现关乎效度：经人工复核，只有 **3 个解（1.2%）**保有真正的新意，而 **16 个（6.3%）**利用了评测特有的捷径。更换 harness 使 avg@3 提高 **0.019–0.055**，但对任何模型的 best@3 最多只移动 **0.035**。

## Typical Duration

**每个任务 2–12 小时墙钟时间**，沿用 AutoLab 的设定。各模型每任务的平均推理开销相差约一个数量级：**Opus 89.9 美元**、**GLM-5.2 33.0 美元**、**GPT-5.5 16.5 美元**、**DeepSeek-V4-Pro 4.3 美元**、**LongCat-2.0 3.9 美元**。整场评测的模型推理开销约为 **十万美元**。CUDA 任务平均而言最耗 token。

## Main Contribution

一套面向长时程 agent 运行的过程指标，全部由验证器结果与轨迹信号确定性算出而不依赖评判器，配上抹除式反事实实验把「经验有没有用」变成一个可测量的量——由此得出两个结论：最强与最弱模型的差距从 avg@3 换成 best@3 就缩掉一半；以及模型的基线强弱并不预示它能从经验中获益多少。

## Key Design Ideas

- 每个过程指标都从验证器结果与记录下来的执行信号算出，因此「评估的评估」不依赖 LLM 评判器。
- C1 把运行至今的最佳分数映射到共同时程，奖励的是**早**抵达好解，而不只是抵达。
- C2 按此前的构建失败次数对成功交付作折扣，一个经由大量破损中间状态才走到终点的 agent，不会被记作与不曾破损的 agent 等同。
- C3 把保持度与恢复度分开，从而区分「弄丢了自己最好成果」的 agent 与「受挫后又找回来」的 agent。
- 任务内经验的测法是在分叉点抹上下文而保留解——这把积累下来的知识与积累下来的进展分开了，简单的有无记忆对比则会把两者混作一谈。
- avg@3 与 best@3 并列报告，使跨轮次波动成为一等结果，而不是被平均掉的噪声。
- 对得分最高的解做人工复核，检查高分反映的是新意还是捷径，等于对 benchmark 自身的构念效度做了一次审计。

## Strengths

- 确定性的过程指标具备基于评判器的过程打分所没有的可复现性，而论文也明说它们是代理量而非穷尽的定义。
- avg@3 与 best@3 的对照是一个真正吃重的结果：它把模型排名中的很大一块重新解释为可靠性而非能力。
- 反事实抹除设计直接隔离出经验复用，而不是从跨轮次的相关性里去推断。
- 新意审计（1.2% 真正新颖、6.3% 利用捷径）是一个不利于自家头条分数的发现，而论文照实报告。
- 逐模型的推理成本列表在案，Opus 与 LongCat 之间约 20 倍的成本差距因而与性能差距并置可见。
- harness 效应单独测量，结果显示 harness 的选择对 avg@3 的影响大于对 best@3 的影响——这与可靠性的解释相互印证。

## Limitations

- 论文未说明评估框架与任务集的发布位置，因此指标与任务目前都无法复用（上文记为 `TODO(reference)`）。
- C1–C3 被明确定位为基于验证器分数与执行信号的代理量，捕捉不到未实现的想法或潜在的推理过程；当一条轨迹几乎没有回退时，C3 的恢复项也难以确定。
- 经验复用的估计取决于所选的抹除点、所选的源—目标配对，以及被迁移经验的表示方式，并不涵盖更长部署中会出现的全部积累机制。
- 结论绑定在 AutoLab 的任务分布、预算、验证器与执行环境上，且共用 Claude Code harness；作者说明换一套设置后绝对分数与部分相对排名都可能改变。
- 成本数字取决于评测当时的厂商定价与 token 计费方式，并非稳定量。
- Repository note: 任务集是 AutoLab 的，不是本文的。本卡片记录的贡献是搭在其之上的那套测量框架。

## Related Works

- [AutoResearchEval](./autoresearcheval.md) — 把同样「不能只看最终分数」的论证用在端到端研究上，靠一个经校准的 agent-as-a-judge 读轨迹，而本工作用的是确定性规则。
- [MLE-bench](./mle-bench.md) — 预算约束下的机器学习工程，只按最终排行榜名次打分，不作过程分解。
- [AutoWorldModel-Bench](./autoworldmodel-bench.md) — 同样在固定算力预算下让 agent 改进一份给定工件，领域是世界模型，也同样审计胜出的改动是实质性的还是调参。
- [CostBench](./costbench.md) — 预算感知的 agent 评估，成本直接计入分数，而非并列报告。
- [R³-Bench](./r3-bench.md) — 同样把「已展示的能力」与「资源压力下真正兑现的表现」分开，用的是跨题目共享预算而非 avg@3 与 best@3。

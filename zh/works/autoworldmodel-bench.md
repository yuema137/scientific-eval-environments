# AutoWorldModel-Bench (2026)

> [English](../../works/autoworldmodel-bench.md) | **简体中文**

## Overview

AutoWorldModel-Bench 是一个闭环 benchmark：交给前沿编码 agent 一个能用的世界模型和一份固定算力预算，让它把模型改好，而改进方向事先并不指定。八个游戏环境共用一套结构化状态表示，把感知整个剥离出去，从而单独隔离出动力学建模，也让每次训练短到足以在一个会话内反复迭代。

## Summary

作者的论点是：世界建模恰恰因为悬而未决，才是自主研究的好试验场——架构、训练目标与状态表示之间相互影响的方式很复杂，跨环境也没有哪一套配方占优，于是根本无「规格」可写。这一点把它与当前 agent benchmark 中占主导的「照规格施工」任务区分开来。benchmark 提供一份单文件的基础世界模型——四种架构之一——让 agent 自行决定怎么改进：动架构、动损失、动超参，或动训练流程都可以。八个游戏都通过共享张量格式暴露真值实体状态，agent 因此从不面对像素，被测的量就是已知实体上的转移建模。运行时间刻意压得很短，使会话预算内能做到分钟级的迭代。除了总体改进率之外，论文还审计了每个会话里**赢在哪种改动**上，发现绝大多数会话中胜出的改动是实质性的，而非调参。

## Tasks

**八个游戏环境**——Snake、Frogger、Pong、Breakout、Asteroids、Platformer、Kong、Racer——统一采用实体—组件—系统（ECS）快照表示。每一帧包含实体注册表（**N × 34** 维）、实体状态（**N × 23**）、玩家动作（**7 维**）、游戏状态（**17 维**）与终止标志。

提供的基础模型是四种单文件、可由 agent 修改的架构之一：**RSSM/Dreamer、AR-Transformer、D3PM、MaskGIT**。agent 的任务是在固定算力预算下自主改进该基础模型，架构、损失、超参与训练流程都可动。完整网格为 **64 个会话**——2 个 agent × 8 个游戏 × 4 个基础模型。

## Domains

**AI & Machine Learning Research。** 被评估的对象是一个学习得到的世界模型，agent 所做的是机器学习研究——改架构、改损失、改训练流程，再由留出集上的预测精度来衡量。游戏环境只是产生动力学的载体，本身并非研究对象，因此不指派其他规范领域。

## Evaluation

测试指标是 **Position L1**（可变实体位置）与 **Alive F1** 的组合，在 **h ∈ {1, 10, 20}** 三个时程上评估，按 **0.1 · composite₁ + 0.2 · composite₁₀ + 0.7 · composite₂₀** 合成——长时程 rollout 保真度的权重最高。Δ 定义为**留出测试集**上该会话相对基础模型的最好提升。

**64 个会话**中，Codex-5.4 与 Claude Opus 4.6 只有一个会话没有超过基础模型。**64 个中有 33 个**取得显著提升（**Δ ≥ +0.10**），其余提升较小但为正。测试分平均提升 **+0.196**，中位数 **+0.115**。在另一套场景测试集上，**64 个会话中有 56 个**取得提升，平均 **+0.170**。增益集中在长时程——h₁₀ 平均 **+0.205**、h₂₀ 平均 **+0.215**，而 h₁ 只有 **+0.056**。

两个 agent 的正面对决为 **19–13，Codex-5.4 领先**，论文报告这一差异不具统计显著性（**Wilcoxon p = 0.15**）。

一项改动类型审计发现，**91% 的会话**中胜出的改动是对模型或训练的实质性修改，而不是调超参。

## Typical Duration

**单张 H100 上 6 小时一个会话**，且**每次单独训练限时 10 分钟墙钟**。正是这个很短的单次上限，使会话预算内能做到分钟级迭代。

## Main Contribution

一个刻意不指定改进方向的开放式研究 benchmark；把感知从问题中移除、并把单次训练卡在十分钟以内，使它在工程上可行——外加那项审计结果：91% 的会话中胜出的改动是实质性修改而非调参，这是论文用以论证 agent 在做研究而非在做搜索的证据。

## Key Design Ideas

- 任务由目标而非规格定义，作者正是用这一性质把它与「照规格施工」类 agent benchmark 区分开。
- 来自游戏引擎的真值结构化状态彻底移除了感知，失效因而可归因于动力学建模，而不是表示学习。
- 限制的是**每次训练 10 分钟**而非训练次数，这把算力预算转换成迭代次数，奖励肯多验证几个假设的 agent。
- 每个游戏配四种不同的基础架构，避免 benchmark 变成「擅不擅长改进某一个模型家族」的测试。
- 组合指标给 20 步时程 0.7 的权重，增益必须来自 rollout 保真度，而不能来自若干基础模型本就做得不错的单步预测。
- 审计胜出的改动究竟是实质性修改还是调参，是对 benchmark 自身「测的是研究而非调优」这一主张的直接检验。
- 另设一套场景测试集，为同一批改进提供了第二次、构造方式不同的测量。

## Strengths

- 评分对照留出集全自动完成，回路中没有评判器。
- 改动类型审计检验而非假定论文的核心主张，并给出了具体比例（91%）。
- 移除感知是一次有意的收窄，让被测量的量变得干净，而作者也明确说明了这一选择的代价。
- 汇总值（64 个中 33 个达到 Δ ≥ +0.10）与分布（均值 +0.196、中位数 +0.115）同时报告，偏斜因而可见。
- 两个 agent 的对决连同显著性检验一并给出，并正确地描述为不具结论性，而非当作排名呈现。
- 分时程拆解显示增益来自何处，h₁ 与 h₂₀ 之间的不对称因而一目了然。

## Limitations

- 作者指出比较同时涵盖模型与 harness，因此并不能单独隔离模型质量。
- 来自游戏引擎的显式结构化状态，把 benchmark 限定在已知实体上的转移建模，而且状态是精确的——没有传感器噪声、缺失值或测量误差。
- 许多基础模型的单步预测本就很强，headroom 从构造上就集中在长时程。
- 单元格层面的提升幅度对随机种子敏感，作者报告部分单元格（尤其是较强的基础模型）幅度存在波动。
- 环境是游戏而非科学系统，所建模的动力学是人为编写的，而非自然产生的。
- CC BY-NC-ND 许可禁止商用且不允许演绎，相比宽松许可的 benchmark 限制了复用。

# AFMBench (2025)

## Overview

AFMBench 是一个含 100 个由专家整理任务的评测套件，要求 LLM agent 操作一台真实的原子力显微镜而非仿真器，覆盖从实验设计到结果分析的完整流程。此处收录的是 AFMBench，即该论文的**评测**贡献；与之配套的 AILA 框架属于 agent 实现工作，与本仓库的评测重心相邻（见 Limitations 下的 repository note）。

## Summary

作者指出，领域问答 benchmark 无法确立一个模型是否能操作实验仪器，而基于仿真的评估又抹去了真实硬件的时间约束与实验变异性。因此 AFMBench 要求 agent 在一台经由 Python API 访问的 Nanosurf DriveAFM 上物理执行，把四个可互换的 LLM 装进同一个固定框架，每个任务运行三次。头号结果印证了作者的担忧：在材料科学问答上表现强劲的 Claude-3.5-Sonnet 在此处的错误率为 51.6%，而最佳模型的总体任务完成率为 65%，在把文档记录与分析合并的任务上则跌至 23.3%。

## Tasks

100 个由专家整理的实验任务，沿四条相互独立的轴分层：工具协同（69% 需要多个工具，31% 为单工具）、agent 需求（83% 单 agent，17% 多 agent）、复杂度（56% 基础操作，44% 进阶流程）与功能领域（50 个文档记录任务、14 个分析任务、10 个计算任务，其余为跨领域整合任务）。任务内容涵盖显微镜校准、特征检测、力学性能测量、石墨烯层数计数与压头检测。

## Domains

材料的扫描探针显微术——操作原子力显微镜进行成像、力学表征与图像分析。

## Evaluation

- **在真实硬件上物理执行。** 任务在一台经由 Python API 访问的 Nanosurf DriveAFM 上完成；论文将此与常规 LLM benchmark 及基于仿真的评估区分开，理由是硬件会引入真实的时间约束与实验变异性。
- **任务完成率**，按功能领域分别报告，并单列合并的跨领域任务，每个「模型—任务」对独立运行三次。
- **一套命名的失败分类。** 错误被划分为 sleepwalking（执行超出既定指令的未授权动作）、代码生成错误、agent 选择错误、工具选择错误，以及超出既定操作限制的指令遵循失败。
- **与成功率并列报告的运行指标。** AFM handler 与 data handler 调用次数、步数、总/prompt/completion token、各阶段 token、延迟、每步耗时，以及每千 token 的延迟。
- **报告结果。** GPT-4o 以 65% 的总体任务完成率与 29% 的错误率领先——文档记录 88.3%、计算 56.7%、分析 33.3%，而在文档记录与分析合并的任务上跌至 23.3%。GPT-3.5-turbo-0125 总体为 32.8%、错误率 66.6%，数学运算仅 3.3%；Claude-3.5-Sonnet-20241022 在独立的文档记录任务上为 85.3%，但错误率达 51.6%，平均响应时间最高（17.31 秒），且在涉及 data handler agent 的三次试验中全部失败；Llama-3.3-70B-versatile 错误率 60.6%，其中代码生成错误占 32%。作者另报告多 agent 配置优于单 agent 配置，且两者都对 prompt 变化敏感。

## Typical Duration

未施加每任务的步数、token 或 wall-clock 预算。论文转而把开销作为结果报告：每任务平均步数从 GPT-4o 的 6 步到 Llama-3.3-70B 的 10 步，平均响应时间从 Llama-3.3-70B 的 7 秒到 Claude-3.5-Sonnet 的 17.31 秒。由于任务在仪器上执行，所耗时间反映的是物理操作而非仅推理。

## Main Contribution

一个把 LLM agent 置于真实扫描探针显微镜上物理执行、覆盖完整实验流程的评测套件，并配以一套面向实验室场景的失败分类——在该场景中，超出指令本身就是一个独立且后果严重的错误类别。

## Key Design Ideas

- 把在仪器上物理执行作为硬性要求而非用仿真替代，使时间约束与实验变异性成为该 benchmark 所测量内容的一部分。
- 任务构成沿四条正交轴分层——工具数、agent 数、复杂度与功能领域——使一次失败可归因到具体某个维度，而非笼统归因于任务难度。
- 合并的跨领域任务与其单领域成分分开报告，从而单独暴露出被各领域通过率所掩盖的组合代价。
- 把过度执行作为一等失败模式并命名为 sleepwalking，其理由是：agent 在执行机构上越出指令属于安全问题，而不只是打分上的麻烦。

## Strengths

- 该设计直接检验了一个领域内通常默认成立的主张：论文表明材料科学问答的能力并不迁移到操作仪器上，并以 Claude-3.5-Sonnet 作为具体反例。
- 报告一套错误分类而非单一成功率，使「因写出错误代码而失败」的模型与「因选错 agent 或工具而失败」的模型得以区分。
- 每个模型的运行开销以步数、token 与延迟报告，因此能力与代价同时可见，无需另做一项研究。

## Limitations

- Repository note: 该论文的另一项贡献是 AILA，一个用于自动化原子力显微术的 LLM 驱动框架——属于 agent 实现工作，位于本仓库以评测为中心的范围之外。此处收录的是 AFMBench 这一评测套件；框架本身不是收录理由。
- Repository note: 评测在单一实验室的单台仪器上以每任务三次试验完成，因此所报告的比率在没有该硬件的情况下无法复现，而物理执行也限制了可承担的统计功效。论文未给出判定任务成功的准则，因此「什么算完成一个任务」无法从已报告的材料中复原。

## Related Works

- [Terminal-Bench Science](./terminal-bench-science.md) — 同样以执行而非答案匹配为科学工作流打分，但它在容器内用 pytest 做确定性验证，而 AFMBench 的结果取决于一台仪器，因此并非确定性的。
- [ScienceAgentBench](./scienceagentbench.md) — 同样从真实科学实践中取任务并通过运行 agent 的产出来评分，但其任务最终归结为自包含的 Python 程序，因此没有任何物理环节被调用。
- [Aviary](./aviary.md) — 同样提供带实验室色彩的科学环境，包括分子克隆与蛋白质工程，但那些环境是计算性的评估面，而非一台受控的物理仪器。

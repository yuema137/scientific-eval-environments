## Overview

一个受控 benchmark，测试 agent 执行遥测是否*足以*诊断失败的起源；它在合成的多组件 agent 轨迹上，把三种能力区分开来——失败检测、故障源定位，以及在证据不足时安全弃权。

## Summary

TelemetrySuffBench 认为：能揭示 agent *是否*失败的遥测，未必足以识别失败*从何处*起源。它构造带延迟绑定故障的规范化多组件 agent 轨迹（注入的故障在其引入位置之后才激活），并在受控可观测性条件下渲染每条轨迹：成对的粗粒度视图、七因子遥测掩码，以及完全相同的歧义起点对。作者在统一协议下评估了五个前沿语言模型，配备显式候选集、无效输出计入、子群分析与一份冻结的盲留出集。核心发现是一个检测–定位落差：被掩蔽的遥测视图仍保持近乎完美的失败检测，却使起源步骤定位崩塌。

## Tasks

带程序化注入之延迟绑定故障的合成多组件执行轨迹。论文报告一个由 312 条轨迹组成的语料，分为发现切分（96 条）与确认切分（216 条），并用一份冻结的盲留出集复现核心模式。故障轨迹被组织为成对的两起源故障组（完全相同的歧义起点对），另有洁净的对照轨迹。`TODO(reference)` —— 在此处可获得的抽取层面上，留出集的确切构成以及各切分中故障/洁净轨迹的精确数量，无法从一手来源明确对齐。

每条轨迹在三族可观测性条件下呈现：

- **成对的粗粒度视图**——元数据、OpenTelemetry 兼容与 OpenInference 兼容三种渲染。
- **七因子遥测掩码**——对单个遥测因子的受控移除。
- **完全相同的歧义起点对**——两个候选起源无法区分的输入，用于测试弃权。

## Evaluation

程序化标准真值：钩子记录注入的起源、参考激活、首个可见的错误目标事件、状态更新症状与终态失败，存放在模型不可见的轨迹之外。只有当定位答案同时匹配注入的组件与事件标识时才算正确。所报告指标包括：

- **起源步骤 Top-1 准确率**（故障定位）。
- **检测 F1** 与**故障类型 Macro-F1**（失败检测）。
- **误答率（FAR）** 与**不必要弃权率（UAR）**（弃权研究问题），并以有效唯一起源答案的占比衡量覆盖率。
- **无效输出计入：** 畸形、不一致、超出候选集与超出分类法的输出仍留在分母中，且不获正确性计分。

所报告结果：在完整遥测下，起源步骤 Top-1 准确率在各模型间从 33.8% 到 97.2% 不等。元数据、OpenTelemetry 兼容与 OpenInference 兼容视图保持 99.5% 到 100% 的检测 F1，却把起源步骤准确率限制在至多 0.5%。移除决策内容使每个模型的起源步骤准确率降到零；移除出处也造成大幅且随模型而异的损失。在需要弃权的歧义输入上，证据门控使三个模型无依据的唯一起源答案减少 12.5 到 48.6 个百分点，而另两个模型仍对每个案例作答。

## Main Contribution

一个受控 benchmark，把「失败*检测*」与「故障*源*定位」的区分从 agent 遥测中操作化，量化出一个检测–定位落差，并表明终态状态支撑检测、而可靠的因果归因需要显式的「决策到出处」链接。它还把「证据不足时的安全弃权」构造为一种可测量、且强烈依赖模型的能力。

## Key Design Ideas

- **延迟绑定故障。** 故障在其引入位置之后的某一步才激活，把可观测症状与真实起源解耦。
- **七个遥测因子**接受消融：标识与事件语义；决策与潜在引用内容；注册表与出处映射；传播与交接关系；工具输入与状态转移；观测与验证器证据；终态失败状态。
- **标准化的可观测性渲染**对齐到元数据、OpenTelemetry 与 OpenInference 视图，测试哪种真实世界遥测 schema 足够用。
- **完全相同的歧义起点对**使弃权成为正确行为，把经校准的弃权与瞎猜区分开。
- **程序化、模型不可见的标准真值**，以及把畸形答案留在分母中的无效输出计入规则。
- **冻结的盲留出集**，用于检查核心模式在开发切分之外是否复现。

## Strengths

- 在匹配条件下把故障源定位从失败检测中隔离出来，直接暴露一个单一准确率数字会掩盖的检测–定位落差（论文）。
- 把可观测性条件绑定到真实遥测 schema（OpenTelemetry、OpenInference），使「我的遥测够不够？」这一问题对从业者而言具体可操作（论文）。
- 严谨的协议卫生：显式候选集、把无效输出计入分母、子群分析，以及一份冻结的盲留出集（论文）。
- 把安全弃权当作一等的可测量能力，而非假定模型应当总是作答（论文）。

## Limitations

- 轨迹是合成/规范化构造，而非部署 agent 系统的日志；论文的规范化轨迹设计可能无法捕捉生产遥测的全部杂乱（论文将轨迹描述为受控/规范化的）。Repository note: 所报告实验未确立向真实环境轨迹的泛化。
- 评估覆盖五个前沿语言模型；诸如弃权行为等结果强烈依赖模型，故所报告区间仅适用于被测集合（论文）。
- 所给的代码/数据指针是一个匿名仓库，与在审工作一致；尚无规范化的永久工件 URL。Repository note。

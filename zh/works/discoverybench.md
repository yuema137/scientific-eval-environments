# DiscoveryBench (2024)

> [English](../../works/discoverybench.md) | **简体中文**

> **首次公开：** 2024-07-01 · **来源：** [arXiv 首次提交](https://arxiv.org/abs/2407.01725)

## Overview

DiscoveryBench 让 agent 去找假设，而不是算答案。此前的数据分析套件把问题和答案形式都定死了：跑这个检验、给出这个数、通过这条断言。agent 只要挑对了库，通常就能得分。DiscoveryBench 给的是一个或多个数据集、字段说明，以及一句自然语言写的发现目标，分析流程全部由 agent 自己设计。评分时，它把 agent 给出的陈述句假设和从已发表论文复现出来的标准假设放在一起比，并拆成三个维度：context（适用范围）、variables（变量）、relationship（关系）。这样一来，选对了变量但搞错了人群的那次运行，和什么都没找到的那次，就不会混为一谈。

## Summary

这项来自 Allen Institute for AI、OpenLocus 和 UMass Amherst 的工作把数据驱动发现任务写成了一个定义：给定任务数据集 *D* 和发现目标 *G*，导出假设 *h* = ψ(*c*, *v*, *r*)，在 *D* 能支持的前提下，让 context *c*、variables *v*、relationship *r* 三个维度都尽可能具体。真实划分 DB-Real 用 Python 复现了 20 多篇已发表论文的分析流程，并把论文结论当作标准假设；合成划分 DB-Synth 则从假设语义树自底向上生成数据，因此工作流的深度可以按需调节。因为假设是逐维度评分的，论文能指出 agent *在哪一环* 出问题，而不只是说它做不到：最好的系统只有 25%，而最依赖高级统计方法的生物学任务是 0%。这个分数仍然依赖一个 GPT-4 evaluator，作者对它做了审核，而不是默认它可靠。

## Tasks

**DB-Real：264 个任务（训练 25、测试 239）**，覆盖社会学、生物学、人文、经济学、工程和元科学六个科学领域，训练集含 14 个不重复的标准假设，测试集含 144 个。测试集按领域分布为：元科学 100、社会学 58、人文 38、生物学 16、工程 15、经济学 12。每个任务给出一个或多个数据集、数据集与字段说明、该领域的背景知识，以及一句发现目标；其中 114 个任务（训练 4、测试 110）需要用到不止一个数据集，单个任务最多 6 个，全套任务包含 500 多处清洗、去重、整合之类的数据准备操作。

任务构建走了两条路线。**数据优先** 路线先筛出建立在公开数据集之上的论文，数据来源有 National Longitudinal Surveys、Global Biodiversity Information Facility 和 World Bank Open Data，再用 Python 把这些论文的工作流复现一遍：每篇 NLS 相关论文花 15 到 40 人时，GBIF 数据集最多到 90 人时，约 30% 的尝试以失败告终。**代码优先** 路线在 Zenodo 上检索了 785 条含计算笔记本的记录，其中超过 85% 的仓库要么代码缺失，要么无法迁移到 Python，要么数据集不开放，最终候选 14 个仓库，只有 3 个通过全部检查。作者对每条实现工作流都人工核验过可解性，经济学和社会学的假设还请了经济学博士把关。

**DB-Synth：903 个任务，覆盖 48 个领域**，按 80/20 划分为开发集和测试集，并标注 1–4 级难度。流程是：由 LLM 采样一个领域，构建以目标变量为根的假设语义树，把每条边写成一个 pandas 表达式，再从叶到根逐层生成列，最后向数值中注入噪声和缺失。

## Domains

DB-Real 覆盖六个领域：社会学、生物学、人文、经济学、工程、元科学。生物学任务来自两篇已发表研究：一篇看南美淡水鱼在高地环境中体型演化加速是否与近期物种形成相关，另一篇看引入途径如何影响外来植物沿环境梯度的入侵成功率。工程任务分析的是一份调查数据，内容是工业界如何为 ML 系统做需求工程；人文任务属于考古学；元科学任务研究大规模复制项目中的效应量收缩与异质性。

## Evaluation

- **Hypothesis Matching Score（HMS）。** 由 `gpt-4-preview-0125` 担任 evaluator，分别抽取标准假设和预测假设的 context、variables、relationship，按 context 是否等价把预测子假设和标准子假设配对，再计算 `HMS = ctx_align × var_F1 × rel_acc`，缩放到 [0, 100]。关系一项的判分规则是：完全一致记 1，预测关系比标准关系更宽但能涵盖它记 0.5，其余记 0。
- **一个任务从头走到分数。** 标准假设是「社会经济地位对完成大学学位的影响，女性（0.4995）高于男性（0.4467）」。作者把关系这一维遮掉，交给 agent 的目标就变成「社会经济地位对女性与男性完成大学学位的影响有何不同？」，同时给出 NLS 数据集。agent 必须清洗并合并数据、自行挑选并执行合适的分析、返回一句陈述句；HMS 随后检查它说的是不是同一个人群、同一组变量，以及关系的方向和形式对不对。
- **对 evaluator 的审核。** 两位作者在 200 个样例上各自独立检查了 LLM 的逐步评估过程，消解分歧后得到：GPT-4 在 context 抽取上正确率 97%，context 匹配 99%，变量抽取 94%，关系判分 99%。
- **与人类判断的一致性。** 三位标注者在 DB-Real 测试集上随机抽取 100 组，对两个预测假设相对标准假设排序。人类的偏好排序与 HMS 给出的排序在 95% 的情况下一致，标注者之间 Fleiss κ = 0.91，「人类排序与 HMS 排序存在差异」这一原假设在 *p* < 0.001 水平被拒绝。
- **实测结果。** 在 CodeGen、ReAct、DataVoyager 和 Reflexion (Oracle) 四种 agent 与 GPT-4o、GPT-4-preview-0125、Llama-3-70B 三个模型的组合中，最好的系统也只有 25%：DB-Real 上 Reflexion (Oracle) 配 GPT-4o 得 24.6 HMS，非 oracle 里成绩最好的是 ReAct 配 GPT-4o 的 24.4。`NoDataGuess` 基线完全不碰数据、只凭数据集描述和目标作答，得分为 0.0（GPT-4o）、4.7（GPT-4p）、11.5（Llama-3-70B）。按领域看，非 oracle 最佳 agent 在生物学上 0%、工程上 7%，而经济学 25%、社会学 23%；按工作流类别看，它做得最好的三类是相关性分析、时间序列分析和社会科学相关分析，最差的三类是空间分析、孢粉建模和生态建模。
- **领域知识消融。** 考古学任务在数据采集阶段就需要大量领域知识，作者把这部分知识作为额外提示补给 agent。DataVoyager 配 GPT-4-preview-0125 的成绩从不给提示时的 9.9% 升到给提示后的 25.4%，说明失败有一部分出在缺背景知识，而不是不会分析。
- **逐条轨迹的错误分析。** 论文带着 HMS 走了非 oracle 最佳 agent 的三条轨迹：一条拿 100 分；一条拿 50 分，因为它报了一个汇总统计量，却没做能支撑这个结论的显著性检验；还有一条拿 0 分，因为它用一个更简单的分析顶替了数据本该用的多元回归。

## Typical Duration

论文没有报告墙钟时间。难度改用 *工作流长度* 衡量，即参考实现工作流中的操作步数；DB-Real 把任务分为短（< 10）、中（> 10 且 < 20）、长（> 20）三档，性能在中等长度上就已经明显下滑。

## Main Contribution

第一个把数据驱动发现形式化为多步「搜索加验证」过程的 benchmark，并配上一套结构化的假设表示（context、variables、relationship，以及假设语义树），评估因此能落到单个维度上，看得出失败出在哪里。

## Key Design Ideas

- 把一个假设拆成 context、variables、relationship 三份，单一的对错就变成三路可分辨的信号，部分正确的发现既不会被一笔勾销，也不会被过度记分。
- 标准假设来自已发表、经过同行评议的工作流复现，而不是为 benchmark 现编的；复现过程还额外挖出了论文没写、但数据支持得住的假设。
- 遮掉标准假设的某一维来构造发现目标，保证每个目标只指向一个答案。
- `NoDataGuess` agent 全程不打开数据集，用来量化一个分数里有多少可能来自对已发表工作的记忆。
- DB-Synth 把发现过程反过来做：先建语义树，再生成满足它的数据，工作流深度因此成为一个可控变量。

## Strengths

- HMS 在两个方向上都做过验证：一是在 200 个样例上逐步审核 evaluator 的抽取步骤，二是用 100 组对照人类标注者的偏好实验（一致率 95%，Fleiss κ = 0.91）。
- 按维度拆解的分析把低分变成了诊断：想预测对变量，先得预测对 context；失败集中在需要高级统计或长工作流的任务上。
- 考古学的领域知识消融不止于诊断，还做成了一次受控实验：把缺的背景知识补上，DataVoyager 在这批任务上就从 9.9% 提到 25.4%。
- 论文如实报告了任务构建成本：每篇论文 15–90 人时、30% 的尝试失败、785 个 Zenodo 候选里只剩 3 个，把忠实复现有多贵这件事记录了下来。

## Limitations

- 作者过滤掉了需要预报、模拟或高度专用建模的领域和任务（物种分布、传染扩散、系外行星天体物理），结果自然科学与物理科学的论文占比低于社会科学。
- 超大规模数据集不在范围内；论文点名 8.92 PB 的 Cancer Genome Atlas 作为它没有处理的例子。
- 不处理多模态数据和复杂管线，例如气候科学所需的卫星与其他地理空间数据。
- 作者明确表示，如何保证发现结果稳健、不是 *p*-hacking 的产物，他们的方法还没有解决。
- Repository note：报告的分数依赖一个 GPT-4 evaluator。审核与偏好实验为它在本 benchmark 假设上的可靠性划出了边界，但没有把模型从评分链路里拿掉。

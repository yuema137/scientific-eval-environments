# Agentic Large Language Models for Automated Structural Analysis of 3D Frame Systems (2026)

> [English](../../works/agentic-large-language-models-for-automated-struct.md) | **简体中文**

## Overview

一个含十个不规则三维建筑框架体系的 benchmark：agent 须依据自然语言描述产出可执行的 SAP2000 脚本，只有当每一项受监测的结构响应都落在人工搭建的 ground-truth SAP2000 模型 1% 以内，才算通过。

## Summary

这篇把同一团队的结构建模脉络从平面框架推到三维建筑体系——到了三维，拓扑一致性既要在每个楼层平面内成立，也要跨楼层成立。第一项贡献是一种表示方法：把不规则三维框架投影到由正交轴线定义的二维平面上，再用「层数矩阵」（matrix of number of stories, MNS）给每个网格单元赋一个整数，指明该单元竖向拉伸多高，于是中庭、洞口与退台都能用紧凑的文本形式表达出来。在此之上是一条多 agent 管线，按楼层逐层分解框架：节点、大梁与楼板 agent 在每个楼层平面内并行工作，柱 agent 负责连接相邻楼层，支座、荷载与代码翻译 agent 最终产出 SAP2000 脚本。系统用了两个轻量骨干模型——GPT-OSS 120B 负责空间推理，Llama-3.3 70B Instruct Turbo 负责代码翻译。与此前的二维工作不同，这里判定正确与否依据的是数值结构响应，而非代码能否执行。

## Tasks

十个具有代表性、几何构形不规则的三维框架体系，覆盖工程实践中的三类复杂性：竖向不规则、平面不对称与布置不连续。平面网格从 3 × 3 到 4 × 6 个单元不等，各单元的层数在 0 到 7 之间变化。代表性构形包括阶梯式退台、内部中庭洞口，以及 L 形、U 形与十字形的不对称平面；还纳入了非均匀的网格间距，用以检验超出规整网格之外的泛化能力。每道题都按同一套结构化文字模板给出：轴线位置、层数矩阵、层高、边界条件、荷载与材料属性。除几何之外，其余条件在十道题中保持一致——所有支座底部固定，每块楼板上沿竖直向下施加 10 kN/m² 均布面荷载作为重力荷载，并在左侧外立面每层顶层节点处沿 X 正方向施加 50 kN 侧向集中荷载以代表风效应。材料为线弹性，E = 2 × 10¹¹ Pa，大梁与柱的截面属性各异（含扭转常数），楼板按均匀厚度 0.15 m 的薄壳建模。

## Domains

土木与结构工程。受评对象是三维建筑框架体系——柱、大梁与楼板跨楼层拼装而成——在重力荷载与代表风效应的侧向荷载作用之下，受评产物则是所得有限元模型的结构响应。不规则性分类（竖向不规则、平面不对称、布置不连续）本身就是建筑结构工程的行话。未指派共同领域；SAP2000 是工具，而非受评目标。

## Evaluation

- 十道 benchmark 题目每题用同一份输入描述重复评测十次。每次试验中 agent 产出一份 SAP2000 脚本，执行后得到结构分析结果。
- 每个 benchmark 算例的 ground-truth SAP2000 模型都由作者手工搭建。生成模型的响应在若干选定的关键位置上与 ground-truth 模型比对，只有当**所有**受监测响应量的相对误差都低于 1%，该次试验才计为准确。逐题准确率即准确试验数占总试验数的比例。因此该协议考的是所得模型在分析上是否正确，而不只是脚本在语法上能否执行。
- **所提 agent 框架。** 每道 benchmark 题目的准确率都超过 80%，十题平均 90%，方差 0.007。
- **Baseline。** GPT-5.4 与 Gemini-3.1 Pro 在同样的输入模板下被要求直接产出完整的 SAP2000 脚本，十道题上准确率均为 0%，每一次重复试验都失败。失败分析把第一道门槛定位在脚本导入环节：SAP2000 要求预定义表名精确匹配，GPT 的脚本平均只有 4% 能成功导入，Gemini 为 47%。即便在能导入的脚本中，几何与拓扑的一致性也无法在多次运行间保持——GPT 在不同运行里对同一个开敞中庭构形的理解并不相同，Gemini 则会漏掉跨楼层平面的大梁单元。
- **消融**在前三个 benchmark 算例上进行，每例十次试验。完整框架：90% / 80% / 90%。去掉楼层分解 agent：30% / 50% / 20%。把节点、大梁、楼板 agent 合并为单个平面内几何 agent：50% / 70% / 60%。把几何翻译与代码编译合并为单个脚本翻译 agent：0% / 0% / 0%。
- **运行时长与成本**与准确率一并报告，作为分析耗时的对照：所提框架平均每个算例约 175 s、0.193 美元，GPT-5.4 约 158 s、0.306 美元，Gemini-3.1 Pro 约 386 s、0.502 美元。这些是报告出来的度量，而不是 agent 必须据以规划的预算。

## Typical Duration

所提框架平均每个算例约 175 秒、0.193 美元；GPT-5.4 约 158 s / 0.306 美元，Gemini-3.1 Pro 约 386 s / 0.502 美元。一份三维框架的完整 SAP2000 脚本可以超过一千行，论文正是以此说明代码翻译无法在单次生成里完成。

## Main Contribution

作者提出一种结构化的几何表示，使不规则三维框架能以无歧义的文本表达出来；在此基础上构建的 agent 管线把长周期的三维结构建模分解为楼层级子任务，并设置检查点。配套的十算例 benchmark 以「与手工搭建的参考模型数值响应一致」判分，构成核心证据：前沿通用模型在它上面得零分，而分解式的轻量管线平均达到 90%。

## Key Design Ideas

- 建立在轴线平面之上的层数矩阵（MNS）逐单元编码竖向拉伸量，取值为 0 即表示洞口或中庭，于是不规则的三维拓扑被压缩成一张 LLM 能可靠解析的紧凑二维表。
- 正确性以数值方式定义——所有受监测响应量相对手工搭建的 ground-truth SAP2000 模型误差在 1% 以内——而不是看脚本能否执行或几何目测是否合理。
- 三维问题被分解为一叠彼此独立的楼层级生成任务，再通过连接相邻楼层重新组装，从而限定任何单个 agent 一次需要掌握的拓扑量。
- 节点、大梁与楼板 agent 在一个楼层内并行运行，事后由一个确定性的连通性映射函数把以坐标对表示的单元定义转换成节点 ID 连通关系。
- 在规划阶段之后与几何拼装之后各设一个检查点，执行一致性检查（重复节点、重复单元、悬空坐标、无引用节点）并触发重新生成，重试上限为五次。
- 按任务类型分派两个不同的轻量骨干模型——空间推理 agent 用 GPT-OSS 120B，翻译 agent 用 Llama-3.3 70B Instruct Turbo——而消融检验的是分解边界，而非模型选型。

## Strengths

- 正确性判据是这一脉络中最严的：要求算出的结构响应与手工搭建的参考模型吻合，这能抓住那些跑得通、看着也像样，实际建错了结构的脚本。
- 不规则性分类取自建筑工程实务，而非取自「什么好生成」，其中包含洞口、退台，以及带非均匀网格间距的 L 形、U 形与十字形平面。
- 相对 GPT-5.4 与 Gemini-3.1 Pro 的「0% 对 90%」落差不是简单报出来了事，而是作了诊断，把导入失败、语法失败与运行间的拓扑不一致区分开来。
- 消融逐一隔离每一处分解边界，并表明一旦把翻译与编译合并，三个受测算例的准确率齐齐归零——这是关于长周期代码生成极限的一个具体结论。
- 逐算例的运行时长与美元成本与准确率并列报告，使「轻量骨干」这一主张可被核查。

## Limitations

- 十道题的 benchmark 规模不大，且荷载、边界与材料条件在所有题目中完全相同，因此只有几何在变。
- 只评测线弹性静力分析；非线性、动力、地震响应与设计决策均未涉及。
- ground-truth 模型由作者手工搭建，因此参考本身依赖于他们的建模取舍；受监测的响应量与关键位置也是选定的，而非穷举的。
- 消融只覆盖十个算例中的前三个。
- 所提框架仍存在两类错误：长上下文的几何翻译环节中截面属性指派错误，以及荷载指派的遗漏或多余。
- Repository note: 论文未说明代码或数据集的公开情况，且 SAP2000 是商业软件，独立复现需要许可证。
- Repository note: 运行时长与成本仅用于对照，agent 并没有必须据以规划的预算，因此这属于分析阶段的资源意识，而非 benchmark 层面的资源意识。

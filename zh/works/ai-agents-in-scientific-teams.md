# Position: AI Agents in Scientific Teams Should Be Studied as Human-Agent Systems (2026)

## Overview

一篇立场论文，主张关于「AI 科学家」的研究一直集中在自主能力上，因而忽略了科研协作的社会性现实。作者提出分析单元应当是人—agent 这个二元组而非 agent 本身，汇集了「忽视人机互动会带来近期风险」的证据，并勾勒出一个衡量人机协同增益的决策论框架。

## Summary

人—agent 系统（HAS）由四个部分定义——agent、人类参与者、通过动作促成人机交互的界面，以及系统所处的环境——它的核心主张是：被研究的对象应当是这个**二元组**。作者指出，当前的 AI 科学家工作主要在两个节点支持人类参与，即设定目标与验收成果，而很少有系统支持人类团队中那种持续、迭代、共同推进的协作；同时，HAS 这一支文献又基本与科研的社会技术现实相隔离。论文分三步立论。它先梳理了「大规模部署 AI 科学家会带来风险」的累积证据，而这些风险恰恰是以自主性为中心的评估看不见的。接着它分析两份已发表的、真实科学家与 agent 协作的记录，从中抽出相互增益的模式——人类提供概念框定、领域判断与认识论把关；agent 压缩实现工作，偶尔也在概念层面有所贡献。最后它给出一个玩具效用模型和一组开放问题，并报告了一项关于「主动求反馈」行为的小型实验。论文也承认互补性在经验上很少出现，并提出这可能反映的是结构性障碍：激励机制偏向自主性研究，而严谨的人类实验成本高昂。

## Tasks

N/A — 论文不贡献任务集。它的实证部分只有一张表：一个 ReAct GPT-5-mini agent 在 **AstaBench 的 End-to-End Discovery（E2E）划分**上、在 **10 个开发集任务**上的表现，设三种条件——(1) AstaBench 原生的以规划为中心的 ReAct harness；(2) 在系统提示中加入 `ask_user` 工具与论文提出的 HAS 人类反馈分类体系作为鼓励；(3) 加入「每次动作前都必须调用 `ask_user`」的显式指令，作为 agent 主动脱离的上界。

## Domains

不指派任何规范领域。论文的主题是研究科学 agent 的**方法**，而非任何科学学科；它的两个案例恰好落在复杂性理论与等离子体物理，但那是用作说明的记述，而非受评任务。

## Evaluation

那项初步探测用 **LLM-as-a-judge** 把 agent 提出的问题归入论文的人类反馈分类体系，报告分维度百分比——10 个 E2E 任务上的计数按提问总数归一化——并**在三个评判者之间取平均以增强稳健性**。报告的发现是：没有逐步指令时，agent 不知道该在何时发问，遇到含糊情形宁愿自行假设，哪怕关键资源并不可用；施加逐步强制后，占主导的反馈类型是**评价型**，通常出现在**任务中段**，其次是**求指引型**，密集出现在**任务开始前**；**纠错型**反馈则极少被请求。

风险方面的证据取自既有工作而非本文测量：AI 增强的研究**产出论文数量是三倍，而所探索主题的多样性下降 5%**；NeurIPS 与 ICLR 的投稿量**从 2014 到 2024 年增长 10.4 倍**，而审稿人并未同步增加；一项专家复核发现 **36% 的 LLM 与 AI 科学家生成的论文存在明显抄袭**。

对协同增益，论文给出的是玩具决策论模型而非指标：团队效用 **U(H, A) = CA(H, A) − CD(H, A)**，其中协作优势 CA 衡量团队相对于其最强单个成员的表现（即互补性），协作代价 CD ≥ 0 则刻画协作本身的开销——沟通与协调成本、花在消息上的 token，以及人类成员承受的认知负荷。

## Main Contribution

主张科学 agent 研究应以人—agent 二元组为分析单元，并以风险证据、两个相互增益的案例，以及一个把团队效用拆成互补项与显式协作代价项的分解来支撑——而后一项，正是以自主性为中心的评估系统性遗漏掉的部分。

## Key Design Ideas

- 分析单元是二元组，这把评估问题从「这个 agent 有多强」重新框定为「这一对组合做成了哪些任一方单独做不成的事」。
- 把 CD(H, A) 设为显式项，意味着协调开销——token、轮次、人类认知负荷——会计入协作的成本，而不是隐而不见。
- 区分互补性（团队胜过其最强成员）与较弱的人类增强（AI 帮到了人，但不必证明它单独做不会更好），使论文能主张 HAS 研究的价值而不至于过度声称。
- 两个案例都作双向解读，既问 agent 如何增强了人，也问人如何增强了 agent——这才带出「高度依赖专家」这一发现。
- 主动求反馈的探测特意设了一个过度指令的第三条件作为上界，使「自然发问」与「强制发问」之间的差距可测。
- 论文主张事后复核并不够用，需要多种粒度上的异步交互——包括对轨迹日志与代码的审计——才能更早暴露问题。

## Strengths

- 两个案例取自真实科学家的已发表记述，而非构造出来的演示，且都在陈述 agent 贡献的同时报告了它的失效模式（过早自信、把棘手之处一笔带过）。
- 复杂性理论那个案例明确指出，该工作流之所以成功，正**因为**有专家能诊断出遗漏、并纠正引理中一处错误假设，并说明若无这份专业能力，同样的流程很可能产出一篇误导性的论文。
- 论文报告了不利于自身乐观判断的证据，指出互补性在经验上极少出现。
- 风险一节具体且有出处，而非泛泛推测，在产出量、审稿负荷、去技能化与抄袭四方面都给出了具名数值。
- 附上一个小型实验，使这个立场带上了可检验的一角，而不停留在纯粹论辩。
- 论文设专节回应不同观点，而不只是陈述己见。

## Limitations

- 实证部分被明确定位为初步：10 个开发集任务、一个 agent、一个骨干模型，且问题分类由 LLM 评判者而非人类完成。
- 效用模型被作者称作玩具模型；CA 与 CD 没有被操作化为可测量的量，也没有给出估计任一者的工具。
- 两个案例是不同学科中的定性单例，且都由专家用户参与，因此说不出同样的工作流在专业能力较弱的人手中会如何——而那恰恰是论文去技能化担忧所指向的人群。
- 头条风险数字承自所引研究，而非本文确立。
- 论文不发布任何 benchmark、协议或数据集，因此其主张在评估层面无法直接落地执行。
- Repository note: 本卡片归入 Survey，是因为该主题同时收录综述与立场论文；这项工作不贡献任务集，也不贡献评分协议。

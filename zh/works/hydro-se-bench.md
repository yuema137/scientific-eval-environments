# Hydro-SE Bench (2025)

> [English](../../works/hydro-se-bench.md) | **简体中文**

## Overview

Hydro-SE Bench 是一个中文选择题 benchmark，含 4,000 道题，覆盖水科学与水利工程的九个子领域，用以衡量通用 LLM 究竟掌握了多少实用的水利工程知识——包括水工建筑物、岩土工程与行业设计标准。

## Summary

作者认为水科学与水利工程（Hydro-SE）是一个知识密集的领域，而 LLM 在其中的能力尚未被系统测量过；他们由此构建了自称首个跨 Hydro-SE 子领域维度评估 LLM 知识的 benchmark。题目取自教材、行业标准、法律法规与统计年鉴，再由 LLM 在专家设计的范例引导下半自动生成，并各自经至少三位专家独立评审。十六个模型——十个商业、六个开源——在 temperature 0 下以思维链零样本评测，结果按子领域与认知层级拆分呈现，使知识短板可以定位，而不是汇成一个总分。

## Tasks

4,000 组中文问答对。论文报告的构成是 2,700 道单选题（68%）与 1,300 道多选题（32%）；配套仓库给出的则是 2,696 道单选与 1,304 道多选。题目覆盖九个子领域：背景知识、行业标准、水文与水资源、岩土工程、水工建筑物与设备、工程安全与管理、水力学与河流动力学、气象学、电力系统。每题另标注三种认知层级之一：Type A 为基础概念知识，Type B 为情景化的工程应用，Type C 为推理与计算。仓库给出的层级分布为 Type A 43.75%、Type B 43.75%、Type C 12.5%。题源为教材、行业标准、法律法规与统计年鉴；候选题由半自动的 LLM 生成管线产出，以专家撰写的范例作种子，每道题再由至少三位领域专家独立评审。各子领域的题量在论文中只以分布图呈现——精确的分子领域数字为 `TODO(reference)`。仓库说明只公开发布了一半题目（ID 为奇数的那部分）。

## Domains

土木与结构工程，具体表现为水利基础设施工程。九个子领域中有四个落在建成水利设施的土木工程之内：水工建筑物与设备（坝、溢洪道、闸门及配套机械）、岩土工程、行业标准（管辖水利水电工程的设计规范与技术标准），以及工程安全与管理。论文的核心结论恰恰是模型在「行业标准、水工建筑物这类领域专有知识」上最弱，而这正是该 benchmark 的土木工程内核。共同领域：地球科学（水文与水资源、水力学与河流动力学、气象学）、环境科学（水资源管理）与能源系统（电力系统，对应该领域的水电一侧）。

## Evaluation

指标为准确率，即答对题数与总题数之比，既报告总体值，也按子领域、题型与认知层级拆分。模型在 temperature 0 下以思维链提示零样本作答，以保证输出确定；评测分两阶段，受评模型先给出推理过程，再由另一个 LLM 从这段自由文本中提取最终的选项字母。多选题是否给部分分未见说明——`TODO(reference)`。报告结果：商业模型的准确率落在 0.74–0.80 区间，开源模型落在 0.41–0.68。总体领先的是 DeepSeek-V3.2-Exp 与 DeepSeek-R1，两者均高于 0.79，其中 DeepSeek-V3.2-Exp 为 0.796。共评测十六个模型：十个商业（DeepSeek-V3.2-Exp、DeepSeek-R1、Kimi K2、GLM-4.5、GPT-5、Grok-4、Qwen-Plus、Gemini-2.5-Pro、Llama-4、Claude-4.5）与六个开源（GLM-4-32B，Qwen2.5 的 32B/72B/7B，Llama-3 的 70B/8B）。作者观察到，模型在以自然科学与物理科学为基底的子领域上表现好于在成文化、实务专有的工程子领域上，且扩大规模主要改善的是推理而非领域知识。

## Main Contribution

作者把 Hydro-SE Bench 呈现为首个跨水科学与水利工程各子领域维度、全面评估 LLM 知识与能力的 benchmark，并借其子领域与认知层级的拆分表明：当前模型在有科学基底的内容上远强于在行业标准与水工建筑物这类实用水利工程所依赖的知识上。

## Key Design Ideas

- 每道题带两个正交标签——子领域标签与认知层级标签（A 概念 / B 工程应用 / C 推理与计算）——使模型的弱项能归因到某个领域或某种推理模式。
- 题源刻意向实务文件倾斜：除教材之外，还有行业标准、法律法规与统计年鉴。
- 以专家设计的范例做半自动生成，随后每题由至少三位专家独立评审。
- 以中文构建，与题目所取的国家标准和法规语料相匹配。
- 在 temperature 0 下做确定性评测，并把答案提取交给另一个 LLM，从而无需对受评模型施加格式约束即可为思维链回答判分。
- 采用单选与多选混合的题型，而非只用单选。

## Strengths

- 覆盖了通用科学 benchmark 略去的、成文化且受标准约束的那一面水利工程，并表明模型恰恰就败在这里。
- 逐子领域报告使失效模式可被针对，而不是只留下一个总分。
- 模型阵容广，十六个系统横跨商业前沿模型与多种规模的开放权重模型。
- 每题至少三位独立评审的专家复核回路。
- 数据集与评测包一并发布，支持批量评测、按类别/难度/题型的统计拆分与报告生成。

## Limitations

- 作者指出该 benchmark 仅限选择题，因此无法完整反映真实的工程应用。
- 作者指出它不含实时数据，也没有情景化的 agentic 任务。
- 作者指出评测是纯文本的，而 Hydro-SE 实务大量依赖多模态输入，如卫星遥感影像、站点时间序列与视频流。
- Repository note: 只有一半题目——ID 为奇数的那些——公开发布，因此在公开划分上算出的结果与论文的全集数字并不直接可比。
- Repository note: 各子领域的题量只以图的形式给出，故仅凭论文正文无法对子领域层面的结果重新加权。
- Repository note: 由于候选题在专家评审之前由 LLM 生成，题目措辞可能与作答模型自身的分布相关，不过论文未就此做检验。

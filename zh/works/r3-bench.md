# R³-Bench (2026)

> [English](../../works/r3-bench.md) | **简体中文**

## Overview

R³-Bench 评估的是资源理性推理：模型面对的是一组六道题，它们必须共用一份预算，因此成败取决于如何在题目之间分配算力，而不是逐题孤立求解。它的独到之处在于把套题表现校准到同一模型在这些题上已展示出的单题水平——用匹配的响应曲线，在实际观察到的成功之上构造一个离线经验 oracle。

## Summary

资源理性这一概念借自认知科学，问的是 agent 应当如何分配有限算力以最大化期望价值。作者观察到，多数推理与 agent benchmark 都为每道题单发预算；而现有的共享预算研究，从来没有把套题表现校准到同一模型在同一批题上确实做得到的水平。R³-Bench 补上了这个缺失的参照。每道题先在隔离状态下按一组预算档位各跑五次，得到一条经验响应曲线——成功率随预算的变化。随后由一个背包求解器为每道题挑一个预算档（含「分配为零」这一选项），在共享约束下最大化期望答对数。得到的并不是 agent 能执行的策略，而是一个离线诊断量：它说明这个模型自己已展示的能力，在完美分配下本可以值多少分。这个 oracle 与模型实际比赛得分之间的差距，就是全文的核心量——而它既大又近乎无例外。

## Tasks

**每个领域 50 组套题**，覆盖三个领域，每组含 **六道题**，按 **3 易、2 中、1 难**分层——难度依据 DeepSeek V4 Pro、GLM-5.2 与 GPT-5.5 的平均输出长度划定。题源为数学的 **Omni-MATH 与 MathNet**（**300 题**）、竞赛编程的 **LiveCodeBench Pro**（**300 题**）、抽象推理的 **Reasoning Gym**（**300 题**）。

评测设两种设定。**无工具**设定下模型自由作答，不用工具、不接 shell，预算以输出 token（`max_tokens`）计。**agentic** 设定下，使用工具的 agent 在 **Terminus-2** shell 环境中作业并可执行代码，预算以计数的工具动作计；记账类命令（`focus_problem`、`shelve_problem`）单独记录为免费步骤。

预算按模型校准为相对压力档 **ρ ∈ {0.2, 0.8}**，参照各模型自己的无预算基线——ρ = 0.2 为强压力，ρ = 0.8 为中等压力。

## Domains

**Mathematics** 与 **Computer Science。** 两个切片都既可辨识又有明确规模：数学 300 题取自 Omni-MATH 与 MathNet，竞赛编程 300 题取自 LiveCodeBench Pro。第三个领域即 Reasoning Gym 的抽象推理，是合成的推理载体而非一门科学学科，不获得领域归属。

## Evaluation

主表共 **72 个单元格**（6 模型 × 2 设定 × 3 领域 × 2 压力档）。**oracle 在全部 72 个单元格中都不低于比赛得分，并在其中 71 个严格更高**——已展示的单题能力与共享预算下真正兑现的表现之间，几乎处处存在差距。

另有两项比较收紧了解释。**等额分配重放**——直接把预算平均分掉再重跑——在 ρ = 0.8 时对 **6 个模型中的 4 个**都胜过模型自己的比赛表现，可见这个缺口并不只是「没找到某种巧妙分配」。在强 agentic 压力下的三模型诊断中（DeepSeek-V4-Pro、GLM-5.2、Hy-3），**至少有一个固定调度器在 9 个单元格中的 6 个超过比赛均值**，但没有哪个策略能跨领域全面占优。

轨迹诊断显示策略更新有限，且失效模式随压力档而变。

六个旗舰模型为 **DeepSeek-V4-Pro、Qwen3.7-Max、GLM-5.2、Hy-3、GPT-5.5 与 Claude-Opus-4.8**；附录结果扩展到八个模型，另加 DeepSeek-V4-Chat 与 DeepSeek-V4-Reasoner。

## Typical Duration

预算本身就是被评估的变量，而非一项固定设置。无工具设定下它是输出 token，上限为 ρ × 模型的无预算基线；agentic 设定下是按同样相对比例缩放的工具动作计数。响应曲线的构造则让每道题在隔离状态下跑遍固定预算网格，**每档五次**。

## Main Contribution

一个自带参照点的共享预算评估：由于每道题的响应曲线是先在隔离状态下测出来的，它能说明模型已展示的能力在最优分配下本该产出多少，从而把差距报告为一个有校准的量，而不是一个无从参照的分数。

## Key Design Ideas

- oracle 建立在**实际观察到**的成功之上，而非某个假定的缩放律，因此有经验依据，且永远不会超出模型确实在某处做到过的水平。
- 允许背包求解器给某道题分配零预算，等于把「决定不做某题」这种取舍也明确纳入最优解的范畴。
- 预算按模型、对照其自身的无预算基线校准，因此 ρ = 0.2 对啰嗦程度迥异的模型意味着可比的压力。
- 套题构成固定为 3 易 / 2 中 / 1 难，每组套题提出的分配问题形状一致，结果因而可以有意义地汇总。
- 难度由三个模型的实测输出长度划定，而非人工标注，分层因此可复现。
- 等额分配重放是一个刻意「不聪明」的对照：若连它都胜过模型，说明问题出在分配行为上，而不是分配问题本身太难。
- 记账类命令记为免费步骤，使 agentic 预算衡量的是解题动作，而不至于惩罚「把工作整理清楚」这件事本身。

## Strengths

- oracle 把「模型表现不佳」变成了逐单元格、对照模型自身已展示能力的量化缺口，这是绝对分数表达不了的。
- 差距近乎无例外（72 个中 71 个严格更高），结论并不依赖某个讨巧的子集。
- 等额分配重放是一道很强的合理性检验，而论文报告了这个平凡策略胜过六个模型中四个——一个对模型不利、却是全文论证核心的结果。
- 按模型校准预算，避免了固定 token 上限惩罚啰嗦模型这一常见的人为效应。
- 无工具与 agentic 两种设定都跑过，结论因而不是某一种交互模式的产物。
- 作者直言没有哪个调度器能跨领域占优，克制住了顺势给出解决方案的冲动。
- 代码与数据集均已公开。

## Limitations

- 响应曲线 oracle 离线掌握每道题完整的经验响应曲线，因此它是一个诊断性上界，作者也明确说明它并非可部署的策略。
- 在预算压力很强时，等额分配重放分到每题的份额可能小到没有意义。
- 在线调度器研究只覆盖三个模型，套题内目标的上下文压力诊断更只覆盖两个模型、12 个单元格。
- 失效原因的人工标注排除了证据不足的案例，因此所报告的失效分布是以「可判读」为条件的。
- Reasoning Gym 的抽象推理是合成的，数学与竞赛编程则取自既有 benchmark，污染风险由这些来源继承而来，本文所见内容未加处理。
- Repository note: 该评估针对的是预算约束下的模型，而非科研能力；数学与竞赛编程这两个切片才是它与本仓库领域轴的连接点。
